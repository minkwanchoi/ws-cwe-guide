# 부록

부록은 본문을 따라 일하다가 필요할 때 찾아보는 표와 양식이다. 대부분의 일은 본문, [규칙별 해설](../cwe/index.md), [지침 선택 도구](../selection-tool.md)로 끝난다. 부록은 다음 경우에 편다.

- **여러 항목을 한 표로 훑을 때**: 보안약점 점검 목록 44개를 단계 열로 보거나(부록 A), 언어 뷰 153개의 적용성을 한꺼번에 판정할 때(부록 B)
- **지침이나 근거의 전문을 찾을 때**: 환경 지침 245건 전문(부록 C), C#·Python 보안 규칙 대응(부록 D), 오픈소스 근거(부록 E), 용어 표기(부록 F)
- **과제 기록을 남길 때**: 환경 프로파일·지침 선택·적용성 판정 기록지와 단계 자가점검표(부록 G)

| 부록 | 무엇이 있나 | 언제 펴나 | 같은 내용이 있는 다른 곳 |
|---|---|---|---|
| [A. 보안약점 점검 목록(44개) 조견표](a-weakness-list.md) | A-1 단계별 지침(44개 × 수명주기 5단계), A-2 도구 지원 확인(매핑 권고, 도구가 보고하는 하위 CWE), A-3 보조 항목 4개의 추가 근거 | 설계 검토·코드 리뷰 체크리스트를 만들 때 한 단계 열만 훑기, 정적 분석 도구의 CWE 지원표와 대조할 때(2.5 ⑥, 6.2) | 항목 하나의 상세는 규칙별 해설, 전체 데이터는 Excel cwe-phase-matrix.xlsx |
| [B. 언어 뷰 보안약점 153개와 적용성](b-language-views.md) | CWE-658·659·660 구성원 중 보안약점 점검 목록 밖 153개의 적용성(해당·조건부)과 조건 | 요구사항 분석 단계에서 적용 보안약점을 판정할 때(2.5 ⑥, 3.3, 부록 G-4) | 언어별 쪽은 언어별 규칙(C·C++·Java), 과제별 판정은 지침 선택 도구의 '해당 보안약점' 목록 |
| [C. 개발환경별 지침 245건](c-environment-guides.md) | 6축 25종 환경의 지침 전문(적용 조건·보정 유형·대상 CWE·근거), C-0 특성 → 지침 역색인 | 선택 결과나 본문의 지침 ID(예: MCU-03)를 눌러 전문을 볼 때, 종이로 지침을 고를 때(C-0) | 지침 선택 도구(같은 데이터로 계산), Excel guide-data.xlsx |
| [D. C#·Python 보안 규칙 대응표](d-security-rules.md) | CWE와 함께 참고할 분석 도구 규칙. D-1 .NET 분석기 Security 범주 규칙 94개, D-2 Bandit 규칙 75개와 CWE·언어 지침(LCS·LPY)의 대응 | 분석 도구 규칙을 켜고 CWE 지원 범위를 확인할 때(5.6, 5.7) | Excel guide-data.xlsx |
| [E. 참조 오픈소스 프로젝트와 근거 목록](e-oss-evidence.md) | E-1 참조 프로젝트와 고정 판, E-2 지침별 대표 근거 1건 | 지침의 근거가 실제 코드에서 어떻게 쓰였는지 확인할 때(2.7) | 근거 전체는 Excel guide-data.xlsx '오픈소스근거' 시트, 방법은 검증 방법 |
| [F. 용어 대조표](f-glossary.md) | 영문 용어의 이 가이드 표기, 병기 규칙, 근거, 약점 이름 표기 주석 | 문서를 쓰며 용어를 맞출 때(1.4) | Excel guide-data.xlsx '용어집' 시트 |
| [G. 선택 워크시트와 점검표](g-worksheets.md) | G-1 새 환경 특성 시트, G-2 환경 선택표, G-3 지침 선택 워크시트, G-4 적용성 판정 기록지, G-5 단계 자가점검표 | 착수 때 환경 프로파일을 만들 때(G-1~G-3), 적용성 판정을 기록할 때(G-4), 단계 검토 때(G-5) | 계산은 지침 선택 도구, 기록 양식과 점검표는 여기에만 있다 |

부록 A~F는 원천 데이터(문서 정보 참고)에서 생성한 표이고, 부록 G는 직접 쓴 양식이다. 전체 데이터는 [내려받기](../downloads.md)의 Excel 2종에 있다.
