# 지침 선택 도구

개발 언어, 운용 환경(하드웨어·운영체제), 사용하는 기능(데이터베이스·파일시스템·외부 입력·인증·암호 등), 개발 환경(개발·시험 망·컴파일러)에 답하면 필요한 지침이 수명주기 단계별로 모인다. 결과는 기준선 활동 33개와 환경 지침 245건에서 고르며, 이 가이드 본문·부록 C와 같은 ID와 제목을 쓴다(기준선 활동의 지침 문구는 요약).

[지침 선택 도구 열기](tools/selection-tool.html){ .md-button .md-button--primary }

## 쓰는 법

1. **질문에 답하기**: 네 가지 질문에 답한다. 개발 언어, 하드웨어, 운영체제, 개발·시험 망, 컴파일러는 하나씩 고르고, 사용하는 기능만 여럿을 고른다. 처음 화면은 예시(ATmega 제어기)를 고른 상태이며 '모두 지우기'로 비운다.
2. **단계별 지침 보기**: 결과는 단계마다 지침 ID와 제목만 한 줄씩 보인다. 지침을 누르면 내용·포함 사유·대상 CWE·근거가 펼쳐지고, ID를 누르면 본문 설명으로 간다. 답하지 않은 질문이나 정하지 않은 특성에 따라 들어갈 수 있는 지침은 단계마다 '확인 필요'로 접어 둔다. '특성 일치'로 표시한 지침은 다른 환경을 위해 쓴 것이지만 특성이 같아서 들어온 것이다. 펼치면 원래 환경과 일치한 조건이 보인다. 망 질문에 어떻게 답해도 NET-IN-04·06·09와 NET-CL-09는 나온다(8.6).
3. **사용하는 기능에 답하기**: 기능을 하나라도 고르거나 '위 기능을 하나도 쓰지 않음'을 고르면 답한 것으로 보고, 고르지 않은 기능에만 해당하는 기준선 활동과 보안약점을 거른다.
4. **해당 보안약점(CWE) 보기**: 지침 아래 접힌 목록에 이 과제에 해당하는 보안약점이 해당·확인 필요·비해당으로 나뉘어 보인다. 범위는 보안약점 점검 목록 44개, 고른 언어의 CWE 언어 뷰(C·C++·Java), 보조 항목 4개이고, 언어 뷰가 없는 C#·Python은 언어 뷰 항목 가운데 MITRE가 그 언어를 적용 언어로 적은 항목(C# 19개, Python 16개)을 더한다. 조건부 항목은 부록 G-4-1 사용 기술 체크리스트와 같은 규칙으로 가른다. 판정 결과와 사유는 부록 G-4에 기록한다.
5. **결과 활용**: '결과를 표로 복사'로 과제 문서에 붙여 넣는다.

**상세 설정.** 화면 아래 '상세 설정'을 펼치면 축마다 환경을 직접 고르고, 특성 프로파일(15개)을 확인·덮어쓰고, 목록에 없는 환경을 특성 시트로 추가할 수 있다. 위 질문의 답은 상세 설정에 그대로 반영되고, 상세 설정에서 바꾼 값도 질문과 결과에 반영된다. 도구는 지침 선택 절차(2.5 ①~⑦) 가운데 ②~⑤를 계산하며, 실행 단위(빌드 환경)가 여럿이면(①) 실행 단위마다 한 번씩 쓴다.

도구 밖에서 하는 일은 ⑥ 보안약점 적용성 판정의 기록(부록 G-4, 도구의 해당 보안약점 목록을 옮겨 적고 사유를 단다. 목록에 없는 항목은 고르지 않은 언어의 언어 뷰 항목이므로 G-4의 규칙대로 묶어 적는다)과 ⑦ 단계 자가점검표(부록 G-5)다. 선택 규칙(특성 목록·조건식·상속)은 [2.4~2.5](ch2-framework.md)와 [부록 G](appendix/g-worksheets.md)에 있다. 같은 데이터는 [내려받기](downloads.md)의 Excel에도 있다.

## 질문과 답의 규칙

**하나씩 고르는 까닭.** 시험과 점검 기준은 실행 단위(빌드 환경) 하나를 기준으로 정한다. 한 빌드에 C와 C++를 함께 쓰는 것처럼 한 축에서 여럿을 골라야 하면 '상세 설정'에서 고른다. 외부 통신을 '모름(환경 기본값)'으로 두면 고른 환경의 기본값을 따른다.

**맞지 않는 조합 안내.** 언어와 환경이 맞지 않으면 그 질문 바로 아래에 알린다. 어느 쪽도 선택을 막지는 않으며, 판정 기준과 근거는 아래 [조합 안내 기준](#combos)에 있다.

| 안내 | 뜻 | 예 | 도구의 처리 |
|---|---|---|---|
| 맞지 않는 조합(붉은색) | 성립하지 않는다. 컴파일러가 고른 언어를 컴파일하지 않거나 하드웨어·운영체제와 맞지 않는다. | MCU와 Windows, Windows와 Wind River Workbench | 질문에서는 맞지 않는 컴파일러를 보이지 않고, 상세 설정에서 고르면 그 항목에 표시한다. |
| 드문 조합(주황색) | 성립할 수 있지만 확인이 필요하다. 공식 사례가 있지만 흔하지 않다. | Java·C#·Python과 마이크로컨트롤러·DSP나 운영체제 없음·RTOS, MCU와 Linux(MMU 없는 Linux), Windows와 GCC(MinGW-w64) | 그 환경용 언어 런타임(예: C#의 .NET nanoFramework, Python의 MicroPython)이 있어야 하므로, 안내의 단추로 상세 설정의 '목록에 없는 환경 추가'를 열어 런타임을 등록한다(2.5 ②). |

**사용하는 기능 목록.** CWE 적용 플랫폼과 행정안전부·KISA 「소프트웨어 개발보안 가이드」 항목이 전제하는 기술을 거꾸로 점검해 정했다(데이터베이스, 파일시스템, OS 명령, 외부 입력, 웹 서버·HTTP, XML, 객체 직렬화, 동적 코드 실행·적재, 인증, 암호·TLS, 현장·원격 업데이트, 오픈소스, 칩 제조사 BSP). 현장·원격 업데이트는 원격과 현장 매체·정비 포트를 함께 묻고(지침·보안약점 판정이 같다), 공장 재프로그래밍만 하면 고르지 않는다. C·C++의 자체 직렬화 형식 해석은 '외부 파일·메시지 입력 해석'에 해당한다.

**언어·환경에 따라 보이는 기능.** 언어나 환경 때문에 성립하지 않는 항목은 보이지 않는다.

| 기능 | 보이는 조건 |
|---|---|
| 시그널 핸들러 | C·C++ |
| 네이티브 코드 호출 | Java·C#·Python |
| POSIX 기능(파일 권한·chroot·프로세스 생성·getlogin) | C·C++와 Linux·VxWorks |
| 커널 드라이버(IOCTL) | C·C++와 Windows·Linux |
| OS 명령 실행 | 운영체제가 있을 때(베어메탈에서는 숨김) |
| 객체 직렬화, 동적 코드 실행·적재 | C·C++가 아닐 때(CWE-502·95·1336·470의 적용 언어에 C·C++가 없다) |

**기능 답에 따른 기준선 활동.**

| 기준선 활동 | 처리 |
|---|---|
| I-04 | 데이터베이스·OS 명령·파일시스템·외부 입력을 하나도 쓰지 않으면 빠진다(외부 입력은 자원 식별자를 정할 수 있어서 함께 본다). |
| T-04 | 외부 입력·외부 통신이 없으면 빠진다. |
| T-06 | 인증·암호를 쓰지 않고 외부 통신이 없으며 현장·원격 업데이트도 하지 않으면 빠진다. 인증이 없는 것 자체가 약점일 수 있으므로 외부 통신이 있으면 남는다. |
| M-03 | 파일시스템이 없으면(S3 = 없음) 빠진다. |
| M-04 | 항상 남는다. 업데이트 경로가 없으면 적용성 판정에 비해당으로 기록한다. |
| D-06 | 항상 남는다. 하드웨어 신뢰 기점이 없고(H3 = 없음) 공장 재프로그래밍만 하면 [보완] 해시 검증으로 대체하고 G-3에 적는다(2.3). |

## 조합 안내 기준 {#combos}

질문 1·2·4의 답끼리 맞지 않거나 드문 조합이면 도구가 그 질문 아래에 아래 안내를 띄운다. 짝은 하드웨어–운영체제, 하드웨어–컴파일러, 운영체제–컴파일러, 언어–하드웨어, 언어–운영체제이고, 언어–컴파일러는 '언어를 컴파일하는 도구만 보인다'로 처리한다. 판정은 환경 데이터의 특성·제약과 벤더·프로젝트 공식 원문으로 했고, 공식 근거를 찾지 못한 짝(단종·레거시 RTOS가 든 짝 등)은 안내하지 않는다. 언어를 특정 환경에 한정하지 않으므로 '드문 조합'은 성립하는 공식 사례가 있는 경우만 적었다(2026. 10. 24. 점검).
