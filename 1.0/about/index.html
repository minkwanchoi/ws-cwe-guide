    문서 이름 「무기체계 소프트웨어 보안약점(CWE) 예방 참고 가이드」
    작성·공개 minkwanchoi(개인 연구자). 교육·연구 목적 공개
    작성 방법 작성자가 목적·범위·구성·용어와 주요 결정을 정하고 결과를 검토했다. 자료 조사, 초안 작성, 예시 코드 작성과 검증에는 생성형 AI(Anthropic Claude)를 썼다. 근거 대조와 예시 검증 방법은 검증 방법에 있다
    라이선스 MIT(제3자 자료 제외). 제3자 자료의 권리와 조건은 출처와 이용 조건에 있다
    문서 지위 개발자 참고 가이드(권고형). 준수 의무를 정하는 규정이 아니다.
    기준일 2026. 11. 2.
    기준 데이터 MITRE CWE 5.0(2026. 10. 28.) / 방위사업청 「무기체계 소프트웨어 개발 및 관리 매뉴얼」(방위사업청 매뉴얼 제2024-6호, 2024. 12. 26. 개정)
    대상 보안약점 197개와 따로 세는 보조 항목 4개(구성은 2.1, 보조 항목 근거는 부록 A-3).
    대상 독자 1차: 개발자(설계·구현·시험 담당) / 2차: 사업관리·품질 담당

    부속 도구 지침 선택 도구(특성 기반 선택·새 환경 추가), 내려받기의 Excel 2종

    이 판의 한계¶

    • 매뉴얼 내용은 방위사업청 행정규칙 게시판의 제2024-6호 첨부 PDF로 확인했다. 첨부 파일명이 '개정안'이고 PDF 생성일이 본문 2025. 1. 8., 부록 2025. 1. 7.이므로, 인쇄 확정본과 같은지는 따로 확인하지 않았다.
    • 처음 CWE 4.20으로 만들고 2026. 11. 2.에 CWE 5.0으로 갱신했다. 원문이 바뀐 항목의 해설과 번역은 다시 썼고, 지침 문구는 바뀐 원문과 대조해 필요한 곳만 고쳤다. 오픈소스 근거의 확인일은 항목마다 적힌 날짜 그대로다.
    • VxWorks 6.x 커널 모드의 단일 주소공간과 Diab 5.x 구판의 보호 기능은 공개된 공식 원문을 찾지 못했다. 사용 버전의 설명서로 확인한다.
    • 이 가이드의 근거는 현행 매뉴얼 제2024-6호다. 논문(최민관 외, 2019)이 설명한 2016년 개정판(제2016-4호) 내용은 연혁으로만 인용하며, 그 원문은 확보하지 않기로 했다(2026. 10. 18.).
    • 환경 지침 245건의 특성 태깅(적용 조건·범위·보정 유형·대상 기준선)은 2026. 10. 16.에 전체를 기존 태그를 보지 않고 생성형 AI로 별도 태깅해 대조하고, 어긋난 곳을 2.3 기준으로 가린 판이다(일치도는 2.3 각주). 보정 유형 '추가'와 '강화'는 판정이 갈리기 쉬웠으므로, 과제에서 쓸 때는 지침 본문과 기준선 활동 문구를 함께 본다.
    • 지침 245건 가운데 원문으로 확인한 근거가 있는 지침은 243건이다. 그중 34건은 지침의 일부만 확인했고(부분, 부록 E), VXW·PSOS·WRW 다수는 그 환경 고유 자료가 아니라 공개 데이터시트나 다른 프로젝트의 일반 자료다. SOC-06과 LCS-01은 뒷받침하는 공개 원문을 찾지 못했다.
    • Microsoft .NET 보안 규칙(Security 범주 94개)과 CWE의 대응(부록 D-1)은 규칙 문서에 CWE 번호가 없어 이 가이드가 판단한 것이다(BinaryFormatter 관련 7개만 Microsoft 문서에 근거가 있음). 분석기 동작은 .NET SDK 10.0.402로 net10.0(2026. 10. 18.)과 net48(2026. 10. 28.) 대상에서 시험했다. .NET Framework 판은 4.8만 시험했다.
    • Bandit 규칙과 CWE의 대응(부록 D-2)은 75개 가운데 53개가 Bandit이 붙인 CWE를 따르고, 22개는 약점이 일으키는 결과를 기준으로 이 가이드가 판단했다. Bandit 1.9.4 소스로 대조했으며 규칙을 실행해 시험한 것은 예시에 쓰인 규칙뿐이다.
    • Java XML 해석기 설정(LJ-02, 보조 항목 CWE-611)은 Oracle Java SE 21 문서로 확인하고 JDK 21.0.12에서만 시험했다(2026. 10. 28.). Find Security Bugs의 XXE 패턴이 안전한 설정과 안전하지 않은 설정을 실제로 구분하는지는 시험하지 않았다.
    • 보조 언어 지침은 CWE 언어 뷰에서 도출하지 않았다. C#과 Python은 CWE 언어 뷰가 없어 언어 지침 13건씩을 KISA 「Python 시큐어코딩 가이드」, Microsoft Learn, 도구 문서와 참조 프로젝트 원문에서 골랐다. 통합 및 시험·유지보수 단계 지침은 언어별 3건(LCS-11~13, LPY-11~13)을 더해 단계별 2~3건이며, 나머지는 기준선 활동(T-01·T-02·T-04~T-08, M-01~M-07)으로 다룬다.
