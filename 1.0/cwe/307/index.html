    Improper Restriction of Excessive Authentication Attempts

    항목 내용
    추상화 수준 기본(Base)
    상태 초안(Draft)
    소속 「보안약점 점검 목록」(44개)
    가이드 적용성 조건부 — 사용자 계정·비밀번호 사용
    적용 플랫폼 언어: 언어 무관, Go
    원문 MITRE CWE-307 (CWE 5.0)

    한 줄 요약

    짧은 시간 안에 반복되는 인증 실패를 막는 조치가 충분하지 않아 생기는 약점이다.

    → 나쁜 예·좋은 예

    설명(Description)¶

    제품이 짧은 시간 안에 여러 번 실패하는 인증 시도를 막을 충분한 조치를 구현하지 않는다.

    원문(Description)

    The product does not implement sufficient measures to prevent multiple failed authentication attempts within a short time frame.

    발생 단계(Modes Of Introduction)¶

    CWE 단계(Phase) 수명주기 단계(가이드 대응) 설명
    아키텍처·설계(Architecture and Design) 설계 작위(COMMISSION): 아키텍처 보안 전술과 관련된 잘못된 설계로 생기는 약점이다.

    영향(Common Consequences)¶

    영역 영향 설명
    접근 통제 보호 메커니즘 우회 공격자는 서로 다른 비밀번호로 인증을 횟수 제한 없이 시도해, 결국 무차별 대입 공격(brute force attack)으로 대상 계정에 접근할 수 있다.

    완화책(Potential Mitigations)¶

    원문 완화책 2건(수명주기 단계로 묶은 규칙은 색인에 있다).

    요구사항 분석 (본문 제3장)¶

    원문 완화책 없음. 이 단계의 기준선 활동: R-01 보안 요구사항 정의

    설계 (본문 제4장)¶

    CWE 단계(Phase) 전략 요지
    아키텍처·설계(Architecture and Design) — 흔히 쓰는 보호 방법으로는 적은 횟수의 실패 뒤 사용자 연결 끊기, 시간 제한(timeout) 적용, 대상 계정 잠금, 사용자에게 계산 작업 요구가 있다.
    원문

    Common protection mechanisms include:

    - Disconnecting the user after a small number of failed attempts

    - Implementing a timeout

    - Locking out a targeted account

    - Requiring a computational task on the user's part.
    아키텍처·설계(Architecture and Design) 라이브러리·프레임워크 활용 이 약점이 생기지 않게 하거나 피하기 쉬운 구조를 제공하는 검증된 라이브러리·프레임워크를 쓴다 [REF-1482]. OpenSSL이나 ESAPI Authenticator처럼 인증 기능을 갖춘 라이브러리 사용을 고려한다 [REF-45].
    원문

    Use a vetted library or framework that does not allow this weakness to occur or provides constructs that make this weakness easier to avoid [REF-1482].

    Consider using libraries with authentication capabilities such as OpenSSL or the ESAPI Authenticator. [REF-45]

    구현 (본문 제5장)¶

    원문 완화책 없음

    예시(나쁜 예·좋은 예)¶

    아래 코드는 이 가이드가 다음 상황을 가정해 새로 작성한 것이다. 정비 키패드·운용자 콘솔·정비 정보 시스템·키 적재 장비가 PIN이나 비밀번호로 로그인을 받는다. 예시의 main(Python은 맨 아래 반복문)은 공격자가 가능한 값을 처음부터 차례로 넣어 보는 무차별 대입을 흉내 내며, 실패 횟수 제한이 있는지에 따라 결과가 갈린다. 언어마다 분석기·새니타이저·실행 결과로 나쁜 예는 잡히고 좋은 예는 잡히지 않음을 확인했다. 좋은 예는 그 약점 하나를 막는 최소 예이며 그대로 운용 코드가 되는 것은 아니다. 언어 상자를 눌러 펼친다.

    C

    나쁜 예

    #include <stdio.h>

/* 예시용 등록 PIN: 실제로는 보호 저장소에 둔 해시와 비교한다 */
static const unsigned enrolled_pin = 7351u;

/* 정비 키패드 로그인: 틀려도 횟수를 세지 않고 바로 다시 받는다 */
static int keypad_login(unsigned pin)
{
    return pin == enrolled_pin;
}

int main(void)
{
    /* 공격자가 0000부터 9999까지 차례로 넣어 보는 상황 */
    unsigned tries = 0;
    for (unsigned pin = 0; pin <= 9999u; ++pin) {
        ++tries;
        if (keypad_login(pin)) {
            printf("UNLOCKED after %u attempts\n", tries);
            return 0;
        }
    }
    puts("all attempts failed");
    return 0;
}

    틀린 PIN을 세지도 늦추지도 않아 4자리 PIN 전체(1만 개)를 차례로 넣으면 결국 열린다.

    좋은 예

    #include <stdio.h>

#define MAX_FAILURES 5u

static const unsigned enrolled_pin = 7351u;    /* 시험용 등록값(실제로는 보호 저장소의 해시) */

/* 실패 횟수와 잠금 상태: 실제로는 비휘발성 메모리에 두어 전원을 다시 넣어도 유지한다 */
static struct { unsigned failures; int locked; } guard;

typedef enum { LOGIN_OK, LOGIN_BAD_PIN, LOGIN_LOCKED } LoginResult;

static LoginResult keypad_login(unsigned pin)
{
    if (guard.locked) {
        return LOGIN_LOCKED;                    /* 해제는 관리자 절차로만 */
    }
    if (pin == enrolled_pin) {
        guard.failures = 0;
        return LOGIN_OK;
    }
    if (++guard.failures >= MAX_FAILURES) {
        guard.locked = 1;                       /* 감사 로그에도 남긴다 */
    }
    return LOGIN_BAD_PIN;
}

int main(void)
{
    unsigned tries = 0;
    for (unsigned pin = 0; pin <= 9999u; ++pin) {
        ++tries;
        LoginResult r = keypad_login(pin);
        if (r == LOGIN_OK) {
            printf("UNLOCKED after %u attempts\n", tries);
            return 0;
        }
        if (r == LOGIN_LOCKED) {
            printf("LOCKED after %u failures; attempt %u refused\n", guard.failures, tries);
            return 0;
        }
    }
    puts("all attempts failed");
    return 0;
}

    실패 횟수를 세어 한도(5회)에서 잠그고, 잠금 해제는 관리자 절차로만 한다. 전원 재인가로 횟수가 초기화되지 않도록 실제로는 비휘발성 메모리에 두고, 비교 전에 횟수를 먼저 저장해 판정 직후 전원을 끊어 기록을 건너뛰지 못하게 한다.

    검증: 실행 결과 — 나쁜 예에서 UNLOCKED after … attempts 검출, 좋은 예에서 미검출·LOCKED after … failures; attempt … refused 출력 확인 · 참고: MITRE CWE-307 Demonstrative Example 4(시도 횟수 제한 없는 사용자 확인 반복) 참고, 이 가이드가 새로 작성

    C++

    나쁜 예

    #include <cstdio>
#include <iostream>
#include <string>

// 지상 통제 콘솔의 운용자 인증 서비스
class OperatorAuth {
public:
    explicit OperatorAuth(std::string code) : code_(std::move(code)) {}

    // 실패해도 기록·지연·잠금이 없어 같은 계정으로 끝없이 다시 시도할 수 있다
    bool verify(const std::string &account, const std::string &code) {
        (void)account;
        return code == code_;
    }

private:
    std::string code_;
};

int main() {
    OperatorAuth auth("482916");  // 시험용 등록값(실제로는 보호 저장소)
    char guess[8];
    for (long n = 0; n < 1000000; ++n) {        // 6자리 코드를 전수 대입
        std::snprintf(guess, sizeof guess, "%06ld", n);
        if (auth.verify("opr03", guess)) {
            std::cout << "UNLOCKED after " << n + 1 << " attempts\n";
            return 0;
        }
    }
    std::cout << "not found\n";
    return 0;
}

    운용자 인증 서비스가 실패를 기록하지 않아 6자리 코드도 무차별 대입으로 찾아낸다.

    좋은 예

    #include <cstdio>
#include <iostream>
#include <map>
#include <string>

class OperatorAuth {
public:
    enum class Result { Ok, Rejected, Locked };
    static constexpr int kMaxFailures = 5;

    explicit OperatorAuth(const std::map<std::string, std::string> &enrolled) {
        for (const auto &[account, code] : enrolled) accounts_[account] = Entry{code, 0};
    }

    // 등록 계정별 실패 횟수를 장비 쪽에 남기고, 한도를 넘으면 잠근다
    Result verify(const std::string &account, const std::string &code) {
        auto it = accounts_.find(account);      // 모르는 계정 이름으로 집계 항목을 늘리지 않는다
        if (it == accounts_.end()) return Result::Rejected;
        Entry &e = it->second;
        if (e.failures >= kMaxFailures) return Result::Locked;   // 잠금 해제는 관리자 절차로
        if (code == e.code) {
            e.failures = 0;
            return Result::Ok;
        }
        ++e.failures;                           // 실제로는 지연 시간도 늘리고 감사 로그를 남긴다
        return Result::Rejected;
    }

private:
    struct Entry { std::string code; int failures; };
    std::map<std::string, Entry> accounts_;
};

int main() {
    OperatorAuth auth({{"opr03", "482916"}});   // 시험용 등록값(실제로는 보호 저장소의 해시)
    char guess[8];
    for (long n = 0; n < 1000000; ++n) {
        std::snprintf(guess, sizeof guess, "%06ld", n);
        auto r = auth.verify("opr03", guess);
        if (r == OperatorAuth::Result::Ok) {
            std::cout << "UNLOCKED after " << n + 1 << " attempts\n";
            return 0;
        }
        if (r == OperatorAuth::Result::Locked) {
            std::cout << "LOCKED after " << OperatorAuth::kMaxFailures << " failures; attempt " << n + 1 << " refused\n";
            return 0;
        }
    }
    std::cout << "not found\n";
}

    등록 계정별 실패 횟수를 장비 쪽에 두고 한도에서 잠근다. 등록되지 않은 계정 이름으로는 집계 항목을 만들지 않고 거부해, 임의 이름을 보내 메모리를 늘리지 못하게 한다. 예시의 코드 값은 시험용 등록값이다. 실제로는 보호 저장소의 해시와 비교하고, 실패할수록 응답 지연을 늘리며 감사 로그를 남긴다.

    검증: 실행 결과 — 나쁜 예에서 UNLOCKED after … attempts 검출, 좋은 예에서 미검출·LOCKED after … failures; attempt … refused 출력 확인 · 참고: MITRE CWE-307 Demonstrative Example 2(인증 시도 제한 없음) 참고, 이 가이드가 새로 작성

    C#

    나쁜 예

    var gate = new KeyLoaderGate(expectedPin: "5308");    // 시험용 등록값(실제로는 보호 저장소)
int tries = 0;
for (int n = 0; n < 10000; n++)
{
    tries++;
    if (gate.Unlock(n.ToString("D4", System.Globalization.CultureInfo.InvariantCulture)))
    {
        Console.WriteLine($"UNLOCKED after {tries} attempts");
        return;
    }
}
Console.WriteLine("not found");

// 키 적재 장비(fill device) 잠금 해제: 틀린 PIN을 몇 번이고 받아 준다
sealed class KeyLoaderGate(string expectedPin)
{
    public bool Unlock(string pin) => string.Equals(pin, expectedPin, StringComparison.Ordinal);
}

    키 적재 장비의 잠금 해제가 틀린 PIN을 몇 번이고 받아 주어 4자리 PIN을 무차별 대입으로 찾아낸다.

    좋은 예

    var gate = new KeyLoaderGate(expectedPin: "5308");   // 시험용 등록값(실제로는 보호 저장소의 해시)
int tries = 0;
for (int n = 0; n < 10000; n++)
{
    tries++;
    var r = gate.Unlock(n.ToString("D4", System.Globalization.CultureInfo.InvariantCulture));
    if (r == UnlockResult.Ok)
    {
        Console.WriteLine($"UNLOCKED after {tries} attempts");
        return;
    }
    if (r == UnlockResult.Locked)
    {
        Console.WriteLine($"LOCKED after {KeyLoaderGate.MaxFailures} failures; attempt {tries} refused");
        return;
    }
}
Console.WriteLine("not found");

enum UnlockResult { Ok, Rejected, Locked }

// 실패 횟수를 세어 한도에서 잠근다(실제로는 횟수를 비휘발성 저장소에 두고, 잠기면 키를 소거하는 정책도 검토)
sealed class KeyLoaderGate(string expectedPin)
{
    public const int MaxFailures = 3;
    int failures;

    public UnlockResult Unlock(string pin)
    {
        if (failures >= MaxFailures)
        {
            return UnlockResult.Locked;
        }
        if (string.Equals(pin, expectedPin, StringComparison.Ordinal))
        {
            failures = 0;
            return UnlockResult.Ok;
        }
        failures++;
        return UnlockResult.Rejected;
    }
}

    실패 횟수를 세어 3회에서 잠근다. 실제 장비에서는 횟수를 비휘발성 저장소에 두어 전원을 다시 넣어도 유지하고, 비교 전에 횟수를 먼저 저장해 판정 직후 전원을 끊어 기록을 건너뛰지 못하게 하며, 잠기면 보관 키를 소거할지 정책으로 정한다.

    검증: 실행 결과 — 나쁜 예에서 UNLOCKED after … attempts 검출, 좋은 예에서 미검출·LOCKED after … failures; attempt … refused 출력 확인 · 참고: MITRE CWE-307 Demonstrative Example 2(인증 시도 제한 없음) 참고, 이 가이드가 새로 작성

    Java

    나쁜 예

    public class Example {

    좋은 예

    import java.util.HashMap;
import java.util.Map;

public class Example {
    enum Outcome { OK, REJECTED, LOCKED }

    static final class MaintPortal {
        static final int MAX_FAILURES = 5;
        private final Map<String, String> enrolled;
        private final Map<String, Integer> failures = new HashMap<>();   // 서버 쪽에 보관

        MaintPortal(Map<String, String> enrolled) {
            this.enrolled = Map.copyOf(enrolled);
        }

        // 읽기·비교·갱신을 한 덩어리로 묶어 동시 요청에서 횟수를 잃지 않게 한다
        synchronized Outcome signIn(String user, String typed) {
            String passcode = enrolled.get(user);
            if (passcode == null) {
                return Outcome.REJECTED;                  // 모르는 계정 이름으로 집계 항목을 늘리지 않는다
            }
            int failed = failures.getOrDefault(user, 0);
            if (failed >= MAX_FAILURES) {
                return Outcome.LOCKED;                    // 관리자 해제 전까지 거부
            }
            if (typed.equals(passcode)) {
                failures.remove(user);
                return Outcome.OK;
            }
            failures.put(user, failed + 1);               // 실제로는 감사 로그·경보도 남긴다
            return Outcome.REJECTED;
        }
    }

    public static void main(String[] args) {
        // 시험용 등록값(실제로는 보호 저장소의 해시)
        MaintPortal portal = new MaintPortal(Map.of("tech11", "w7k2"));
        String chars = "abcdefghijklmnopqrstuvwxyz0123456789";
        int tries = 0;
        for (char a : chars.toCharArray())
            for (char b : chars.toCharArray())
                for (char c : chars.toCharArray())
                    for (char d : chars.toCharArray()) {
                        tries++;
                        Outcome o = portal.signIn("tech11", "" + a + b + c + d);
                        if (o == Outcome.OK) {
                            System.out.println("UNLOCKED after " + tries + " attempts");
                            return;
                        }
                        if (o == Outcome.LOCKED) {
                            System.out.println("LOCKED after " + MaintPortal.MAX_FAILURES
                                    + " failures; attempt " + tries + " refused");
                            return;
                        }
                    }
        System.out.println("not found");
    }
}

    등록 계정별 실패 횟수를 서버 쪽에 두고 한도에서 잠근다. 등록되지 않은 계정 이름은 집계 항목을 만들지 않고 거부해 임의 이름으로 메모리를 늘리지 못하게 하고, 동시 요청에서 횟수를 잃지 않게 읽기와 갱신을 묶는다. 실제 서비스에서는 출처(단말)별 횟수도 함께 세고, 연속 실패 자동화 시험으로 확인한다(T-06).

    import hmac
import time

PIN_VERIFIER = "4817"                 # 시험용 등록값. 실제로는 해시 검증값을 보호 저장소에 둔다
MAX_FAILURES = 5
LOCK_SECONDS = 900


class KeypadLogin:
    def __init__(self):
        self.failures = 0
        self.locked_until = 0.0

    def try_pin(self, pin):
        now = time.monotonic()
        if now < self.locked_until:
            return "locked"
        if hmac.compare_digest(pin.encode(), PIN_VERIFIER.encode()):
            self.failures = 0
            return "ok"
        self.failures += 1
        if self.failures >= MAX_FAILURES:       # 연속 실패가 한도에 이르면 잠그고 감사 기록을 남긴다
            self.locked_until = now + LOCK_SECONDS
            print(f"audit: keypad locked after {self.failures} failures")
        return "fail"


login = KeypadLogin()
for n in range(10000):
    result = login.try_pin(f"{n:04d}")
    if result == "ok":
        print(f"UNLOCKED after {n + 1} attempts")
        break
    if result == "locked":
        print(f"locked at attempt {n + 1}: guessing stopped")
        break
