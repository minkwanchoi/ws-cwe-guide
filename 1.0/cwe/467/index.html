    Use of sizeof() on a Pointer Type

    항목 내용
    추상화 수준 변형(Variant)
    상태 초안(Draft)
    소속 「보안약점 점검 목록」(44개) · 언어 뷰 C·C++(CWE-658·659)
    가이드 적용성 해당
    적용 플랫폼 언어: C, C++
    원문 MITRE CWE-467 (CWE 5.0)

    한 줄 요약

    가리키는 데이터의 크기를 구하려다 포인터 타입에 sizeof()를 호출하는 약점이다.

    → 나쁜 예·좋은 예

    설명(Description)¶

    프로그래머가 포인터가 가리키는 데이터의 크기를 구하려 했는데 코드가 포인터 타입에 sizeof()를 호출하는 약점이다.

    원문(Description)

    The code calls sizeof() on a pointer type, when the programmer intended to determine the size of the data that is being pointed to.

    발생 단계(Modes Of Introduction)¶

    CWE 단계(Phase) 수명주기 단계(가이드 대응) 설명
    구현(Implementation) 구현 포인터에 sizeof()를 쓰는 것이 때로 유용한 정보를 줄 수도 있으며, 대표적인 경우가 플랫폼의 워드 크기를 알아낼 때다. 그러나 sizeof(pointer)가 보이면 대개 잘못된 계산, 곧 버그다.

    영향(Common Consequences)¶

    영역 영향 설명
    무결성 / 기밀성 메모리 수정 / 메모리 읽기 이 오류로 흔히 필요한 것보다 훨씬 작은 버퍼를 할당하게 되어 버퍼 오버플로 같은 결과적 약점이 생길 수 있다.

    완화책(Potential Mitigations)¶

    원문 완화책 1건(수명주기 단계로 묶은 규칙은 색인에 있다).

    요구사항 분석 (본문 제3장)¶

    원문 완화책 없음

    설계 (본문 제4장)¶

    원문 완화책 없음

    구현 (본문 제5장)¶

    CWE 단계(Phase) 전략 요지
    구현(Implementation) — 'sizeof(pointer)' 대신 'sizeof(*pointer)' 같은 표현을 쓴다. 단, 플랫폼 독립성을 일부 얻으려고 포인터 타입에 sizeof()를 쓰려는 경우나 스택에 변수를 할당하는 경우는 예외다.
    원문

    Use expressions such as "sizeof(*pointer)" instead of "sizeof(pointer)", unless you intend to run sizeof() on a pointer type to gain some platform independence or if you are allocating a variable on the stack.

    통합 및 시험 (본문 제6장)¶

    원문 완화책 없음

    유지보수 (본문 제7장)¶

    원문 완화책 없음

    예시(나쁜 예·좋은 예)¶

    아래 코드는 이 가이드가 다음 상황을 가정해 새로 작성한 것이다. 정비 단말에서 받은 온도 보정 계수를 센서 설정 표에 복사한다(C). 원격측정(텔레메트리) 송신 프레임을 다음 주기 전에 0으로 비운다(C++). 두 경우 모두 크기를 sizeof로 구한다. 언어마다 분석기·새니타이저·실행 결과로 나쁜 예는 잡히고 좋은 예는 잡히지 않음을 확인했다. 좋은 예는 그 약점 하나를 막는 최소 예이며 그대로 운용 코드가 되는 것은 아니다. 언어 상자를 눌러 펼친다.

    C

    나쁜 예

    #include <stdint.h>
#include <stdio.h>
#include <string.h>

#define COEF_COUNT 16

typedef struct {
    uint16_t sensor_id;
    int16_t coef[COEF_COUNT];      /* 온도 보정 계수 */
} CalTable;

/* 정비 단말에서 받은 보정 계수를 센서 설정 표에 적용한다 */
static void apply_cal(CalTable *t, const int16_t *coef)
{
    memcpy(t->coef, coef, sizeof(coef));   /* 배열 크기가 아니라 포인터 크기만큼만 복사 */
}

int main(void)
{
    int16_t received[COEF_COUNT];
    for (int i = 0; i < COEF_COUNT; ++i) {
        received[i] = (int16_t)(100 + i);
    }
    CalTable t = {7, {0}};
    apply_cal(&t, received);
    printf("coef[15]=%d (expected 115)\n", t.coef[15]);
    return 0;
}

    함수 인자 coef는 배열이 아니라 포인터이므로 sizeof(coef)는 포인터 크기(64비트 호스트에서 8바이트)다. 계수 16개 중 앞의 4개만 복사되고 나머지는 0으로 남아 센서 값이 틀어진다. 타깃이 32비트면 복사량이 또 달라진다.

    좋은 예

    #include <stdint.h>
#include <stdio.h>
#include <string.h>

#define COEF_COUNT 16

typedef struct {
    uint16_t sensor_id;
    int16_t coef[COEF_COUNT];      /* 온도 보정 계수 */
} CalTable;

/* 정비 단말에서 받은 보정 계수를 센서 설정 표에 적용한다. 성공 0, 개수 불일치 -1 */
static int apply_cal(CalTable *t, const int16_t *coef, size_t count)
{
    if (count != COEF_COUNT) {
        return -1;                          /* 개수는 호출자가 따로 알려 준다 */
    }
    memcpy(t->coef, coef, sizeof t->coef); /* 크기는 대상 배열에서 잰다 */
    return 0;
}

int main(void)
{
    int16_t received[COEF_COUNT];
    for (int i = 0; i < COEF_COUNT; ++i) {
        received[i] = (int16_t)(100 + i);
    }
    CalTable t = {7, {0}};
    if (apply_cal(&t, received, sizeof received / sizeof received[0]) != 0) {
        puts("calibration rejected");
        return 1;
    }
    printf("coef[15]=%d (expected 115)\n", t.coef[15]);
    return 0;
}

    복사 크기는 대상 배열(sizeof t->coef)에서 재고, 원본 개수는 인자로 따로 받아 맞지 않으면 거부한다. 이런 실수는 컴파일러 경고로 잡을 수 있으므로 경고 0건을 빌드 통과 조건으로 둔다(LC-08).

    검증: 컴파일러 경고 — 나쁜 예에서 -Wsizeof-pointer-memaccess 검출, 좋은 예에서 미검출 · 참고: MITRE CWE-467 Demonstrative Example 1·2(포인터에 sizeof를 적용해 할당·비교 크기를 계산) 참고, 이 가이드가 새로 작성

    C++

    나쁜 예

    #include <cstdint>
#include <cstdio>
#include <cstring>

// 원격측정(텔레메트리) 송신 프레임
struct TelemetryFrame {
    std::uint16_t sync;
    std::uint8_t body[60];
    std::uint16_t crc;
};

class Downlink {
public:
    // 다음 주기 송신 전에 프레임을 비운다
    void reset(TelemetryFrame *frame) {
        std::memset(frame, 0, sizeof(frame));   // 구조체가 아니라 포인터 크기만큼만 지운다
    }
};

int main() {
    TelemetryFrame f{};
    f.crc = 0xBEEF;                             // 이전 주기의 값
    Downlink link;
    link.reset(&f);
    std::printf("crc after reset 0x%04X\n", static_cast<unsigned>(f.crc));
    return 0;
}

    frame은 구조체 포인터이므로 sizeof(frame)은 포인터 크기다. memset이 앞의 몇 바이트만 지우고 crc 등 뒤쪽 필드에는 이전 주기의 값이 남아 그대로 송신된다.

    좋은 예

    #include <cstdint>
#include <cstdio>

// 원격측정(텔레메트리) 송신 프레임
struct TelemetryFrame {
    std::uint16_t sync;
    std::uint8_t body[60];
    std::uint16_t crc;
};

class Downlink {
public:
    // 다음 주기 송신 전에 프레임을 비운다
    void reset(TelemetryFrame &frame) {
        frame = TelemetryFrame{};   // 값 초기화로 모든 멤버를 0으로: 크기 계산이 필요 없다
    }
};

int main() {
    TelemetryFrame f{};
    f.crc = 0xBEEF;                 // 이전 주기의 값
    Downlink link;
    link.reset(f);
    std::printf("crc after reset 0x%04X\n", static_cast<unsigned>(f.crc));
    return 0;
}

    포인터 대신 참조로 받고 값 초기화(frame = TelemetryFrame{})로 모든 멤버를 비운다. 크기 계산 자체가 없어져 같은 실수가 생길 여지가 없다.

    검증: clang-tidy — 나쁜 예에서 bugprone-sizeof-expression 검출, 좋은 예에서 미검출 · 참고: MITRE CWE-467 Demonstrative Example 1(구조체 대신 구조체 포인터에 sizeof를 적용) 참고, 이 가이드가 새로 작성

    C# — 예시 없음(언어상 생기지 않음): C#의 관리 코드는 배열 Length를 쓰고 포인터 형식은 unsafe 코드에서만 쓸 수 있다. unsafe 코드의 sizeof와 P/Invoke 구조체 크기 계산(Marshal.SizeOf)에서는 포인터와 구조체를 혼동할 수 있으므로 그 범위에는 C 예시와 C 지침을 적용한다(LCS-02).

    Java — 예시 없음(언어상 생기지 않음): Java에는 sizeof 연산자와 포인터가 없고 배열 크기는 length로 얻으므로 이 약점이 생기지 않는다. JNI로 부르는 네이티브 코드에는 C 예시를 적용한다(LJ-08).

    Python — 예시 없음(언어상 생기지 않음): Python에는 sizeof 연산자와 포인터가 없고 크기는 len()으로 얻으므로 이 약점이 생기지 않는다. ctypes에서 ctypes.sizeof(POINTER(…))처럼 포인터 형의 크기를 구조체 크기로 잘못 쓰는 경우는 같은 문제가 생기므로 그 범위에는 C 예시와 C 지침을 적용한다.

    MITRE 원문 예시(Demonstrative Examples, 영문 2건)

    Example 1. Care should be taken to ensure sizeof returns the size of the data structure itself, and not the size of the pointer to the data structure.

    In this example, sizeof(foo) returns the size of the pointer.

    Bad / C

    double *foo;
...
foo = (double *)malloc(sizeof(foo));

    In this example, sizeof(*foo) returns the size of the data structure and not the size of the pointer.

    Good / C

    double *foo;
...
foo = (double *)malloc(sizeof(*foo));

    Example 2. This example defines a fixed username and password. The AuthenticateUser() function is intended to accept a username and a password from an untrusted user, and check to ensure that it matches the username and password. If the username and password match, AuthenticateUser() is intended to indicate that authentication succeeded.

    Bad / C

                         /* Ignore CWE-259 (hard-coded password) and CWE-309 (use of password system for authentication) for this example. */

char *username = "admin";
char *pass = "password";

int AuthenticateUser(char *inUser, char *inPass) {

  printf("Sizeof username = %d\n", sizeof(username));
  printf("Sizeof pass = %d\n", sizeof(pass));

  if (strncmp(username, inUser, sizeof(username))) {
    printf("Auth failure of username using sizeof\n");
    return(AUTH_FAIL);
  }

                             /* Because of CWE-467, the sizeof returns 4 on many platforms and architectures. */

  if (! strncmp(pass, inPass, sizeof(pass))) {
    printf("Auth success of password using sizeof\n");
    return(AUTH_SUCCESS);
  }
  else {
    printf("Auth fail of password using sizeof\n");
    return(AUTH_FAIL);
  }

}

int main (int argc, char **argv)
{

  int authResult;

  if (argc < 3) {
    ExitError("Usage: Provide a username and password");
  }
  authResult = AuthenticateUser(argv[1], argv[2]);
  if (authResult != AUTH_SUCCESS) {
    ExitError("Authentication failed");
  }
  else {
    DoAuthenticatedTask(argv[1]);
  }

}

    In AuthenticateUser(), because sizeof() is applied to a parameter with an array type, the sizeof() call might return 4 on many modern architectures. As a result, the strncmp() call only checks the first four characters of the input password, resulting in a partial comparison (CWE-187), leading to improper authentication (CWE-287).

    Because of the partial comparison, any of these passwords would still cause authentication to succeed for the "admin" user:

    Attack

    pass5
passABCDEFGH
passWORD

    Because only 4 characters are checked, this significantly reduces the search space for an attacker, making brute force attacks more feasible.

    The same problem also applies to the username, so values such as "adminXYZ" and "administrator" will succeed for the username.

    탐지 방법(Detection Methods)¶

    방법 요지 효과성
    자동 정적 분석 흔히 SAST(Static Application Security Testing)라 부르는 자동 정적 분석(static analysis)은 소스코드(또는 바이너리·컴파일된 코드)를 실행하지 않고 분석해 이 약점의 일부 사례를 찾을 수 있으며, 대개 데이터 흐름·제어 흐름 모델을 만든 뒤 입력 출처('source')와 외부 구성요소나 운영체제 같은 하위 계층과 상호작용하는 목적지('sink')를 잇는 잠재적 취약 패턴을 찾는다.
    원문

    Automated static analysis, commonly referred to as Static Application Security Testing (SAST), can find some instances of this weakness by analyzing source code (or binary/compiled code) without having to execute it. Typically, this is done by building a model of data flow and control flow, then searching for potentially-vulnerable patterns that connect "sources" (origins of input) with "sinks" (destinations where the data interacts with external components, a lower layer such as the OS, etc.)

    		 높음(High)

    탐지 방법별 시험 활동은 제6장에 있다.

    도구 미지원 시 대안. 공통안은 6.2에 있고, 이 절에는 이 항목의 고유안만 적는다.

    점검 착안점 활동 근거
    (C·C++) sizeof의 피연산자가 포인터형 변수(함수 인자로 받은 배열 포함)인 곳을 찾고, memcpy·memset·malloc의 크기 인자와 원소 수 계산에 sizeof(*p)나 원소 수 상수를 써야 하는지 확인한다. I-09·I-05 [CWE] CWE-467 완화책(Implementation: sizeof(*pointer) 사용) · [표준] SEI CERT ARR01-C·MEM35-C
    (C·C++) 사업 정적 분석 도구가 이 항목을 지원하지 않으면 -Wsizeof-pointer-memaccess·-Wsizeof-array-argument 경고를 켜서 컴파일하고, clang-tidy bugprone-sizeof-expression으로 다시 본다. I-08·I-09 [예시] CWE-467 예시 검증(-Wsizeof-pointer-memaccess, bugprone-sizeof-expression)
    (C·C++) 포인터 크기가 다른 두 빌드(32비트 타깃, 64비트 호스트)에서 같은 단위시험을 돌려 복사·초기화된 바이트 수가 달라지는지, 구조체 뒤쪽 필드(CRC 등)에 이전 값이 남는지 확인한다. I-10·T-02 [예시] CWE-467 예시(64비트 호스트에서 8바이트만 복사, 뒤쪽 필드 잔존) · [보완]
    • ① 원문 탐지 방법은 자동 정적 분석뿐이다. 다른 정적 분석 도구·컴파일러 경고로 점검한다.
    • ③ SEI CERT 대응 규칙: ARR01-C, MEM35-C

    단계 지침
    요구사항 분석 —
    설계 버퍼 크기는 명시적 상수·매크로로 관리하는 코딩규칙(coding rule)을 정의한다.
    구현(C·C++) sizeof(ptr) 대신 sizeof(*ptr) 또는 배열 원소 개수 매크로를 사용하고, 배열이 함수 인자로 전달되면 길이를 별도 인자로 받는다.
    구현(Java) 해당 없음.
    통합 및 시험 정적 분석(cppcheck, clang-tidy bugprone-sizeof-expression)과 -Wsizeof-pointer-memaccess로 탐지한다.
    유지보수 자료형을 배열에서 포인터로 변경할 때 sizeof 사용처의 영향을 분석한다.
    임베디드 고려 포인터 크기가 플랫폼마다 다르므로(AVR 2바이트, Cortex-M 4바이트, 64비트 SBC 8바이트) 크로스 플랫폼 코드에서 특히 주의한다.
