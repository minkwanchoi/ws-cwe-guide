    Improper Certificate Validation

    항목 내용
    추상화 수준 기본(Base)
    상태 초안(Draft)
    소속 보조 항목(「보안약점 점검 목록」·언어 뷰 밖, 매뉴얼 7-10쪽 '추가 식별' 근거)

    적용 플랫폼 언어: 언어 무관, Go · 기술: 기술 무관, 웹 기반(Web Based), 모바일(Mobile)
    원문 MITRE CWE-295 (CWE 5.0)

    한 줄 요약

    인증서를 검증하지 않거나 잘못 검증하는 약점이다.

    → 나쁜 예·좋은 예

    설명(Description)¶

    제품이 인증서를 검증하지 않거나 잘못 검증하는 약점이다.

    배경(Background Details)

    인증서는 신원(주체, principal)을 암호 키와 연결하는 토큰이다. 인증서로 공개 키가 소유자로 추정되는 쪽의 것인지 확인할 수 있다.

    원문(Description · Background Details)

    The product does not validate, or incorrectly validates, a certificate.

    A certificate is a token that associates an identity (principal) to a cryptographic key. Certificates can be used to check if a public key belongs to the assumed owner.

    발생 단계(Modes Of Introduction)¶

    CWE 단계(Phase) 수명주기 단계(가이드 대응) 설명
    아키텍처·설계(Architecture and Design) 설계 —
    구현(Implementation) 구현 실현(REALIZATION): 이 약점은 아키텍처 보안 전술을 구현하는 과정에서 생긴다.
    구현(Implementation) 구현 제품이 인증서 고정(certificate pinning)을 쓸 때, 개발자가 인증서를 고정하기 전에 인증서의 관련 구성요소를 모두 제대로 검증하지 않을 수 있다. 이 때문에 고정을 마친 뒤에는 시험하기가 어렵거나 비용이 많이 들 수 있다.

    영향(Common Consequences)¶

    영역 영향 설명
    무결성 / 인증 보호 메커니즘 우회 / 권한 획득 또는 신원 도용 인증서가 유효하지 않거나 악의적이면, 공격자가 호스트와 클라이언트 사이의 통신 경로에 끼어들어 신뢰된 개체로 위장할 수 있다. 제품이 신뢰된 호스트라고 믿고 악의적인 호스트에 연결하거나, 신뢰된 호스트에서 온 것처럼 보이는 위조 데이터를 받아들이도록 속을 수 있다.

    완화책(Potential Mitigations)¶

    원문 완화책 2건(수명주기 단계로 묶은 규칙은 색인에 있다).

    요구사항 분석 (본문 제3장)¶

    원문 완화책 없음

    설계 (본문 제4장)¶

    CWE 단계(Phase) 전략 요지
    아키텍처·설계(Architecture and Design) / 구현(Implementation) — 데이터가 의도한 소유자의 공개키로 암호화되도록 인증서를 신중하게 관리하고 검사해야 한다. (구현 단계에도 해당)
    원문

    Certificates should be carefully managed and checked to assure that data are encrypted with the intended owner's public key.

    구현 (본문 제5장)¶

    CWE 단계(Phase) 전략 요지
    구현(Implementation) — 인증서 고정(certificate pinning)을 쓴다면, 인증서를 고정하기 전에 호스트 이름을 포함해 인증서의 관련 속성을 모두 완전히 검증한다.
    원문

    If certificate pinning is being used, ensure that all relevant properties of the certificate are fully validated before the certificate is pinned, including the hostname.

    통합 및 시험 (본문 제6장)¶

    원문 완화책 없음. 이 단계의 기준선 활동: T-06 보안 기능 부정 시험

    유지보수 (본문 제7장)¶

    원문 완화책 없음

    예시(나쁜 예·좋은 예)¶

    아래 코드는 이 가이드가 다음 상황을 가정해 새로 작성한 것이다. 정비 단말·임무 계획 도구가 정비 기록 서버·형상 서버에 TLS로 접속한다. 서버 인증서를 검증하지 않거나 신뢰 기준·서버 이름 가운데 하나를 빼고 검증하면, 같은 망에 끼어든 장비가 자기 인증서를 내밀어 서버 행세를 한다. 예시는 외부 네트워크 없이 같은 프로세스 안(메모리 BIO 쌍)이나 로컬 루프백에서 가짜 서버와 핸드셰이크하거나, TLS 계층이 부르는 인증서 검사를 직접 불러 가짜 서버를 받아들이는지 본다. Python 예시는 Bandit 규칙으로 검증을 끄는 설정을 점검한다. 언어마다 분석기·새니타이저·실행 결과로 나쁜 예는 잡히고 좋은 예는 잡히지 않음을 확인했다. 좋은 예는 그 약점 하나를 막는 최소 예이며 그대로 운용 코드가 되는 것은 아니다. 언어 상자를 눌러 펼친다.

    C

    나쁜 예

    #include <stdio.h>
#include <openssl/evp.h>
#include <openssl/ssl.h>
#include <openssl/x509.h>

/* 정비 단말 → 정비 기록 서버 TLS 접속 설정 */
static SSL *open_records_session(SSL_CTX **out_ctx)
{
    SSL_CTX *ctx = SSL_CTX_new(TLS_client_method());
    if (ctx == NULL) return NULL;
    SSL_CTX_set_verify(ctx, SSL_VERIFY_NONE, NULL);   /* 시험장에서 인증서 오류가 나서 검증을 꺼 두었다 */
    *out_ctx = ctx;
    return SSL_new(ctx);
}

/* ---- 시험 준비: 같은 프로세스 안의 가짜 서버(자체 서명 인증서)와 메모리 BIO 쌍 ---- */
static X509 *self_signed(EVP_PKEY *key, const char *cn)
{
    X509 *crt = X509_new();
    X509_NAME *name = X509_NAME_new();
    X509_NAME_add_entry_by_txt(name, "CN", MBSTRING_ASC, (const unsigned char *)cn, -1, -1, 0);
    ASN1_INTEGER_set(X509_get_serialNumber(crt), 7);
    X509_gmtime_adj(X509_getm_notBefore(crt), -60);
    X509_gmtime_adj(X509_getm_notAfter(crt), 86400);
    X509_set_subject_name(crt, name);
    X509_set_issuer_name(crt, name);
    X509_set_pubkey(crt, key);
    X509_sign(crt, key, EVP_sha256());
    X509_NAME_free(name);
    return crt;
}

static int pump_handshake(SSL *cli, SSL *srv)
{
    for (int round = 0; round < 50; round++) {
        int c = SSL_do_handshake(cli);
        int s = SSL_do_handshake(srv);
        if (c == 1 && s == 1) return 1;
        if (c <= 0 && SSL_get_error(cli, c) == SSL_ERROR_SSL) return 0;
    }
    return 0;
}

int main(void)
{
    EVP_PKEY *fake_key = EVP_EC_gen("P-256");
    X509 *fake_cert = self_signed(fake_key, "records.example.invalid");   /* 이름만 진짜 서버를 흉내 낸다 */
    SSL_CTX *srv_ctx = SSL_CTX_new(TLS_server_method());
    SSL_CTX_use_certificate(srv_ctx, fake_cert);
    SSL_CTX_use_PrivateKey(srv_ctx, fake_key);

    SSL_CTX *cli_ctx = NULL;
    SSL *cli = open_records_session(&cli_ctx);
    SSL *srv = SSL_new(srv_ctx);
    BIO *a = NULL, *b = NULL;
    if (cli == NULL || srv == NULL || BIO_new_bio_pair(&a, 0, &b, 0) != 1) return 1;
    SSL_set_bio(cli, a, a);
    SSL_set_bio(srv, b, b);
    SSL_set_connect_state(cli);
    SSL_set_accept_state(srv);

    puts(pump_handshake(cli, srv) ? "IMPOSTOR SERVER ACCEPTED" : "impostor server refused");

    SSL_free(cli); SSL_free(srv);
    SSL_CTX_free(cli_ctx); SSL_CTX_free(srv_ctx);
    X509_free(fake_cert); EVP_PKEY_free(fake_key);
    return 0;
}

    SSL_CTX_set_verify에 SSL_VERIFY_NONE을 주어 서버 인증서를 검증하지 않는다. 진짜 서버 이름만 단 자체 서명 인증서로도 핸드셰이크가 끝나 정비 기록이 가짜 서버로 넘어간다. 시험장에서 인증서 오류를 피하려고 끈 설정이 배포판에 남는 경우가 많다.

    좋은 예

    #include <stdio.h>
#include <openssl/evp.h>
#include <openssl/ssl.h>
#include <openssl/x509.h>
#include <openssl/x509v3.h>

#define RECORDS_HOST "records.example.invalid"

/* 정비 단말 → 정비 기록 서버 TLS 접속 설정: 사업 인증기관만 신뢰하고 서버 이름까지 확인한다 */
static SSL *open_records_session(SSL_CTX **out_ctx, X509 *project_ca)
{
    SSL_CTX *ctx = SSL_CTX_new(TLS_client_method());
    if (ctx == NULL) return NULL;
    *out_ctx = ctx;
    if (SSL_CTX_set_min_proto_version(ctx, TLS1_2_VERSION) != 1
        || X509_STORE_add_cert(SSL_CTX_get_cert_store(ctx), project_ca) != 1) {
        return NULL;
    }
    SSL_CTX_set_verify(ctx, SSL_VERIFY_PEER, NULL);    /* 검증에 실패하면 핸드셰이크를 끊는다 */
    SSL *ssl = SSL_new(ctx);
    if (ssl == NULL || SSL_set1_host(ssl, RECORDS_HOST) != 1) {   /* 인증서의 서버 이름 확인 */
        SSL_free(ssl);
        return NULL;
    }
    return ssl;
}

/* ---- 시험 준비: 사업 인증기관, 같은 프로세스 안의 가짜 서버(자체 서명 인증서), 메모리 BIO 쌍 ---- */
static X509 *self_signed(EVP_PKEY *key, const char *cn, int is_ca)
{
    X509 *crt = X509_new();
    X509_NAME *name = X509_NAME_new();
    X509_NAME_add_entry_by_txt(name, "CN", MBSTRING_ASC, (const unsigned char *)cn, -1, -1, 0);
    ASN1_INTEGER_set(X509_get_serialNumber(crt), is_ca ? 1 : 7);
    X509_gmtime_adj(X509_getm_notBefore(crt), -60);
    X509_gmtime_adj(X509_getm_notAfter(crt), 86400);
    X509_set_subject_name(crt, name);
    X509_set_issuer_name(crt, name);
    X509_set_pubkey(crt, key);
    if (is_ca) {
        X509_EXTENSION *bc = X509V3_EXT_conf_nid(NULL, NULL, NID_basic_constraints, "critical,CA:TRUE");
        X509_add_ext(crt, bc, -1);
        X509_EXTENSION_free(bc);
    }
    X509_sign(crt, key, EVP_sha256());
    X509_NAME_free(name);
    return crt;
}

static int pump_handshake(SSL *cli, SSL *srv)
{
    for (int round = 0; round < 50; round++) {
        int c = SSL_do_handshake(cli);
        int s = SSL_do_handshake(srv);
        if (c == 1 && s == 1) return 1;
        if (c <= 0 && SSL_get_error(cli, c) == SSL_ERROR_SSL) return 0;
    }
    return 0;
}

int main(void)
{
    EVP_PKEY *ca_key = EVP_EC_gen("P-256");
    X509 *project_ca = self_signed(ca_key, "Project Maintenance CA (example)", 1);
    EVP_PKEY *fake_key = EVP_EC_gen("P-256");
    X509 *fake_cert = self_signed(fake_key, RECORDS_HOST, 0);   /* 이름만 진짜 서버를 흉내 낸다 */
    SSL_CTX *srv_ctx = SSL_CTX_new(TLS_server_method());
    SSL_CTX_use_certificate(srv_ctx, fake_cert);
    SSL_CTX_use_PrivateKey(srv_ctx, fake_key);

    SSL_CTX *cli_ctx = NULL;
    SSL *cli = open_records_session(&cli_ctx, project_ca);
    SSL *srv = SSL_new(srv_ctx);
    BIO *a = NULL, *b = NULL;
    if (cli == NULL || srv == NULL || BIO_new_bio_pair(&a, 0, &b, 0) != 1) return 1;
    SSL_set_bio(cli, a, a);
    SSL_set_bio(srv, b, b);
    SSL_set_connect_state(cli);
    SSL_set_accept_state(srv);

    if (pump_handshake(cli, srv)) {
        puts("IMPOSTOR SERVER ACCEPTED");
    } else {
        printf("impostor server refused: %s\n", X509_verify_cert_error_string(SSL_get_verify_result(cli)));
    }

    SSL_free(cli); SSL_free(srv);
    SSL_CTX_free(cli_ctx); SSL_CTX_free(srv_ctx);
    X509_free(fake_cert); EVP_PKEY_free(fake_key);
    X509_free(project_ca); EVP_PKEY_free(ca_key);
    return 0;
}

    SSL_VERIFY_PEER로 검증을 켜고 신뢰 저장소에는 사업 인증기관 인증서만 넣는다. SSL_set1_host로 인증서의 서버 이름도 확인하고 TLS 1.2 미만은 받지 않는다. 가짜 서버의 자체 서명 인증서는 사슬 검증에서 거부된다(D-05·T-06). 시험장에서 인증서 오류가 나면 검증을 끄지 말고 시험용 인증기관을 따로 두어 해결하며, 배포 전 점검에서 SSL_VERIFY_NONE을 grep으로 찾는다.

    검증: 실행 결과 · Linux(gcc)에서 빌드 — 나쁜 예에서 IMPOSTOR SERVER ACCEPTED 검출, 좋은 예에서 미검출·impostor server refused 출력 확인 · 참고: MITRE CWE-295 Demonstrative Example 5(인증서 검증 단계를 생략) 참고, 이 가이드가 새로 작성

    X509_gmtime_adj(X509_getm_notBefore(crt.get()), -60);
    X509_gmtime_adj(X509_getm_notAfter(crt.get()), 86400);

    }

    return crt;

static bool pump_handshake(SSL *cli, SSL *srv) {

        const int s = SSL_do_handshake(srv);
        if (c == 1 && s == 1) return true;
        if (c <= 0 && SSL_get_error(cli, c) == SSL_ERROR_SSL) return false;
    }
    return false;
}

    {

        RevocationMode = X509RevocationMode.Online,       // 폐기 정보를 얻지 못하면 정상 서버도 거부한다(폐쇄망은 내부 CRL 배포 지점 운영)

    var options = new SslClientAuthenticationOptions
    {
        TargetHost = "records.example.invalid",          // 인증서의 서버 이름과 맞춰 본다

    };
    try
    {
        await tls.AuthenticateAsClientAsync(options);
        return true;
    }
    catch (AuthenticationException)
    {
        return false;                                     // 검증 실패 시 연결하지 않는다
    }
