    Divide By Zero

    항목 내용
    추상화 수준 기본(Base)
    상태 초안(Draft)
    소속 「보안약점 점검 목록」(44개)
    가이드 적용성 해당
    적용 플랫폼 언어 무관
    원문 MITRE CWE-369 (CWE 5.0)

    한 줄 요약

    제품이 어떤 값을 0으로 나누어 생기는 약점이다.

    → 나쁜 예·좋은 예

    설명(Description)¶

    제품이 어떤 값을 0으로 나누는 약점이다.

    원문(Description)

    The product divides a value by zero.

    발생 단계(Modes Of Introduction)¶

    CWE 단계(Phase) 수명주기 단계(가이드 대응) 설명
    구현(Implementation) 구현 이 약점은 대개 제품에 예상치 못한 값이 들어오거나 오류가 제대로 감지되지 않을 때 생긴다. 크기·길이·너비·높이 같은 물리적 치수를 다루는 계산에서 자주 발생한다.

    영향(Common Consequences)¶

    영역 영향 설명
    가용성 서비스 거부: 비정상 종료·재시작 0으로 나누기는 프로그램 비정상 종료(crash)를 일으킨다.

    완화책(Potential Mitigations)¶

    원문에 이 항목의 완화책이 없다. 상위 계통에서 가장 가까운 항목 CWE-682(기둥(Pillar), 이 가이드 범위 밖 — MITRE 원문)의 완화책 6건을 참고한다(2.7 규칙 1, 내용은 그 항목 쪽에 있다). 기둥(Pillar) 항목의 내용은 일반 원칙 수준이다. 아래 '이 가이드에서 다루는 곳'의 지침을 함께 본다.

    요구사항 분석 (본문 제3장)¶

    원문 완화책 없음

    설계 (본문 제4장)¶

    원문 완화책 없음

    구현 (본문 제5장)¶

    원문 완화책 없음. 이 단계의 기준선 활동: I-05 정수·포인터·메모리 안전 코딩

    통합 및 시험 (본문 제6장)¶

    원문 완화책 없음. 이 단계의 기준선 활동: T-04 퍼징, T-05 경계값·오류 주입 시험

    유지보수 (본문 제7장)¶

    원문 완화책 없음

    예시(나쁜 예·좋은 예)¶

    아래 코드는 이 가이드가 다음 상황을 가정해 새로 작성한 것이다. 수신 통계·센서 보정·정비 기록·연료 계산처럼 평균이나 비율을 구할 때, 나누는 수(받은 프레임 수, 보정 분모, 고장 횟수, 분당 소모량)가 링크 두절·보정 파일 누락·고장 기록 없음·엔진 정지 같은 정상 운용 상황에서 0이 될 수 있다. 언어마다 분석기·새니타이저·실행 결과로 나쁜 예는 잡히고 좋은 예는 잡히지 않음을 확인했다. 좋은 예는 그 약점 하나를 막는 최소 예이며 그대로 운용 코드가 되는 것은 아니다. 언어 상자를 눌러 펼친다.

    C

    나쁜 예

    #include <stdio.h>

/* 데이터링크 수신 통계: 주기마다 받은 프레임 수와 지연 합계 */
typedef struct { int frames; int latency_sum_ms; } LinkWindow;

static int mean_latency_ms(const LinkWindow *w)
{
    return w->latency_sum_ms / w->frames;   /* 프레임 0개면 0으로 나눔 */
}

int main(void)
{
    const LinkWindow history[] = {{4, 120}, {0, 0}, {5, 95}};  /* 둘째 주기: 링크 두절 */
    for (int k = 0; k < 3; ++k) {
        printf("window %d: mean latency %d ms\n", k, mean_latency_ms(&history[k]));
    }
    return 0;
}

    링크가 끊긴 주기에는 프레임 수가 0인데 검사 없이 나눈다. C에서 정수를 0으로 나누는 것은 정의되지 않은 동작이라 프로세서·설정에 따라 예외(UsageFault·HardFault)로 멈추거나 0 같은 엉뚱한 값을 낸다.

    좋은 예

    #include <limits.h>
#include <stdbool.h>
#include <stdio.h>

/* 데이터링크 수신 통계: 주기마다 받은 프레임 수와 지연 합계 */
typedef struct { int frames; int latency_sum_ms; } LinkWindow;

/* 나눌 수 없으면 false를 돌려주고 호출자가 '링크 두절'로 처리한다 */
static bool mean_latency_ms(const LinkWindow *w, int *out)
{
    if (w->frames == 0 || (w->latency_sum_ms == INT_MIN && w->frames == -1)) {
        return false;
    }
    *out = w->latency_sum_ms / w->frames;
    return true;
}

int main(void)
{
    const LinkWindow history[] = {{4, 120}, {0, 0}, {5, 95}};
    for (int k = 0; k < 3; ++k) {
        int mean = 0;
        if (mean_latency_ms(&history[k], &mean)) {
            printf("window %d: mean latency %d ms\n", k, mean);
        } else {
            printf("window %d: no frames, link lost\n", k);
        }
    }
    return 0;
}

    나누기 전에 분모가 0인지, INT_MIN을 -1로 나누는 오버플로 조합인지 검사하고, 나눌 수 없으면 실패를 돌려 호출자가 '링크 두절'로 처리하게 한다.

    검증: UndefinedBehaviorSanitizer(clang) — 나쁜 예에서 division by zero 검출, 좋은 예에서 미검출 · 참고: MITRE CWE-369 Demonstrative Example 2(분모 검사 없는 나눗셈) 참고, 이 가이드가 새로 작성

    C++

    나쁜 예

    #include <cstdio>
#include <vector>

// 압력 센서 채널별 보정 계수: 원시값 / 환산 분모
struct Calibration { int channel; int divisor; };

int to_kpa(int raw, const Calibration &cal) {
    return raw / cal.divisor;                  // 분모 검사 없음
}

int main() {
    std::vector<Calibration> table{{0, 8}, {1, 0}};   // 채널 1: 보정 파일 누락으로 0
    std::vector<int> raw{1600, 2400};
    for (std::size_t ch = 0; ch < table.size(); ++ch) {
        std::printf("ch%d pressure %d kPa\n", table[ch].channel, to_kpa(raw[ch], table[ch]));
    }
    return 0;
}

    보정 파일이 빠져 분모가 0으로 남은 채널을 검사 없이 환산한다. 정의되지 않은 동작이라 정상 채널 처리까지 함께 멈출 수 있다.

    좋은 예

    #include <climits>
#include <cstdio>
#include <optional>
#include <vector>

// 압력 센서 채널별 보정 계수: 원시값 / 환산 분모
struct Calibration { int channel; int divisor; };

std::optional<int> to_kpa(int raw, const Calibration &cal) {
    if (cal.divisor == 0 || (raw == INT_MIN && cal.divisor == -1)) {
        return std::nullopt;                   // 환산 불가를 형으로 알린다
    }
    return raw / cal.divisor;
}

int main() {
    std::vector<Calibration> table{{0, 8}, {1, 0}};
    std::vector<int> raw{1600, 2400};
    for (std::size_t ch = 0; ch < table.size(); ++ch) {
        if (auto kpa = to_kpa(raw[ch], table[ch])) {
            std::printf("ch%d pressure %d kPa\n", table[ch].channel, *kpa);
        } else {
            std::printf("ch%d calibration invalid: sensor marked failed\n", table[ch].channel);
        }
    }
    return 0;
}

    분모 0과 INT_MIN/-1을 먼저 거르고, 환산할 수 없다는 사실을 std::optional로 돌려 호출자가 해당 센서를 고장 처리하게 한다.

    검증: UndefinedBehaviorSanitizer(clang) — 나쁜 예에서 division by zero 검출, 좋은 예에서 미검출 · 참고: MITRE CWE-369 Demonstrative Example 2(분모 검사 없는 나눗셈) 참고, 이 가이드가 새로 작성

    C#

    나쁜 예

    // 보유 기체별 연료 잔량(kg)과 분당 소모량(kg/min)으로 남은 비행 시간을 계산한다
const int ReserveKg = 60;                       // 착륙 예비 연료
(string Tail, int FuelKg, int BurnKgPerMin)[] fleet =
[
    ("UAV-1", 540, 6),
    ("UAV-2", 320, 0),                          // 지상 대기: 엔진 정지로 소모량 0
    ("UAV-3", 410, 5),
];

int shortest = int.MaxValue;
foreach (var (tail, fuel, burn) in fleet)
{
    int usable = Math.Max(0, fuel - ReserveKg);
    int minutes = usable / burn;                // 분모 검사 없음
    shortest = Math.Min(shortest, minutes);
    Console.WriteLine($"{tail}: endurance {minutes} min");
}
Console.WriteLine($"shortest endurance {shortest} min");

    엔진이 정지한 기체는 소모량이 0이라 정수 나눗셈에서 DivideByZeroException이 나고, 루프가 중단되어 뒤에 남은 기체와 전체 최소 체공 시간도 계산되지 않는다.

    좋은 예

    // 보유 기체별 연료 잔량(kg)과 분당 소모량(kg/min)으로 남은 비행 시간을 계산한다
const int ReserveKg = 60;                       // 착륙 예비 연료
(string Tail, int FuelKg, int BurnKgPerMin)[] fleet =
[
    ("UAV-1", 540, 6),
    ("UAV-2", 320, 0),
    ("UAV-3", 410, 5),
];

int shortest = int.MaxValue;
foreach (var (tail, fuel, burn) in fleet)
{
    if (burn <= 0)
    {
        // 나누지 않고 상태를 따로 보고하며, 전체 최소값 계산에서도 뺀다
        Console.WriteLine($"{tail}: endurance not computed (engine idle)");
        continue;
    }
    int usable = Math.Max(0, fuel - ReserveKg);
    int minutes = usable / burn;
    shortest = Math.Min(shortest, minutes);
    Console.WriteLine($"{tail}: endurance {minutes} min");
}
Console.WriteLine(shortest == int.MaxValue ? "shortest endurance n/a" : $"shortest endurance {shortest} min");

    예외를 잡아 넘기는 대신 나누기 전에 분모를 검사해, 0 이하이면 계산을 건너뛰고 상태를 따로 보고하며 전체 최소 체공 시간 계산에서도 뺀다.

    검증: 실행 결과 — 나쁜 예에서 DivideByZeroException 검출, 좋은 예에서 미검출·endurance not computed (engine idle) 출력 확인 · 참고: MITRE CWE-369 Demonstrative Example 3(C# 정수 나눗셈) 참고, 이 가이드가 새로 작성

    Java

    나쁜 예

    import java.util.List;

public class Example {
    // 정비 기록: 장비별 누적 운용 시간과 고장 횟수
    record UnitLog(String unit, int operatingHours, int failures) {}

    static int mtbfHours(UnitLog log) {
        return log.operatingHours() / log.failures();   // 고장 0회면 0으로 나눔
    }

    public static void main(String[] args) {
        List<UnitLog> logs = List.of(
                new UnitLog("IMU-A", 1200, 3),
                new UnitLog("RADIO-RX", 800, 0));
        for (UnitLog log : logs) {
            System.out.println(log.unit() + " MTBF " + mtbfHours(log) + " h");
        }
    }
}

    고장 기록이 없는 장비는 고장 횟수가 0이라 정수 나눗셈에서 ArithmeticException이 나고, 처리하지 않으면 정비 보고서 생성이 중간에 멈춘다.

    좋은 예

    import java.util.List;
import java.util.OptionalInt;

public class Example {
    // 정비 기록: 장비별 누적 운용 시간과 고장 횟수
    record UnitLog(String unit, int operatingHours, int failures) {}

    static OptionalInt mtbfHours(UnitLog log) {
        if (log.failures() <= 0) {
            return OptionalInt.empty();                  // 고장 기록 없음: 계산하지 않는다
        }
        return OptionalInt.of(log.operatingHours() / log.failures());
    }

    public static void main(String[] args) {
        List<UnitLog> logs = List.of(
                new UnitLog("IMU-A", 1200, 3),
                new UnitLog("RADIO-RX", 800, 0));
        for (UnitLog log : logs) {
            OptionalInt m = mtbfHours(log);
            System.out.println(log.unit() + (m.isPresent()
                    ? " MTBF " + m.getAsInt() + " h"
                    : " MTBF n/a (no failures recorded)"));
        }
    }
}

    분모가 0 이하이면 계산하지 않고 OptionalInt.empty()를 돌려 '해당 없음'으로 보고하게 한다. 부동소수 나눗셈이라면 예외 대신 NaN·Infinity가 나오므로 결과를 따로 검사한다.

    검증: 실행 결과 — 나쁜 예에서 ArithmeticException 검출, 좋은 예에서 미검출·MTBF n/a (no failures recorded) 출력 확인 · 참고: MITRE CWE-369 Demonstrative Example 1(평균 계산의 분모 검사 누락) 참고, 이 가이드가 새로 작성

    Python

    나쁜 예

    # 데이터링크 수신 통계: 주기마다 평균 프레임 길이를 계산해 화면에 올린다
def mean_frame_length(total_bytes, frames_received):
    return total_bytes / frames_received          # 수신 프레임이 0이면 ZeroDivisionError


cycles = [(12800, 100), (6400, 50), (0, 0)]        # 세 번째 주기: 링크 두절로 수신 0
for total, frames in cycles:
    print(f"mean frame length: {mean_frame_length(total, frames):.1f} B")
print("telemetry loop still running")

    링크가 끊겨 수신 프레임이 0인 주기에 0으로 나눈다. Python은 정의되지 않은 동작 대신 ZeroDivisionError를 던지지만, 잡지 않으면 원격측정 처리 반복문 전체가 비정상 종료한다(서비스 거부). numpy 배열 나눗셈은 예외 없이 inf·nan을 내고 계산을 이어 가므로 결과가 잘못된 채 화면에 오를 수 있다.

    좋은 예

    def mean_frame_length(total_bytes, frames_received):
    if frames_received <= 0:                      # 분모를 먼저 확인하고 '값 없음'을 따로 돌려준다
        return None
    return total_bytes / frames_received


cycles = [(12800, 100), (6400, 50), (0, 0)]
for total, frames in cycles:
    mean = mean_frame_length(total, frames)
    print("mean frame length: no frames (link lost)" if mean is None else f"mean frame length: {mean:.1f} B")
print("telemetry loop still running")

    나누기 전에 분모가 0 이하인지 확인하고, 그때는 0이나 직전 값이 아니라 '값 없음'(None)을 돌려 화면에 링크 두절로 표시한다(I-06). 분모가 0이 되는 상황(링크 두절·센서 고장)은 경계값 시험에 넣는다(T-05).

    검증: 실행 결과 — 나쁜 예에서 ZeroDivisionError 검출, 좋은 예에서 미검출·no frames (link lost)…telemetry loop still running 출력 확인 · 참고: MITRE CWE-369 Demonstrative Example 1(평균 계산의 분모 검사 누락) 참고, 이 가이드가 새로 작성

    Example 1. The following Java example contains a function to compute an average but does not validate that the input value used as the denominator is not zero. This will create an exception for attempting to divide by zero. If this error is not handled by Java exception handling, unexpected results can occur.

    Bad / Java

    public int computeAverageResponseTime (int totalTime, int numRequests) {
  return totalTime / numRequests;
}

    By validating the input value used as the denominator the following code will ensure that a divide by zero error will not cause unexpected results. The following Java code example will validate the input value, output an error message, and throw an exception.

    Good / Java

    public int computeAverageResponseTime (int totalTime, int numRequests) throws ArithmeticException {
  if (numRequests == 0) {
    System.out.println("Division by zero attempted!");
    throw ArithmeticException;
  }
  return totalTime / numRequests;
}

    탐지 방법(Detection Methods)¶

    방법 요지 효과성
    자동 정적 분석 흔히 SAST(Static Application Security Testing)라 부르는 자동 정적 분석(static analysis)은 소스코드(또는 바이너리·컴파일된 코드)를 실행하지 않고 분석해 이 약점의 일부 사례를 찾을 수 있으며, 대개 데이터 흐름·제어 흐름 모델을 만든 뒤 입력 출처('source')와 외부 구성요소나 운영체제 같은 하위 계층과 상호작용하는 목적지('sink')를 잇는 잠재적 취약 패턴을 찾는다.
    원문

    Automated static analysis, commonly referred to as Static Application Security Testing (SAST), can find some instances of this weakness by analyzing source code (or binary/compiled code) without having to execute it. Typically, this is done by building a model of data flow and control flow, then searching for potentially-vulnerable patterns that connect "sources" (origins of input) with "sinks" (destinations where the data interacts with external components, a lower layer such as the OS, etc.)

    		 높음(High)
    퍼징(Fuzzing) 퍼징(fuzzing)은 무작위 또는 알고리즘으로 다양한 입력을 대량 생성해 코드를 동적으로 호출하는 강력한 기법으로, 무작위 입력으로도 흔히 비정상 종료·메모리 손상·자원 소모 같은 예상치 못한 결과를 일으키며, 버그를 분명히 보여 주는 재현 가능한 시험 케이스를 만들어 진단을 돕는다.
    원문

    Fuzz testing (fuzzing) is a powerful technique for generating large numbers of diverse inputs - either randomly or algorithmically - and dynamically invoking the code with those inputs. Even with random inputs, it is often capable of generating unexpected results such as crashes, memory corruption, or resource consumption. Fuzzing effectively produces repeatable test cases that clearly indicate bugs, which helps developers to diagnose the issues.

    		 높음(High)

    점검 착안점 활동 근거
    나눗셈·나머지 연산의 분모를 거꾸로 따라가 외부 입력, 보정 파일, 계수(프레임 수, 고장 횟수, 소모량)에서 오는 분모를 찾고, 그 앞에 0 검사가 있는지 확인한다. I-09·I-05 [예시] CWE-369 예시(링크 단절·보정 파일 누락으로 분모 0) · [표준] SEI CERT INT33-C·NUM02-J
    분모가 0이 되는 상황(링크 두절, 보정 파일 누락, 고장 기록 없음)을 시험 사례로 만들어, 호스트 빌드는 UBSan의 'division by zero' 보고를, Java·C#은 예외 발생과 그 뒤 처리 중단 여부를 확인한다. T-05·I-10 [예시] CWE-369 예시 검증(UBSan 보고, ArithmeticException·DivideByZeroException)
    (C·C++) Cortex-M3·M4·M7 같은 ARMv7-M 계열은 SCB->CCR의 DIV_0_TRP 비트가 0(리셋값)이면 SDIV·UDIV가 0으로 나눈 결과를 예외 없이 0으로 내므로, 이 비트 설정과 UsageFault 처리기를 확인한다. 하드웨어 나눗셈이 없는 코어와 DSP는 컴파일러 런타임이 0으로 나눌 때 부르는 처리 함수(ARM EABI는 __aeabi_idiv0)가 어떻게 동작하는지 보고, 같은 시험을 타깃에서 수행해 고장 처리와 결과값을 본다. T-02 [보완]
    부동소수점 나눗셈 결과가 무한대·NaN이 되어 뒤 계산으로 퍼지는지 확인한다. I-09·T-05 [표준] SEI CERT FLP03-C
