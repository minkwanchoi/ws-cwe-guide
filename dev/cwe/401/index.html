    Missing Release of Memory after Effective Lifetime

    항목 내용
    추상화 수준 변형(Variant)
    상태 초안(Draft)
    소속 언어 뷰 C·C++(CWE-658·659)
    가이드 적용성 해당
    적용 플랫폼 언어: 언어 무관, C, C++
    원문 MITRE CWE-401 (CWE 5.0)

    한 줄 요약

    할당한 메모리를 사용한 뒤 충분히 추적·해제하지 않아 그 메모리를 다시 할당·재사용할 수 없게 되는 약점이다.

    설명(Description)¶

    제품이 할당한 메모리를 사용한 뒤 충분히 추적하고 해제하지 않아, 그 메모리를 재할당하고 재사용할 수 없게 되는 약점이다.

    원문(Description · Dimensions)

    The product does not sufficiently track and release allocated memory after it has been used, making the memory unavailable for reallocation and reuse.

    Dimensions: Behavior-Type = Release; Behavior-Property = Missing; Resource-Type = Memory; Resource-Property = after Effective Lifetime

    발생 단계(Modes Of Introduction)¶

    CWE 단계(Phase) 수명주기 단계(가이드 대응) 설명
    구현(Implementation) 구현 메모리 누수에는 흔하고 때로 겹치는 두 원인이 있다. 첫째는 잘못된 형식의 데이터나 예기치 않게 중단된 세션을 부적절하게 처리할 때 흔히 발생하는 오류 상황과 기타 예외 상황이다. 둘째는 프로그램의 어느 부분이 메모리를 해제해야 하는지에 대한 혼동이다. 일부 언어에서는 개발자가 메모리 할당을 추적하고 해제할 책임을 지는데, 메모리를 가리키는 포인터나 참조가 더 이상 없으면 해제 대상으로 추적·식별할 수 없다.

    영향(Common Consequences)¶

    영역 영향 설명
    가용성 서비스 거부: 비정상 종료·재시작 / 서비스 거부: 불안정 / 서비스 거부: 자원 소모(CPU) / 서비스 거부: 자원 소모(메모리) 대부분의 메모리 누수는 일반적인 제품 신뢰성 문제로 이어지지만, 공격자가 의도적으로 메모리 누수를 일으킬 수 있으면 (프로그램을 비정상 종료시키거나 멈추게 해) 서비스 거부 공격을 하거나 메모리 부족 상태에서 생기는 다른 예기치 않은 프로그램 동작을 악용할 수 있다.

    요구사항 분석 (본문 제3장)¶

    원문 완화책 없음

    설계 (본문 제4장)¶

    CWE 단계(Phase) 전략 요지 효과성
    아키텍처·설계(Architecture and Design) — 추상화 라이브러리를 써서 위험한 API를 감춘다. 이것은 완전한 해결책이 아니다.
    원문

    Use an abstraction library to abstract away risky APIs. Not a complete solution.

    		 —
    아키텍처·설계(Architecture and Design) / 빌드·컴파일(Build and Compilation) — 메모리 누수를 피하는 데 도움이 될 수 있는 Boehm-Demers-Weiser 가비지 컬렉터(bdwgc) 사용을 고려한다. (구현 단계에도 해당)
    원문

    Consider using the Boehm-Demers-Weiser garbage collector (bdwgc), which can help avoid leaks.

    		 보통(Moderate) — 100% 효과적이지는 않으므로 완전한 해결책은 아니다.

    구현 (본문 제5장)¶

    CWE 단계(Phase) 전략 요지 효과성
    구현(Implementation) 라이브러리·프레임워크 활용 자동 메모리 관리를 제공하거나 수동 메모리 관리를 오류가 덜 나게 하는 언어나 도구를 고른다. 예: Linux의 glibc는 유효하지 않은 포인터 해제에 대한 보호 기능을 제공하고, Xcode로 OS X·iOS를 대상으로 할 때는 자동 참조 카운팅(ARC)을 켠다 [REF-391]. C++에서 메모리를 올바르고 일관되게 관리하려면 std::auto_ptr(ISO/IEC 14882:2003 정의), std::shared_ptr·std::unique_ptr(C++ 표준의 차기 개정판, 비공식 명칭 C++ 1x에 규정) 같은 스마트 포인터 클래스나 Boost 같은 동등한 해결책 사용을 고려한다. (원문 표현 그대로다. shared_ptr·unique_ptr는 C++11에 들어갔고 auto_ptr는 C++11에서 폐기 예고, C++17에서 삭제됐다.)
    원문

    Choose a language or tool that provides automatic memory management, or makes manual memory management less error-prone.

    For example, glibc in Linux provides protection against free of invalid pointers.

    When using Xcode to target OS X or iOS, enable automatic reference counting (ARC) [REF-391].

    To help correctly and consistently manage memory when programming in C++, consider using a smart pointer class such as std::auto_ptr (defined by ISO/IEC ISO/IEC 14882:2003), std::shared_ptr and std::unique_ptr (specified by an upcoming revision of the C++ standard, informally referred to as C++ 1x), or equivalent solutions such as Boost.

    		 —

    탐지 방법(Detection Methods)¶

    방법 요지 효과성
    퍼징(Fuzzing) 퍼징(fuzzing)은 무작위 또는 알고리즘으로 다양한 입력을 대량 생성해 코드를 동적으로 호출하는 강력한 기법으로, 무작위 입력으로도 흔히 비정상 종료·메모리 손상·자원 소모 같은 예상치 못한 결과를 일으키며, 버그를 분명히 보여 주는 재현 가능한 시험 케이스를 만들어 진단을 돕는다.
    원문

    Fuzz testing (fuzzing) is a powerful technique for generating large numbers of diverse inputs - either randomly or algorithmically - and dynamically invoking the code with those inputs. Even with random inputs, it is often capable of generating unexpected results such as crashes, memory corruption, or resource consumption. Fuzzing effectively produces repeatable test cases that clearly indicate bugs, which helps developers to diagnose the issues.

    		 높음(High)
    자동 동적 분석 컴파일 과정에 통합되어 메모리 안전 오류와 관련된 런타임 오류 검사 장치를 삽입하는 도구, 예를 들어 C/C++용 AddressSanitizer(ASan) [REF-1518]나 valgrind [REF-480]를 사용한다.
    원문

    Use tools that are integrated during compilation to insert runtime error-checking mechanisms related to memory safety errors, such as AddressSanitizer (ASan) for C/C++ [REF-1518] or valgrind [REF-480].

    		 보통(Moderate) — 오류가 있는 코드에 도달하려면 퍼징 도구가 생성하는 것과 같은 조작된 입력이 필요하고, 이런 도구는 성능을 떨어뜨릴 수 있으며 오류 상태만 보고할 뿐 오류를 낳은 원래 실수는 알려 주지 않는다.
    자동 정적 분석 흔히 SAST(Static Application Security Testing)라 부르는 자동 정적 분석(static analysis)은 소스코드(또는 바이너리·컴파일된 코드)를 실행하지 않고 분석해 이 약점의 일부 사례를 찾을 수 있으며, 대개 데이터 흐름·제어 흐름 모델을 만든 뒤 입력 출처('source')와 외부 구성요소나 운영체제 같은 하위 계층과 상호작용하는 목적지('sink')를 잇는 잠재적 취약 패턴을 찾는다.
    원문

    Automated static analysis, commonly referred to as Static Application Security Testing (SAST), can find some instances of this weakness by analyzing source code (or binary/compiled code) without having to execute it. Typically, this is done by building a model of data flow and control flow, then searching for potentially-vulnerable patterns that connect "sources" (origins of input) with "sinks" (destinations where the data interacts with external components, a lower layer such as the OS, etc.)

    		 높음(High)

    탐지 방법별 시험 활동은 제6장에 있다.

    도구 미지원 시 대안. 공통안은 6.2에 있고, 이 절에는 이 항목의 고유안만 적는다.

    • ① 원문 탐지 방법(원문 효과성별): 높음: 퍼징(Fuzzing) / 보통: 자동 동적 분석. 각 방법의 시험 활동은 6.2의 대응표를 따른다.
    • ③ SEI CERT 대응 규칙: MEM31-C, MSC04-J

    요구사항 분석 —
    설계 메모리 소유권·해제 책임 규칙을 설계 단계에서 정하고, 가능하면 정적 할당·메모리 풀·RAII(스마트 포인터) 구조를 사용한다.

    통합 및 시험 Valgrind(memcheck), AddressSanitizer(LeakSanitizer), 정적 분석 도구(예: Coverity, cppcheck) 분석과 장시간 부하 시험으로 누수를 탐지한다.
    유지보수 장기 운용 시 힙 사용량을 모니터링하여 증가 추세를 분석하고 누수 결함 패치 후 회귀시험으로 확인한다.
    임베디드 고려 MCU는 힙이 작고 재부팅이 어려우므로 동적 할당 금지(MISRA C:2012 Rule 21.3)를 원칙으로 하고, 초기화 때만 할당하는 방식을 쓰면 편차로 기록하며, 불가피하면 풀 할당자와 힙 잔량 감시, 워치독 연동을 적용한다.

    관찰 사례(원문 Observed Examples 6건, 요지는 한글 요약이고 원문은 접은 상자)

    참조 요지
    CVE-2005-3119 함수가 데이터 구조의 한 요소를 free()하지 않아 메모리 누수가 일어난다.
    원문

    Memory leak because function does not free() an element of a data structure.

    원문

    Memory leak when counter variable is not decremented.
    CVE-2002-0574 연쇄: 참조 카운트를 감소시키지 않아 ICMP 패킷을 보내면 OS에서 메모리 누수가 일어난다.
    원문

    Chain: reference count is not decremented, leading to memory leak in OS by sending ICMP packets.
    CVE-2005-3181 커널이 데이터 구조를 해제할 때 잘못된 함수를 사용해 다른 코드가 데이터를 제대로 추적하지 못한다.
    원문

    Kernel uses wrong function to release a data structure, preventing data from being properly tracked by other code.
    CVE-2004-0222 프로토콜 시험 도구 모음(test suite)에 들어 있는, 내용이 밝혀지지 않은 조작으로 메모리 누수가 일어난다.
