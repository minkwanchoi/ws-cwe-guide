    Improper Check for Certificate Revocation

    항목 내용
    추상화 수준 기본(Base)
    상태 초안(Draft)
    소속 보조 항목(「보안약점 점검 목록」·언어 뷰 밖, 매뉴얼 7-10쪽 '추가 식별' 근거)
    가이드 적용성 조건부 — TLS·인증서 사용
    적용 플랫폼 언어 무관 · 기술: 기술 무관, 웹 기반(Web Based)
    원문 MITRE CWE-299 (CWE 5.0)

    한 줄 요약

    인증서의 폐기 상태를 확인하지 않거나 잘못 확인하는 약점이다.

    → 나쁜 예·좋은 예

    설명(Description)¶

    제품이 인증서의 폐기(revocation) 상태를 확인하지 않거나 잘못 확인하는 약점이다.

    원문(Description)

    The product does not check or incorrectly checks the revocation status of a certificate.

    발생 단계(Modes Of Introduction)¶

    CWE 단계(Phase) 수명주기 단계(가이드 대응) 설명
    구현(Implementation) 구현 제품이 인증서 고정(certificate pinning)을 쓸 때, 개발자가 인증서를 고정하기 전에 인증서의 관련 구성요소를 모두 제대로 검증하지 않을 수 있다. 이 때문에 고정을 마친 뒤에는 시험하기가 어렵거나 비용이 많이 들 수 있다.
    구현(Implementation) 구현 실현(REALIZATION): 이 약점은 아키텍처 보안 전술을 구현하는 과정에서 생긴다.

    영향(Common Consequences)¶

    영역 영향 설명
    접근 통제 권한 획득 또는 신원 도용 어떤 경로로든 인증서를 손에 넣은 신뢰할 수 없는 개체, 곧 자신이 주장하는 주체가 아닌 개체에 신뢰가 부여될 수 있다.
    무결성 / 기타 기타 신뢰할 수 없는(그리고 악의적일 수 있는) 출처의 데이터가 통합될 수 있다.
    기밀성 애플리케이션 데이터 읽기 인증서에 접근하게 된 신뢰할 수 없는 개체가 신뢰된 개체로 위장하면, 그 개체에 데이터가 공개되어 정보가 노출될 수 있다.

    완화책(Potential Mitigations)¶

    원문 완화책 2건(수명주기 단계로 묶은 규칙은 색인에 있다).

    요구사항 분석 (본문 제3장)¶

    원문 완화책 없음

    설계 (본문 제4장)¶

    CWE 단계(Phase) 전략 요지
    아키텍처·설계(Architecture and Design) — 인증서의 폐기 상태를 확인한다.
    원문

    Ensure that certificates are checked for revoked status.

    구현 (본문 제5장)¶

    CWE 단계(Phase) 전략 요지
    구현(Implementation) — 인증서 고정(certificate pinning)을 쓴다면, 인증서를 고정하기 전에 폐기 상태를 포함해 인증서의 관련 속성을 모두 완전히 검증한다.
    원문

    If certificate pinning is being used, ensure that all relevant properties of the certificate are fully validated before the certificate is pinned, including the revoked status.

    통합 및 시험 (본문 제6장)¶

    원문 완화책 없음. 이 단계의 기준선 활동: T-06 보안 기능 부정 시험

    유지보수 (본문 제7장)¶

    원문 완화책 없음

    예시(나쁜 예·좋은 예)¶

    아래 코드는 이 가이드가 다음 상황을 가정해 새로 작성한 것이다. 지상 키 관리 소프트웨어가 키 적재 장비의 장비 인증서를, 임무 계획 도구가 계획 파일에 서명한 운용자 인증서를, 정비 단말이 형상 서버 인증서를 확인한다. 장비 분실·키 유출·운용자 전출로 인증기관이 폐기한 인증서도 서명과 유효 기간은 그대로 맞으므로, 폐기 여부를 보지 않으면 계속 신뢰된다. 폐쇄망에서는 폐기 정보를 받을 경로가 없다는 이유로 확인을 빼기 쉽다. 예시는 인증기관이 폐기한 인증서를 받아들이는지 본다. C# 예시는 .NET 분석기 규칙으로 HttpClient의 폐기 확인 설정을 점검한다. 언어마다 분석기·새니타이저·실행 결과로 나쁜 예는 잡히고 좋은 예는 잡히지 않음을 확인했다. 좋은 예는 그 약점 하나를 막는 최소 예이며 그대로 운용 코드가 되는 것은 아니다. 언어 상자를 눌러 펼친다.

    C

    나쁜 예

    #include <stdio.h>
#include <openssl/evp.h>
#include <openssl/x509.h>
#include <openssl/x509v3.h>

/* 지상 키 관리 소프트웨어가 접속한 키 적재 장비의 장비 인증서를 확인한다 */
static int keyloader_trusted(X509 *device_cert, X509 *project_ca)
{
    X509_STORE *store = X509_STORE_new();
    X509_STORE_CTX *vctx = X509_STORE_CTX_new();
    int ok = 0;
    if (store != NULL && vctx != NULL && X509_STORE_add_cert(store, project_ca) == 1
        && X509_STORE_CTX_init(vctx, store, device_cert, NULL) == 1) {
        ok = X509_verify_cert(vctx) == 1;     /* 서명 사슬과 유효 기간만 본다. 폐쇄망이라 폐기 목록은 쓰지 않는다 */
    }
    X509_STORE_CTX_free(vctx);
    X509_STORE_free(store);
    return ok;
}

/* ---- 시험 준비: 사업 인증기관, 그 기관이 발급한 키 적재 장비 인증서, 그 인증서를 폐기한 CRL ---- */
static X509 *issue(const char *cn, EVP_PKEY *subject, X509 *issuer, EVP_PKEY *signer, long serial)
{
    X509 *crt = X509_new();
    X509_NAME *name = X509_get_subject_name(crt);
    X509_NAME_add_entry_by_txt(name, "CN", MBSTRING_ASC, (const unsigned char *)cn, -1, -1, 0);
    ASN1_INTEGER_set(X509_get_serialNumber(crt), serial);
    X509_gmtime_adj(X509_getm_notBefore(crt), -60);
    X509_gmtime_adj(X509_getm_notAfter(crt), 30L * 86400);
    X509_set_issuer_name(crt, issuer != NULL ? X509_get_subject_name(issuer) : name);
    X509_set_pubkey(crt, subject);
    X509_EXTENSION *bc = X509V3_EXT_conf_nid(NULL, NULL, NID_basic_constraints,
                                             issuer == NULL ? "critical,CA:TRUE" : "critical,CA:FALSE");
    X509_add_ext(crt, bc, -1);
    X509_EXTENSION_free(bc);
    X509_sign(crt, signer, EVP_sha256());
    return crt;
}

static X509_CRL *revoke(X509 *ca, EVP_PKEY *ca_key, X509 *victim)
{
    X509_CRL *crl = X509_CRL_new();
    ASN1_TIME *now = X509_gmtime_adj(NULL, 0), *next = X509_gmtime_adj(NULL, 7L * 86400);
    X509_REVOKED *entry = X509_REVOKED_new();
    X509_CRL_set_version(crl, X509_CRL_VERSION_2);
    X509_CRL_set_issuer_name(crl, X509_get_subject_name(ca));
    X509_CRL_set1_lastUpdate(crl, now);
    X509_CRL_set1_nextUpdate(crl, next);
    X509_REVOKED_set_serialNumber(entry, X509_get_serialNumber(victim));
    X509_REVOKED_set_revocationDate(entry, now);
    X509_CRL_add0_revoked(crl, entry);
    X509_CRL_sort(crl);
    X509_CRL_sign(crl, ca_key, EVP_sha256());
    ASN1_TIME_free(now);
    ASN1_TIME_free(next);
    return crl;
}

int main(void)
{
    EVP_PKEY *ca_key = EVP_EC_gen("P-256"), *kl_key = EVP_EC_gen("P-256");
    X509 *ca = issue("Project Key Management CA (example)", ca_key, NULL, ca_key, 1);
    X509 *keyloader = issue("keyloader-07.example.invalid", kl_key, ca, ca_key, 0x1007);
    X509_CRL *crl = revoke(ca, ca_key, keyloader);   /* 장비 분실로 인증기관이 이미 폐기했다 */

    puts(keyloader_trusted(keyloader, ca) ? "REVOKED DEVICE ACCEPTED" : "revoked device refused");

    X509_CRL_free(crl);
    X509_free(keyloader); X509_free(ca);
    EVP_PKEY_free(kl_key); EVP_PKEY_free(ca_key);
    return 0;
}

    X509_verify_cert로 서명 사슬과 유효 기간만 확인한다. 인증기관이 장비 분실로 폐기한 키 적재 장비 인증서도 서명·기간은 맞으므로 그대로 신뢰되어, 분실 장비가 키를 적재받을 수 있다.

    좋은 예

    #include <stdio.h>
#include <openssl/evp.h>
#include <openssl/x509.h>
#include <openssl/x509v3.h>

/* 지상 키 관리 소프트웨어가 접속한 키 적재 장비의 장비 인증서를 확인한다.
 * CRL은 인증기관이 이동식 매체 등 정해진 경로로 배포한 최신본을 쓰고, 없거나 기한이 지나면 실패로 본다 */
static int keyloader_trusted(X509 *device_cert, X509 *project_ca, X509_CRL *latest_crl)
{
    X509_STORE *store = X509_STORE_new();
    X509_STORE_CTX *vctx = X509_STORE_CTX_new();
    int ok = 0;
    if (store != NULL && vctx != NULL && latest_crl != NULL
        && X509_STORE_add_cert(store, project_ca) == 1
        && X509_STORE_add_crl(store, latest_crl) == 1
        && X509_STORE_set_flags(store, X509_V_FLAG_CRL_CHECK | X509_V_FLAG_CRL_CHECK_ALL) == 1
        && X509_STORE_CTX_init(vctx, store, device_cert, NULL) == 1) {
        ok = X509_verify_cert(vctx) == 1;     /* 사슬·기간에 더해 폐기 여부와 CRL 서명·기한을 본다 */
        if (!ok) {
            printf("reason: %s\n", X509_verify_cert_error_string(X509_STORE_CTX_get_error(vctx)));
        }
    }
    X509_STORE_CTX_free(vctx);
    X509_STORE_free(store);
    return ok;
}

    인증기관이 배포한 최신 CRL을 저장소에 넣고 X509_V_FLAG_CRL_CHECK·X509_V_FLAG_CRL_CHECK_ALL을 켜 사슬의 인증서마다 폐기 여부를 확인한다. CRL이 없거나 서명이 맞지 않거나 다음 갱신일이 지나면 검증이 실패하므로, 낡은 폐기 정보로는 장비를 받아들이지 않는다(D-05·T-06). 폐쇄망에서는 CRL을 이동식 매체 등으로 들여오는 주기와 책임을 설계에서 정한다.

    검증: 실행 결과 · Linux(gcc)에서 빌드 — 나쁜 예에서 REVOKED DEVICE ACCEPTED 검출, 좋은 예에서 미검출·revoked device refused 출력 확인 · 참고: MITRE CWE-299 Demonstrative Example 1(인증서가 있는지만 보고 폐기 여부는 확인하지 않음) 참고, 이 가이드가 새로 작성

    나쁜 예

    #include <openssl/evp.h>
#include <openssl/x509.h>
#include <openssl/x509v3.h>
#include <cstdio>
#include <memory>

template <class T, void (*F)(T *)> struct Deleter { void operator()(T *p) const { F(p); } };
using Key = std::unique_ptr<EVP_PKEY, Deleter<EVP_PKEY, EVP_PKEY_free>>;
using Cert = std::unique_ptr<X509, Deleter<X509, X509_free>>;
using Crl = std::unique_ptr<X509_CRL, Deleter<X509_CRL, X509_CRL_free>>;
using Store = std::unique_ptr<X509_STORE, Deleter<X509_STORE, X509_STORE_free>>;
using StoreCtx = std::unique_ptr<X509_STORE_CTX, Deleter<X509_STORE_CTX, X509_STORE_CTX_free>>;

// 임무 계획 도구: 임무 계획 파일에 서명한 운용자 인증서를 확인한다
class PlanSignerCheck {
public:
    PlanSignerCheck(X509 *project_ca, X509_CRL *latest_crl) : store_(X509_STORE_new()) {
        X509_STORE_add_cert(store_.get(), project_ca);
        X509_STORE_add_crl(store_.get(), latest_crl);   // 폐기 목록을 넣었지만 확인하라는 플래그는 켜지 않았다
    }
    bool trusted(X509 *signer) const {
        StoreCtx ctx(X509_STORE_CTX_new());
        return ctx && X509_STORE_CTX_init(ctx.get(), store_.get(), signer, nullptr) == 1 &&
               X509_verify_cert(ctx.get()) == 1;
    }

private:
    Store store_;
};

// ---- 시험 준비: 사업 인증기관, 운용자 서명 인증서, 그 인증서를 폐기한 CRL ----
static Cert issue(const char *cn, EVP_PKEY *subject, X509 *issuer, EVP_PKEY *signer, long serial) {
    Cert crt(X509_new());
    X509_NAME *name = X509_get_subject_name(crt.get());
    X509_NAME_add_entry_by_txt(name, "CN", MBSTRING_ASC, reinterpret_cast<const unsigned char *>(cn), -1, -1, 0);
    ASN1_INTEGER_set(X509_get_serialNumber(crt.get()), serial);
    X509_gmtime_adj(X509_getm_notBefore(crt.get()), -60);
    X509_gmtime_adj(X509_getm_notAfter(crt.get()), 30L * 86400);
    X509_set_issuer_name(crt.get(), issuer ? X509_get_subject_name(issuer) : name);
    X509_set_pubkey(crt.get(), subject);
    X509_EXTENSION *bc = X509V3_EXT_conf_nid(nullptr, nullptr, NID_basic_constraints,
                                             issuer ? "critical,CA:FALSE" : "critical,CA:TRUE");
    X509_add_ext(crt.get(), bc, -1);
    X509_EXTENSION_free(bc);
    X509_sign(crt.get(), signer, EVP_sha256());
    return crt;
}

static Crl revoke(X509 *ca, EVP_PKEY *ca_key, X509 *victim) {
    Crl crl(X509_CRL_new());
    ASN1_TIME *now = X509_gmtime_adj(nullptr, 0), *next = X509_gmtime_adj(nullptr, 7L * 86400);
    X509_REVOKED *entry = X509_REVOKED_new();
    X509_CRL_set_version(crl.get(), X509_CRL_VERSION_2);
    X509_CRL_set_issuer_name(crl.get(), X509_get_subject_name(ca));
    X509_CRL_set1_lastUpdate(crl.get(), now);
    X509_CRL_set1_nextUpdate(crl.get(), next);
    X509_REVOKED_set_serialNumber(entry, X509_get_serialNumber(victim));
    X509_REVOKED_set_revocationDate(entry, now);
    X509_CRL_add0_revoked(crl.get(), entry);
    X509_CRL_sort(crl.get());
    X509_CRL_sign(crl.get(), ca_key, EVP_sha256());
    ASN1_TIME_free(now);
    ASN1_TIME_free(next);
    return crl;
}

int main() {
    Key ca_key(EVP_EC_gen("P-256")), op_key(EVP_EC_gen("P-256"));
    Cert ca = issue("Project Mission Planning CA (example)", ca_key.get(), nullptr, ca_key.get(), 1);
    Cert op = issue("planner-op-12 (example)", op_key.get(), ca.get(), ca_key.get(), 0x2012);
    Crl crl = revoke(ca.get(), ca_key.get(), op.get());   // 운용자 전출로 인증기관이 이미 폐기했다

    const PlanSignerCheck check(ca.get(), crl.get());
    std::puts(check.trusted(op.get()) ? "REVOKED SIGNER ACCEPTED" : "revoked signer refused");
    return 0;
}

    CRL을 X509_STORE에 넣기만 하고 X509_V_FLAG_CRL_CHECK를 켜지 않는다. OpenSSL은 이 플래그가 없으면 저장소의 CRL을 보지 않으므로, 전출로 폐기된 운용자의 서명 인증서가 그대로 통과한다. 폐기 목록을 넣었다는 사실만 보고 점검을 끝내기 쉬운 경우다.

// 임무 계획 도구: 임무 계획 파일에 서명한 운용자 인증서를 확인한다
class PlanSignerCheck {
public:
    PlanSignerCheck(X509 *project_ca, X509_CRL *latest_crl) : store_(X509_STORE_new()) {
        ready_ = store_ && latest_crl && X509_STORE_add_cert(store_.get(), project_ca) == 1 &&
                 X509_STORE_add_crl(store_.get(), latest_crl) == 1 &&
                 // 끝 인증서와 중간 인증기관 모두 폐기 여부를 확인한다. CRL이 없거나 기한이 지나면 검증 실패
                 X509_STORE_set_flags(store_.get(), X509_V_FLAG_CRL_CHECK | X509_V_FLAG_CRL_CHECK_ALL) == 1;
    }
    bool trusted(X509 *signer) const {
        StoreCtx ctx(X509_STORE_CTX_new());
        if (!ready_ || !ctx || X509_STORE_CTX_init(ctx.get(), store_.get(), signer, nullptr) != 1) return false;
        if (X509_verify_cert(ctx.get()) == 1) return true;
        std::printf("reason: %s\n", X509_verify_cert_error_string(X509_STORE_CTX_get_error(ctx.get())));
        return false;
    }

private:
    Store store_;
    bool ready_ = false;
};

    X509_STORE_set_flags로 X509_V_FLAG_CRL_CHECK·X509_V_FLAG_CRL_CHECK_ALL을 켜고, 설정이 하나라도 실패하면 검증기를 쓰지 않는다. 거부 사유(certificate revoked)는 기록에 남긴다(D-05·T-06). 통합 및 시험 단계에서는 폐기한 인증서, 기한이 지난 CRL, CRL이 없는 경우를 각각 넣어 거부되는지 확인한다.

static HttpClient CreateConfigClient()
{
    // 폐쇄망이라 인증서 폐기 목록을 받을 수 없다는 이유로 폐기 확인을 끈다
#pragma warning disable CA2000 // 처리기는 HttpClient가 함께 해제한다
    var handler = new HttpClientHandler
    {
        CheckCertificateRevocationList = false,
    };
#pragma warning restore CA2000

    {
        BaseAddress = new Uri("https://config.example.invalid/"),
    };
}

    HttpClientHandler.CheckCertificateRevocationList를 false로 둔다. 폐기된 서버 인증서도 사슬과 이름만 맞으면 연결되며, .NET 분석기가 CA5399(HttpClient 인증서 폐기 목록 검사 끄기)로 경고한다. 이 속성의 기본값이 false여서 값을 적지 않은 HttpClientHandler도 CA5399로 경고되지만, 처리기 없이 만든 new HttpClient()는 경고되지 않으므로(net10.0 실험) 코드 리뷰로 확인한다.

    나쁜 예

    import datetime

from cryptography import x509
from cryptography.hazmat.primitives import hashes
from cryptography.hazmat.primitives.asymmetric import ec
from cryptography.x509.oid import NameOID

NOW = datetime.datetime.now(datetime.timezone.utc)
DAY = datetime.timedelta(days=1)


def issue(subject, issuer, pub, key, serial, ca=False):          # 시험 준비용 인증서 발급
    return (x509.CertificateBuilder().subject_name(subject).issuer_name(issuer).public_key(pub)
            .serial_number(serial).not_valid_before(NOW - DAY).not_valid_after(NOW + 365 * DAY)
            .add_extension(x509.BasicConstraints(ca=ca, path_length=None), critical=True)
            .sign(key, hashes.SHA256()))


name = lambda cn: x509.Name([x509.NameAttribute(NameOID.COMMON_NAME, cn)])
ca_key, loader_key = ec.generate_private_key(ec.SECP256R1()), ec.generate_private_key(ec.SECP256R1())
CA = issue(name("GSE Root CA"), name("GSE Root CA"), ca_key.public_key(), ca_key, 1, ca=True)
loader = issue(name("key-loader-07"), CA.subject, loader_key.public_key(), ca_key, 0x2F)
# 키 적재 장비 07을 분실해 기관 CA가 인증서를 폐기하고 CRL을 냈다
CRL = (x509.CertificateRevocationListBuilder().issuer_name(CA.subject).last_update(NOW).next_update(NOW + DAY)
       .add_revoked_certificate(x509.RevokedCertificateBuilder().serial_number(0x2F).revocation_date(NOW).build())
       .sign(ca_key, hashes.SHA256()))


# 지상 키 관리 소프트웨어가 접속한 키 적재 장비의 장비 인증서를 확인한다
def accept_loader(cert):
    cert.verify_directly_issued_by(CA)                            # 서명·발급자 확인
    if not cert.not_valid_before_utc <= NOW <= cert.not_valid_after_utc:
        return "REJECTED (expired)"
    return "ACCEPTED"                                             # 폐기 여부는 보지 않는다


print("key-loader-07:", accept_loader(loader))

    인증서의 발급자 서명과 유효 기간만 보고 폐기 여부는 확인하지 않는다. 분실한 키 적재 장비의 인증서를 기관 CA가 폐기해도 유효 기간이 남아 있는 동안은 그 장비가 키를 적재받을 수 있다. Python ssl 모듈도 기본 설정(create_default_context)에서는 CRL을 확인하지 않는다.

    좋은 예

    import datetime

from cryptography import x509
from cryptography.hazmat.primitives import hashes
from cryptography.hazmat.primitives.asymmetric import ec
from cryptography.x509.oid import NameOID

NOW = datetime.datetime.now(datetime.timezone.utc)
DAY = datetime.timedelta(days=1)


def issue(subject, issuer, pub, key, serial, ca=False):          # 시험 준비용 인증서 발급
    return (x509.CertificateBuilder().subject_name(subject).issuer_name(issuer).public_key(pub)
            .serial_number(serial).not_valid_before(NOW - DAY).not_valid_after(NOW + 365 * DAY)
            .add_extension(x509.BasicConstraints(ca=ca, path_length=None), critical=True)
            .sign(key, hashes.SHA256()))


name = lambda cn: x509.Name([x509.NameAttribute(NameOID.COMMON_NAME, cn)])
ca_key, loader_key = ec.generate_private_key(ec.SECP256R1()), ec.generate_private_key(ec.SECP256R1())
CA = issue(name("GSE Root CA"), name("GSE Root CA"), ca_key.public_key(), ca_key, 1, ca=True)
loader = issue(name("key-loader-07"), CA.subject, loader_key.public_key(), ca_key, 0x2F)
# 키 적재 장비 07을 분실해 기관 CA가 인증서를 폐기하고 CRL을 냈다
CRL = (x509.CertificateRevocationListBuilder().issuer_name(CA.subject).last_update(NOW).next_update(NOW + DAY)
       .add_revoked_certificate(x509.RevokedCertificateBuilder().serial_number(0x2F).revocation_date(NOW).build())
       .sign(ca_key, hashes.SHA256()))


def accept_loader(cert, crl):
    cert.verify_directly_issued_by(CA)
    if not cert.not_valid_before_utc <= NOW <= cert.not_valid_after_utc:
        return "REJECTED (expired)"
    # 폐기 확인: CRL이 같은 CA의 서명이고 기한 안일 때만 믿고, 없거나 낡았으면 거부한다(실패 시 닫힘)
    if crl is None or not crl.is_signature_valid(CA.public_key()) or crl.next_update_utc is None or crl.next_update_utc < NOW:
        return "REJECTED (no valid CRL)"
    if crl.get_revoked_certificate_by_serial_number(cert.serial_number) is not None:
        return "REJECTED (revoked)"
    return "ACCEPTED"


print("key-loader-07:", accept_loader(loader, CRL))

    같은 CA가 서명했고 기한(next_update)이 지나지 않은 CRL로 일련번호가 폐기 목록에 있는지 확인하고, CRL이 없거나 낡았으면 거부한다(실패 시 닫힘, D-05). TLS 연결에서는 ctx.verify_flags |= ssl.VERIFY_CRL_CHECK_LEAF로 켜고 load_verify_locations로 CRL 파일을 함께 넣는다. 폐쇄망에서는 CRL을 반입하는 주기와 기한이 지났을 때의 처리를 운용 절차로 정하고, 폐기한 인증서로 접속이 거부되는지 부정 시험을 한다(T-06).

    MITRE 원문 예시(Demonstrative Examples, 영문 1건)

    Example 1. The following OpenSSL code ensures that there is a certificate before continuing execution.

    Bad / C

    if (cert = SSL_get_peer_certificate(ssl)) {

                             // got a certificate, do secret things

    Because this code does not use SSL_get_verify_results() to check the certificate, it could accept certificates that have been revoked (X509_V_ERR_CERT_REVOKED). The product could be communicating with a malicious host.
