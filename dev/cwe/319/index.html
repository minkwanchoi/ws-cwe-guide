    Cleartext Transmission of Sensitive Information

    항목 내용
    추상화 수준 기본(Base)
    상태 초안(Draft)
    소속 「보안약점 점검 목록」(44개)
    가이드 적용성 해당
    적용 플랫폼 언어: 언어 무관, Go · 기술: 기술 무관, 클라우드 컴퓨팅(Cloud Computing), 모바일(Mobile), 산업제어시스템·운영기술(ICS/OT), 시스템 온 칩(System on Chip), 시험·디버그 하드웨어(Test/Debug Hardware)
    원문 MITRE CWE-319 (CWE 5.0)

    이름 표기

    「소프트웨어 개발보안 가이드」(2021. 11.)의 구현단계 기준은 CWE-312·319를 '암호화되지 않은 중요정보'(인쇄 227쪽) 하나로 묶는다. 이 가이드는 둘을 따로 다루므로 같은 가이드 분석·설계단계 사례의 그림 제목 '중요정보 평문전송'(그림 3-34, 인쇄 123쪽)을 띄어 써서 이름으로 쓴다.

    한 줄 요약

    민감하거나 보안상 중요한 데이터를 도청될 수 있는 통신 채널로 평문 전송하는 약점이다.

    → 나쁜 예·좋은 예

    설명(Description)¶

    제품이 민감하거나 보안상 중요한 데이터를, 권한 없는 행위자가 스니핑(sniffing)할 수 있는 통신 채널에서 평문으로 전송한다.

    원문(Description)

    The product transmits sensitive or security-critical data in cleartext in a communication channel that can be sniffed by unauthorized actors.

    발생 단계(Modes Of Introduction)¶

    CWE 단계(Phase) 수명주기 단계(가이드 대응) 설명
    아키텍처·설계(Architecture and Design) 설계 누락(OMISSION): 아키텍처·설계 단계에서 보안 전술을 빠뜨려 생기는 약점이다.
    아키텍처·설계(Architecture and Design) 설계 하드웨어에서는 정당한 사용자가 장치를 원격으로 조작하는 동안 공격자가 물리적으로 접근하는 상황을 설계에서 고려하지 않을 때 이 약점이 생길 수 있다.
    운용(Operation) 유지보수 —
    시스템 구성(System Configuration) 유지보수 —

    영향(Common Consequences)¶

    영역 영향 설명
    무결성 / 기밀성 애플리케이션 데이터 읽기 / 파일·디렉터리 수정 통신 채널에 접근하면 누구나 정보를 읽을 수 있으며, 많은 채널은 전송 중 스니핑될 수 있다. 예를 들어 패킷은 인터넷·내부망·클라우드 등에서 여러 중간 노드를 거치고, 라우터처럼 채널의 네트워크 인터페이스나 링크에 특권 접근을 가진 일부 행위자는 데이터를 수집할 권한이 없더라도 트래픽을 스니핑해 보안상 중요한 데이터를 유출할 수 있다.
    무결성 / 기밀성 애플리케이션 데이터 읽기 / 파일·디렉터리 수정 / 기타 패킷 덤프처럼 통신 전체가 기록되면 공격자는 전송 한참 뒤에 덤프를 얻어 그 안의 평문을 읽으려 할 수 있으며, 사람이 읽을 수 없게 인코딩되어 있어도 일부 기법으로 인코딩 방식을 알아내 디코딩할 수 있다.

    완화책(Potential Mitigations)¶

    원문 완화책 5건(수명주기 단계로 묶은 규칙은 색인에 있다).

    요구사항 분석 (본문 제3장)¶

    원문 완화책 없음. 이 단계의 기준선 활동: R-01 보안 요구사항 정의

    설계 (본문 제4장)¶

    CWE 단계(Phase) 전략 요지
    아키텍처·설계(Architecture and Design) — 전송 전에 기밀성을 보호하는 신뢰할 수 있는 암호 프로토콜로 데이터를 암호화한다.
    원문

    Before transmitting, encrypt the data using reliable, confidentiality-protecting cryptographic protocols.

    구현 (본문 제5장)¶

    CWE 단계(Phase) 전략 요지
    구현(Implementation) — SSL을 쓰는 웹 애플리케이션은 첫 로그인 페이지만이 아니라 로그인부터 로그아웃까지 세션 전체에 SSL을 사용한다.
    원문

    When using web applications with SSL, use SSL for the entire session from login to logout, not just for the initial login page.
    구현(Implementation) — 하드웨어 플랫폼을 설계할 때 승인된 암호 알고리즘(예: NIST 권고 알고리즘)이 보안상 중요한 데이터에서 신뢰된 사용자 애플리케이션까지의 경로를 보호하게 한다.
    원문

    When designing hardware platforms, ensure that approved encryption algorithms (such as those recommended by NIST) protect paths from security critical data to trusted user applications.

    통합 및 시험 (본문 제6장)¶

    CWE 단계(Phase) 전략 요지
    시험(Testing) — 침투 시험, 위협 모델링, 활성 세션을 기록·수정할 수 있는 대화형 도구처럼 사람의 수동 분석이 필요한 도구·기법을 사용한다. 이런 도구·기법은 순수 자동 기법보다 효과적일 수 있으며, 특히 설계·업무 규칙과 관련된 약점에서 그렇다.
    원문

    Use tools and techniques that require manual (human) analysis, such as penetration testing, threat modeling, and interactive tools that allow the tester to record and modify an active session. These may be more effective than strictly automated techniques. This is especially the case with weaknesses that are related to design and business rules.

    유지보수 (본문 제7장)¶

    CWE 단계(Phase) 전략 요지
    운용(Operation) — 서버가 암호화 채널로 통신하도록 설정하며, 여기에는 SSL이나 다른 보안 프로토콜이 포함될 수 있다.
    원문

    Configure servers to use encrypted channels for communication, which may include SSL or other secure protocols.

    예시(나쁜 예·좋은 예)¶

    아래 코드는 이 가이드가 다음 상황을 가정해 새로 작성한 것이다. 지상 통제 소프트웨어가 무인기에 경로점 변경 명령을 데이터링크 프레임으로 보낸다. 무선 구간은 제3자도 수신할 수 있으므로 송신 버퍼에 실린 바이트가 곧 도청자가 보는 내용이다. 예시는 실제 네트워크 대신 송신 버퍼에서 좌표 문자열이 보이는지 찾아 본다. 좋은 예의 논스 순번은 어느 언어든 비휘발성으로 유지해 재시작 뒤에도 되돌아가지 않게 하고, 양방향에 같은 키를 쓰면 순번이 겹치므로 방향별로 키를 나누거나 논스에 방향·장비 번호를 넣으며, 한계에 이르기 전에 키를 갱신한다. 언어마다 분석기·새니타이저·실행 결과로 나쁜 예는 잡히고 좋은 예는 잡히지 않음을 확인했다. 좋은 예는 그 약점 하나를 막는 최소 예이며 그대로 운용 코드가 되는 것은 아니다. 언어 상자를 눌러 펼친다.

    C

    나쁜 예

    #define _GNU_SOURCE
#include <stdint.h>
#include <stdio.h>
#include <string.h>

#define MSG_WAYPOINT_UPDATE 0x21u

/* 데이터링크 프레임: [동기 2|메시지 ID 1|길이 1|페이로드] */
static size_t build_frame(uint8_t *frame, size_t cap, const char *payload)
{
    size_t len = strlen(payload);
    if (len > 255 || 4 + len > cap) {
        return 0;
    }
    frame[0] = 0xEB; frame[1] = 0x90;
    frame[2] = MSG_WAYPOINT_UPDATE;
    frame[3] = (uint8_t)len;
    memcpy(frame + 4, payload, len);          /* 임무 명령을 그대로 싣는다 */
    return 4 + len;
}

int main(void)
{
    const char *order = "WP7 LAT=EXAMPLE-ONLY-35.10 LON=EXAMPLE-ONLY-129.04";
    uint8_t tx[300];
    size_t n = build_frame(tx, sizeof tx, order);

    /* 무선 구간을 수신한 제3자가 보는 것은 tx 바이트 그대로다 */
    const char *probe = "LAT=EXAMPLE-ONLY-35.10";
    int seen = n > 0 && memmem(tx, n, probe, strlen(probe)) != NULL;
    puts(seen ? "PLAINTEXT ON LINK" : "link carries ciphertext only");
    return 0;
}

    명령 본문(좌표)을 프레임에 그대로 복사해 보낸다. 무선 구간을 수신하는 누구나 좌표를 읽고, 같은 형식으로 가짜 명령을 만들 수도 있다.

    좋은 예

    #define _GNU_SOURCE
#include <stdint.h>
#include <stdio.h>
#include <string.h>
#include <openssl/evp.h>
#include <openssl/rand.h>

#define MSG_WAYPOINT_UPDATE 0x21u

/* 프레임: [동기 2|ID 1|길이 1|논스 12|암호문|태그 16], 머리부는 AAD로 무결성만 보호 */
static size_t seal_frame(uint8_t *frame, size_t cap, const uint8_t key[32],
                         uint64_t counter, const char *payload)
{
    int len = (int)strlen(payload), out = 0, tail = 0, ok = 0;
    if (len > 255 || (size_t)(32 + len) > cap) {
        return 0;
    }
    uint8_t *nonce = frame + 4, *body = frame + 16;
    frame[0] = 0xEB; frame[1] = 0x90; frame[2] = MSG_WAYPOINT_UPDATE; frame[3] = (uint8_t)len;
    memset(nonce, 0, 4);                          /* 송신 장비 번호 자리 */
    memcpy(nonce + 4, &counter, 8);               /* 같은 키로 논스를 다시 쓰지 않는다 */
    EVP_CIPHER_CTX *ctx = EVP_CIPHER_CTX_new();
    if (ctx != NULL && EVP_EncryptInit_ex(ctx, EVP_aes_256_gcm(), NULL, key, nonce) == 1
        && EVP_EncryptUpdate(ctx, NULL, &out, frame, 4) == 1
        && EVP_EncryptUpdate(ctx, body, &out, (const uint8_t *)payload, len) == 1
        && EVP_EncryptFinal_ex(ctx, body + out, &tail) == 1
        && EVP_CIPHER_CTX_ctrl(ctx, EVP_CTRL_GCM_GET_TAG, 16, body + len) == 1) {
        ok = 1;
    }
    EVP_CIPHER_CTX_free(ctx);
    return ok ? (size_t)(32 + len) : 0;          /* 실패하면 평문으로 보내지 않는다 */
}

int main(void)
{
    uint8_t key[32];                              /* 시험용: 실제로는 키 관리 체계가 주입한 링크 키 */
    if (RAND_bytes(key, sizeof key) != 1) {
        return 1;
    }
    const char *order = "WP7 LAT=EXAMPLE-ONLY-35.10 LON=EXAMPLE-ONLY-129.04";
    uint8_t tx[300];
    size_t n = seal_frame(tx, sizeof tx, key, 1u, order);

    const char *probe = "LAT=EXAMPLE-ONLY-35.10";
    int seen = n > 0 && memmem(tx, n, probe, strlen(probe)) != NULL;
    puts(n == 0 ? "send refused" : seen ? "PLAINTEXT ON LINK" : "link carries ciphertext only");
    return 0;
}

    검증된 암호 라이브러리의 AES-256-GCM으로 본문을 암호화하고 프레임 머리부는 AAD로 넣어 변조를 탐지한다. 논스는 장비 번호와 순번으로 만들어 같은 키에서 다시 쓰지 않고, 암호화에 실패하면 평문으로 보내지 않는다. 링크 단위로는 승인된 보안 프로토콜(TLS·DTLS 등)이나 링크 암호 장비를 쓰는 것이 원칙이다.

    검증: 실행 결과 · Linux(gcc)에서 빌드 — 나쁜 예에서 PLAINTEXT ON LINK 검출, 좋은 예에서 미검출·link carries ciphertext only 출력 확인 · 참고: MITRE CWE-319 Demonstrative Example 1(암호화하지 않은 연결로 중요정보 전송) 참고, 이 가이드가 새로 작성

    C++

    나쁜 예

    #include <algorithm>
#include <cstdint>
#include <cstdio>
#include <string>
#include <vector>

// 지상 통제 소프트웨어가 무인기로 보낼 임무 명령 프레임을 만든다
struct CommandFrame {
    std::uint8_t msg_id;
    std::string body;

    std::vector<std::uint8_t> encode() const {
        std::vector<std::uint8_t> wire{0xEB, 0x90, msg_id, static_cast<std::uint8_t>(body.size())};
        wire.insert(wire.end(), body.begin(), body.end());   // 명령 본문이 그대로 무선 구간에 실린다
        return wire;
    }
};

static bool eavesdropper_reads(const std::vector<std::uint8_t> &wire, const std::string &probe) {
    return std::search(wire.begin(), wire.end(), probe.begin(), probe.end()) != wire.end();
}

int main() {
    const CommandFrame cmd{0x21, "WP7 LAT=EXAMPLE-ONLY-35.10 LON=EXAMPLE-ONLY-129.04"};
    const std::vector<std::uint8_t> wire = cmd.encode();
    std::puts(eavesdropper_reads(wire, "LAT=EXAMPLE-ONLY-35.10") ? "PLAINTEXT ON LINK"
                                                                  : "link carries ciphertext only");
    return 0;
}

    명령 객체를 직렬화하면서 본문을 그대로 무선 프레임에 넣는다. 도청자는 송신 바이트에서 좌표를 바로 읽는다.

    좋은 예

    #include <openssl/evp.h>
#include <openssl/rand.h>
#include <algorithm>
#include <array>
#include <cstdint>
#include <cstdio>
#include <memory>
#include <optional>
#include <string>
#include <vector>

using Bytes = std::vector<std::uint8_t>;
using CtxPtr = std::unique_ptr<EVP_CIPHER_CTX, decltype(&EVP_CIPHER_CTX_free)>;

// 검증된 암호 라이브러리의 AES-256-GCM: 머리부는 AAD(무결성), 본문은 암호화
static std::optional<Bytes> seal_command(const std::array<std::uint8_t, 32> &key, std::uint64_t seq,
                                         std::uint8_t msg_id, const std::string &body) {
    if (body.size() > 255) return std::nullopt;
    Bytes wire{0xEB, 0x90, msg_id, static_cast<std::uint8_t>(body.size())};
    std::array<std::uint8_t, 12> nonce{};
    for (int i = 0; i < 8; ++i) nonce[4 + i] = static_cast<std::uint8_t>(seq >> (8 * i));   // 순번 논스
    wire.insert(wire.end(), nonce.begin(), nonce.end());
    const std::size_t at = wire.size();
    wire.resize(at + body.size() + 16);
    CtxPtr ctx(EVP_CIPHER_CTX_new(), &EVP_CIPHER_CTX_free);
    int n = 0;
    const int len = static_cast<int>(body.size());
    if (!ctx || EVP_EncryptInit_ex(ctx.get(), EVP_aes_256_gcm(), nullptr, key.data(), nonce.data()) != 1 ||
        EVP_EncryptUpdate(ctx.get(), nullptr, &n, wire.data(), 4) != 1 ||
        EVP_EncryptUpdate(ctx.get(), &wire[at], &n, reinterpret_cast<const std::uint8_t *>(body.data()), len) != 1 ||
        EVP_EncryptFinal_ex(ctx.get(), &wire[at] + n, &n) != 1 ||
        EVP_CIPHER_CTX_ctrl(ctx.get(), EVP_CTRL_GCM_GET_TAG, 16, &wire[at + body.size()]) != 1) {
        return std::nullopt;                                      // 실패하면 보내지 않는다
    }
    return wire;
}

int main() {
    std::array<std::uint8_t, 32> key{};   // 시험용: 실제로는 키 관리 체계가 주입한 링크 키
    if (RAND_bytes(key.data(), static_cast<int>(key.size())) != 1) return 1;
    const auto wire = seal_command(key, 1, 0x21, "WP7 LAT=EXAMPLE-ONLY-35.10 LON=EXAMPLE-ONLY-129.04");
    if (!wire) { std::puts("send refused"); return 1; }
    const std::string probe = "LAT=EXAMPLE-ONLY-35.10";
    const bool seen = std::search(wire->begin(), wire->end(), probe.begin(), probe.end()) != wire->end();
    std::puts(seen ? "PLAINTEXT ON LINK" : "link carries ciphertext only");
    return 0;
}

    AES-256-GCM으로 본문을 암호화하고 머리부를 AAD로 묶는다. 실패하면 std::nullopt를 돌려 보내지 않게 하고, 순번 논스로 재사용을 막는다.

    import java.nio.ByteBuffer;

public class Example {

    // 데이터링크 프레임: [동기 2|메시지 ID 1|길이 1|본문]
    static byte[] buildFrame(String order) {

        if (body.length > 255) {

    import java.nio.ByteBuffer;
import java.nio.charset.StandardCharsets;
import java.security.GeneralSecurityException;
import javax.crypto.Cipher;
import javax.crypto.KeyGenerator;
import javax.crypto.SecretKey;
import javax.crypto.spec.GCMParameterSpec;

public class Example {
    static final byte MSG_WAYPOINT_UPDATE = 0x21;

    // 프레임: [동기 2|ID 1|길이 1|논스 12|암호문+태그 16], 머리부는 AAD로 무결성 보호
    static byte[] sealFrame(SecretKey linkKey, long seq, String order) throws GeneralSecurityException {
        byte[] body = order.getBytes(StandardCharsets.US_ASCII);
        if (body.length > 255) {
            throw new IllegalArgumentException("order too long");
        }
        byte[] head = {(byte) 0xEB, (byte) 0x90, MSG_WAYPOINT_UPDATE, (byte) body.length};
        byte[] nonce = ByteBuffer.allocate(12).putInt(0).putLong(seq).array();   // 장비 번호 + 순번
        Cipher gcm = Cipher.getInstance("AES/GCM/NoPadding");
        gcm.init(Cipher.ENCRYPT_MODE, linkKey, new GCMParameterSpec(128, nonce));
        gcm.updateAAD(head);
        byte[] sealed = gcm.doFinal(body);
        return ByteBuffer.allocate(head.length + nonce.length + sealed.length).put(head).put(nonce).put(sealed).array();
    }

    public static void main(String[] args) throws GeneralSecurityException {
        KeyGenerator kg = KeyGenerator.getInstance("AES");   // 시험용: 실제로는 키 관리 체계가 주입한 키
        kg.init(256);
        byte[] wire = sealFrame(kg.generateKey(), 1L, "WP7 LAT=EXAMPLE-ONLY-35.10 LON=EXAMPLE-ONLY-129.04");
        String heard = new String(wire, StandardCharsets.ISO_8859_1);
        System.out.println(heard.contains("LAT=EXAMPLE-ONLY-35.10") ? "PLAINTEXT ON LINK" : "link carries ciphertext only");
    }
}

    AES/GCM/NoPadding으로 본문을 암호화하고 updateAAD로 머리부를 인증한다. 논스는 장비 번호와 순번으로 만들어 같은 키에서 반복되지 않게 한다. 소켓 통신이라면 SSLSocket·HTTPS를 쓰고 인증서 검증을 끄지 않는다.

    탐지 방법(Detection Methods)¶

    방법 요지 효과성
    블랙박스 시험 운영체제·네트워크와 상호작용하는 소프트웨어 프로세스를 살피는 모니터링 도구를 쓴다. 소스코드가 없거나, 직접 개발하지 않은 소프트웨어이거나, 빌드 단계에서 새 약점이 들어오지 않았는지 확인하려 할 때 유용하다. 도구로는 실행 중인 프로세스에 붙는 디버거, truss(Solaris)·strace(Linux) 같은 시스템 호출 추적 도구, FileMon·RegMon·Process Monitor 등 Sysinternals 유틸리티(Windows), 네트워크 트래픽을 보는 스니퍼·프로토콜 분석기가 있다. 모니터를 프로세스에 붙이고 데이터를 보내는 기능을 실행해 호출 트리에 일반적인 암호 함수가 있는지 본다. 네트워크를 감시해 데이터 패킷에 읽을 수 있는 명령이 있는지 확인한다. 특정 인코딩 사용을 탐지하는 도구도 있으며, 트래픽 엔트로피가 높으면 암호화를 쓰고 있다는 뜻일 수 있다.

    Use monitoring tools that examine the software's process as it interacts with the operating system and the network. This technique is useful in cases when source code is unavailable, if the software was not developed by you, or if you want to verify that the build phase did not introduce any new weaknesses. Examples include debuggers that directly attach to the running process; system-call tracing utilities such as truss (Solaris) and strace (Linux); system activity monitors such as FileMon, RegMon, Process Monitor, and other Sysinternals utilities (Windows); and sniffers and protocol analyzers that monitor network traffic.

    Attach the monitor to the process, trigger the feature that sends the data, and look for the presence or absence of common cryptographic functions in the call tree. Monitor the network and determine if the data packets contain readable commands. Tools exist for detecting if certain encodings are in use. If the traffic contains high entropy, this might indicate the usage of encryption.

    프레임을 만드는 직렬화 코드에서 중요 필드가 암호화 함수를 거치지 않고 송신 버퍼로 복사되는 경로를 찾는다. I-09 [예시] CWE-319 예시(명령 본문을 프레임에 그대로 복사)
    ICD의 링크·메시지 목록에서 중요정보를 싣는 메시지마다 암호 보호 요구가 있는지, 물리 보호를 근거로 평문을 허용한 내부 버스는 그 근거가 기록됐는지 확인한다. D-09·R-01 [CWE] CWE-319 완화책(Architecture and Design: 전송 전 암호화) · [보완]
    암호 설정을 협상하는 링크는 상대가 평문이나 약한 모드를 제안할 때 받아들이는지 중간자 시험으로 확인한다. T-06 [CWE] CWE-319 완화책(Testing: 침투 시험)
    • ① 원문 탐지 방법(원문 효과성별): 효과 등급 없음: 블랙박스 시험. 각 방법의 시험 활동은 6.2의 대응표를 따른다.
    • ③ SEI CERT 대응 규칙: SEC06-J, SER02-J

    이 가이드에서 다루는 곳¶

    부록 A의 이 항목 행에 있는 단계별 지침 (요구사항 분석 행은 기준선 활동·환경 지침과 원문 완화책에서 모았다)

    단계 지침
    요구사항 분석 R-01 보안 요구사항 정의
    설계 전송 구간별(내부 버스, 이더넷, 무선 데이터링크) 보호 요구를 정의하고 승인된 암호 프로토콜(TLS 1.2 이상 등)을 지정한다.
    구현(C·C++) Mbed TLS/wolfSSL 등 검증된 라이브러리로 TLS를 구성하고 인증서 검증을 비활성화하지 않는다.
    구현(Java) HTTPS/SSLSocket을 사용하고 TrustManager·HostnameVerifier를 무력화하는 코드를 금지한다.
    통합 및 시험 패킷 캡처(Wireshark)로 평문 여부를 확인하고, 침투 시험(penetration test)으로 다운그레이드·중간자 공격을 점검한다.
    유지보수 암호 스위트·인증서 만료를 주기적으로 점검하고 취약 프로토콜을 비활성화한다.
    임베디드 고려 UART·SPI·CAN 등 장비 내부 버스는 물리 보호 여부를 근거로 위험을 평가하고, 외부 노출 링크는 인증 암호화(AES-CCM 등)를 적용한다.

    기준선 활동 2건

    • R-01 보안 요구사항 정의 (요구사항 분석)
    • T-06 보안 기능 부정 시험 (통합 및 시험)

    모든 항목에 공통인 시험 활동. T-01 정적시험과 T-02 타깃 동적시험은 대상 약점을 가리지 않고 모든 과제가 수행한다.

    환경 지침 5건. 과제 환경에 맞는 지침은 지침 선택 도구로 고른다. 축별로 최대 8건을 보이고 나머지는 부록 C에서 찾는다.
