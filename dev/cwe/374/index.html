    Passing Mutable Objects to an Untrusted Method

    항목 내용
    추상화 수준 기본(Base)
    상태 초안(Draft)
    소속 언어 뷰 C·C++·Java(CWE-658·659·660)
    가이드 적용성 해당
    적용 플랫폼 언어: 객체 지향 언어(Object-Oriented), C, C++, Java, C#
    원문 MITRE CWE-374 (CWE 5.0)

    한 줄 요약

    복제하지 않은 변경 가능 데이터를 메서드나 함수의 인자로 보내는 약점이다.

    설명(Description)¶

    제품이 복제(clone)하지 않은 변경 가능(mutable) 데이터를 메서드나 함수의 인자로 보내는 약점이다.

    원문(Description)

    The product sends non-cloned mutable data as an argument to a method or function.

    발생 단계(Modes Of Introduction)¶

    CWE 단계(Phase) 수명주기 단계(가이드 대응) 설명
    구현(Implementation) 구현 —

    영향(Common Consequences)¶

    영역 영향 설명
    무결성 메모리 수정 호출된 함수나 메서드는 변경 가능 데이터를 바꾸거나 삭제할 수 있고, 그 결과 호출한 함수가 자신의 상태에 대해 세운 가정이 깨질 수 있다. 알 수 없는 코드를 변경 가능 데이터의 참조와 함께 호출하는 상황에서는 그 외부 코드가 전달된 데이터를 바꿀 수 있다. 이 데이터를 미리 복제하지 않았다면, 바뀐 데이터는 실행 맥락에서 유효하지 않을 수 있다.

    완화책(Potential Mitigations)¶

    원문 완화책 2건(수명주기 단계로 묶은 규칙은 색인에 있다).

    요구사항 분석 (본문 제3장)¶

    원문 완화책 없음

    설계 (본문 제4장)¶

    원문 완화책 없음

    구현 (본문 제5장)¶

    CWE 단계(Phase) 전략 요지
    구현(Implementation) — 바뀌면 안 되는 데이터는 상수나 불변(immutable) 형태로 전달한다.
    원문

    Pass in data which should not be altered as constant or immutable.
    구현(Implementation) — 외부 함수에 넘기기 전에 모든 변경 가능 데이터를 복제한다. 이것이 선호되는 완화책이며, 데이터가 어떻게 바뀌든 클래스가 쓸 유효한 사본이 남는다.
    원문

    Clone all mutable data before passing it into an external function . This is the preferred mitigation. This way, regardless of what changes are made to the data, a valid copy is retained for use by the class.

    통합 및 시험 (본문 제6장)¶

    원문 완화책 없음

    유지보수 (본문 제7장)¶

    원문 완화책 없음

    예시(나쁜 예·좋은 예)¶

    이 가이드가 새로 쓰는 예시는 언어별로 컴파일과 분석기 검증을 거치므로, 이 판은 「보안약점 점검 목록(44개)」과 보조 항목에만 싣는다. 아래 MITRE 원문 예시를 참고한다.

    MITRE 원문 예시(Demonstrative Examples, 영문 2건)

    Example 1. The following example demonstrates the weakness.

    Bad / C

    private:
  int foo;
  complexType bar;
  String baz;
  otherClass externalClass;

public:
  void doStuff() {
    externalClass.doOtherStuff(foo, bar, baz)
  }

    In this example, bar and baz will be passed by reference to doOtherStuff() which may change them.

    Example 2. In the following Java example, the BookStore class manages the sale of books in a bookstore, this class includes the member objects for the bookstore inventory and sales database manager classes. The BookStore class includes a method for updating the sales database and inventory when a book is sold. This method retrieves a Book object from the bookstore inventory object using the supplied ISBN number for the book class, then calls a method for the sales object to update the sales information and then calls a method for the inventory object to update inventory for the BookStore.

    Bad / Java

    public class BookStore {

  private BookStoreInventory inventory;
  private SalesDBManager sales;
  ...

                             // constructor for BookStore

  public BookStore() {
    this.inventory = new BookStoreInventory();
    this.sales = new SalesDBManager();
    ...
  }
  public void updateSalesAndInventoryForBookSold(String bookISBN) {

                                     // Get book object from inventory using ISBN

    Book book = inventory.getBookWithISBN(bookISBN);

                                     // update sales information for book sold

    sales.updateSalesInformation(book);

                                     // update inventory

    inventory.updateInventory(book);

  }

                             // other BookStore methods

  ...

}
public class Book {
  private String title;
  private String author;
  private String isbn;

                          // Book object constructors and get/set methods

  ...
}

    However, in this example the Book object that is retrieved and passed to the method of the sales object could have its contents modified by the method. This could cause unexpected results when the book object is sent to the method for the inventory object to update the inventory.

    In the Java programming language arguments to methods are passed by value, however in the case of objects a reference to the object is passed by value to the method. When an object reference is passed as a method argument a copy of the object reference is made within the method and therefore both references point to the same object. This allows the contents of the object to be modified by the method that holds the copy of the object reference. [REF-374]

    In this case the contents of the Book object could be modified by the method of the sales object prior to the call to update the inventory.

    To prevent the contents of the Book object from being modified, a copy of the Book object should be made before the method call to the sales object. In the following example a copy of the Book object is made using the clone() method and the copy of the Book object is passed to the method of the sales object. This will prevent any changes being made to the original Book object.

    Good / Java

    ...
public void updateSalesAndInventoryForBookSold(String bookISBN) {

                             // Get book object from inventory using ISBN

  Book book = inventory.getBookWithISBN(bookISBN);

                             // Create copy of book object to make sure contents are not changed

  Book bookSold = (Book) book.clone();

                             // update sales information for book sold

  sales.updateSalesInformation(bookSold);

                             // update inventory

  inventory.updateInventory(book);

}
...

    탐지 방법(Detection Methods)¶

    원문에 탐지 방법이 없다. 상위 계통에서 가장 가까운 2단계 위 항목 CWE-664(기둥(Pillar), 이 가이드 범위 밖 — MITRE 원문)의 탐지 방법 1건을 참고한다(2.7 규칙 1, 내용은 그 항목 쪽에 있다). 기둥(Pillar) 항목의 내용은 일반 원칙 수준이다. 통합 및 시험 단계 기준선 활동(T-01·T-02·T-04·T-05·T-06·T-07·T-08)과 구현 단계의 I-10으로 점검한다.

    도구 미지원 시 대안. 공통안은 6.2에 있고, 이 절에는 이 항목의 고유안만 적는다.

    • ② 상위 CWE-664의 탐지 방법을 참고한다(2.7 규칙 1, 197개 밖은 MITRE 원문).
    • ③ SEI CERT 대응 규칙: OBJ04-J

    이 가이드에서 다루는 곳¶

    언어 뷰 항목의 단계별 지침 (적용성 판정 기준은 부록 B, 요구사항 분석 행은 기준선 활동·환경 지침과 원문 완화책에서 모았다)

    단계 지침
    요구사항 분석 —
    설계 신뢰 경계를 넘어 전달하는 데이터는 불변(immutable) 객체 또는 복사본으로 전달하는 인터페이스 규칙을 정의한다.
    구현 외부 메서드에 가변 객체를 전달할 때 방어적 복사(clone/복사 생성자)를 사용하고, 변경되면 안 되는 인자는 const(C/C++) 또는 불변 타입(Java)으로 선언한다.
    통합 및 시험 코드 리뷰와 정적 분석(SpotBugs, PMD, clang-tidy)으로 가변 객체 전달 지점을 점검하고 인자 변조 단위시험을 수행한다.
    유지보수 API 시그니처 변경 시 호출 경계의 소유권·불변성 규칙을 재검토하고 외부 라이브러리 업데이트 시 재점검한다.
    임베디드 고려 임베디드에서는 복사 비용이 있으므로 const 참조/포인터 전달과 ROM(const) 배치를 활용하고, DMA가 함께 쓰는 공유 버퍼의 소유권 규칙을 명시한다.

    모든 항목에 공통인 시험 활동. T-01 정적시험과 T-02 타깃 동적시험은 대상 약점을 가리지 않고 모든 과제가 수행한다.

    환경 지침 1건. 과제 환경에 맞는 지침은 지침 선택 도구로 고른다. 축별로 최대 8건을 보이고 나머지는 부록 C에서 찾는다.

    축 지침
