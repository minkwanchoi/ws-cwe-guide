    Struts: Validator Turned Off

    항목 내용
    추상화 수준 변형(Variant)
    상태 초안(Draft)
    소속 언어 뷰 Java(CWE-660)
    가이드 적용성 조건부 — 웹·J2EE·EJB·Struts 프레임워크 사용 — 탑재 소프트웨어에서는 대개 비해당(판정 기록)
    적용 플랫폼 언어: Java
    원문 MITRE CWE-109 (CWE 5.0)

    한 줄 요약

    Struts 빈의 자동 필터링이 꺼져 Struts Validator와 사용자 정의 검증 로직이 비활성화되는 약점이다.

    설명(Description)¶

    Struts 빈을 통한 자동 필터링이 꺼져 Struts Validator와 사용자 정의 검증 로직이 비활성화된 약점이다. 이 때문에 애플리케이션이 불충분한 입력값 검증과 관련된 다른 약점에 노출된다.

    원문(Description)

    Automatic filtering via a Struts bean has been turned off, which disables the Struts Validator and custom validation logic. This exposes the application to other weaknesses related to insufficient input validation.

    발생 단계(Modes Of Introduction)¶

    CWE 단계(Phase) 수명주기 단계(가이드 대응) 설명
    구현(Implementation) 구현 —

    영향(Common Consequences)¶

    영역 영향 설명
    접근 통제 보호 메커니즘 우회 —

    완화책(Potential Mitigations)¶

    원문 완화책 1건(수명주기 단계로 묶은 규칙은 색인에 있다).

    요구사항 분석 (본문 제3장)¶

    원문 완화책 없음

    설계 (본문 제4장)¶

    원문 완화책 없음

    구현 (본문 제5장)¶

    CWE 단계(Phase) 전략 요지
    구현(Implementation) — 액션 폼 매핑(action form mapping)에서 검증이 활성화되도록 validate 필드를 true로 설정한다.
    원문

    Ensure that an action form mapping enables validation. Set the validate field to true.

    예시(나쁜 예·좋은 예)¶

    이 가이드가 새로 쓰는 예시는 언어별로 컴파일과 분석기 검증을 거치므로, 이 판은 「보안약점 점검 목록(44개)」과 보조 항목에만 싣는다. 아래 MITRE 원문 예시를 참고한다.

    MITRE 원문 예시(Demonstrative Examples, 영문 1건)

    Example 1. This mapping defines an action for a download form:

    Bad / XML

    <action path="/download"
type="com.website.d2.action.DownloadAction"
name="downloadForm"
scope="request"
input=".download"
validate="false">
</action>

    This mapping has disabled validation. Disabling validation exposes this action to numerous types of attacks.

    탐지 방법(Detection Methods)¶

    방법 요지 효과성
    자동 정적 분석 흔히 SAST(Static Application Security Testing)라 부르는 자동 정적 분석(static analysis)은 소스코드(또는 바이너리·컴파일된 코드)를 실행하지 않고 분석해 이 약점의 일부 사례를 찾을 수 있으며, 대개 데이터 흐름·제어 흐름 모델을 만든 뒤 입력 출처('source')와 외부 구성요소나 운영체제 같은 하위 계층과 상호작용하는 목적지('sink')를 잇는 잠재적 취약 패턴을 찾는다.
    원문

    Automated static analysis, commonly referred to as Static Application Security Testing (SAST), can find some instances of this weakness by analyzing source code (or binary/compiled code) without having to execute it. Typically, this is done by building a model of data flow and control flow, then searching for potentially-vulnerable patterns that connect "sources" (origins of input) with "sinks" (destinations where the data interacts with external components, a lower layer such as the OS, etc.)

    		 높음(High)

    탐지 방법별 시험 활동은 제6장에 있다.

    도구 미지원 시 대안. 공통안은 6.2에 있고, 이 절에는 이 항목의 고유안만 적는다.

    • ① 원문 탐지 방법은 자동 정적 분석뿐이다. 다른 정적 분석 도구·컴파일러 경고로 점검한다.

    이 가이드에서 다루는 곳¶

    언어 뷰 항목의 단계별 지침 (적용성 판정 기준은 부록 B, 요구사항 분석 행은 기준선 활동·환경 지침과 원문 완화책에서 모았다)

    단계 지침
    요구사항 분석 —
    설계 입력 검증 기능을 비활성화하지 않는 구성 기준을 설계 단계에서 확정한다.
    구현 struts-config.xml의 액션 매핑에서 validate 속성을 true로 설정하고 validate="false"를 금지한다.
    통합 및 시험 Struts 설정(validation.xml, struts-config.xml)과 코드를 정적 분석 도구(예: SpotBugs, PMD, Fortify)와 수동 검토로 점검하고, 비정상 입력 시 검증 동작을 단위시험으로 확인한다.
    유지보수 Struts 폼·검증 설정 변경 시 validation.xml과 ActionForm의 일치성을 재점검하고, Struts 1.x는 지원이 끝났으므로 지원되는 프레임워크로 옮기고(M-07), 그 전까지 보상통제를 기록한다.
    임베디드 고려 Struts는 서버·웹 프레임워크라 MCU 대상에는 해당하지 않는다. SBC의 웹 관리 인터페이스에 쓰는 경우에는 지원되는 프레임워크를 쓴다.

    모든 항목에 공통인 시험 활동. T-01 정적시험과 T-02 타깃 동적시험은 대상 약점을 가리지 않고 모든 과제가 수행한다.
