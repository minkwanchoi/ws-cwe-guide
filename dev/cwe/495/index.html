    Private Data Structure Returned From A Public Method

    항목 내용
    추상화 수준 변형(Variant)
    상태 초안(Draft)
    소속 「보안약점 점검 목록」(44개) · 언어 뷰 C·C++·Java(CWE-658·659·660)
    가이드 적용성 조건부 — 접근 범위가 있는 자료구조 노출(클래스·모듈 정적 배열)
    적용 플랫폼 언어: 객체 지향 언어(Object-Oriented), C, C++, Java, C#
    원문 MITRE CWE-495 (CWE 5.0)

    이름 표기

    「소프트웨어 개발보안 가이드」(2021. 11.)의 항목명은 'Public 메소드부터 반환된 Private 배열'(인쇄 324쪽)이다. 이 가이드는 '메소드'만 가이드 전체 표기인 '메서드'로 적는다. 과학기술정보통신부·한국인터넷진흥원 「Python 시큐어코딩 가이드」(2023. 12.)도 부록 기준표에서 '메서드'로 적는다(본문은 '메소드로부터').

    한 줄 요약

    public으로 선언된 메서드가 private 자료구조의 참조를 반환해 예상치 못하게 수정될 수 있는 약점이다.

    → 나쁜 예·좋은 예

    설명(Description)¶

    제품에 public으로 선언된 메서드가 있는데, 이 메서드가 private 자료구조에 대한 참조를 반환하여 그 자료구조가 예상치 못한 방식으로 수정될 수 있는 약점이다.

    원문(Description)

    The product has a method that is declared public, but returns a reference to a private data structure, which could then be modified in unexpected ways.

    발생 단계(Modes Of Introduction)¶

    CWE 단계(Phase) 수명주기 단계(가이드 대응) 설명
    구현(Implementation) 구현 —

    영향(Common Consequences)¶

    영역 영향 설명
    무결성 애플리케이션 데이터 수정 자료구조의 내용이 의도한 범위 밖에서 수정될 수 있다.

    완화책(Potential Mitigations)¶

    원문 완화책 3건(수명주기 단계로 묶은 규칙은 색인에 있다).

    CWE 단계(Phase) 전략 요지

    원문

    Declare the method private.
    구현(Implementation) — 멤버 데이터를 복제하고, 수정되지 않은 데이터 버전은 객체의 private으로 유지한다.
    원문

    구현(Implementation) — private 멤버를 어떻게 수정할 수 있는지 통제하는 public setter 메서드를 쓴다.
    원문

    예시(나쁜 예·좋은 예)¶

    아래 코드는 이 가이드가 다음 상황을 가정해 새로 작성한 것이다. 고도 제한표·무선 허용 모드·서보 구동 금지 각도·승인 채널표처럼 안전에 직결되는 표를 모듈이나 클래스 안에 감춰 두고, 화면 표시 등 다른 코드가 읽어 간다. 읽기용으로 내준 배열이 내부 저장소 그 자체이면, 받은 쪽이 단위 변환·정렬·편집을 하는 순간 내부 상태가 바뀐다. 언어마다 분석기·새니타이저·실행 결과로 나쁜 예는 잡히고 좋은 예는 잡히지 않음을 확인했다. 좋은 예는 그 약점 하나를 막는 최소 예이며 그대로 운용 코드가 되는 것은 아니다. 언어 상자를 눌러 펼친다.

    C

    나쁜 예

    #include <stdio.h>

/* ---- 비행 제한 모듈(fence.c): 고도 제한표는 모듈 내부(static) 자료다 ---- */
static int altitude_limit_m[3] = {120, 300, 1500};   /* 구역별 최대 고도 */

int *fence_limits(void)                  /* 내부 배열의 쓰기 가능한 주소를 그대로 내준다 */
{
    return altitude_limit_m;
}

int fence_allows(int zone, int alt_m)
{
    return alt_m <= altitude_limit_m[zone];
}

/* ---- 다른 모듈(표시 장치): 화면 단위 변환을 하려다 내부 표를 바꿔 버린다 ---- */
static void show_limits_in_feet(void)
{
    int *lim = fence_limits();
    for (int i = 0; i < 3; ++i) {
        lim[i] = lim[i] * 328 / 100;      /* 복사본이라 생각하고 덮어씀 */
        printf("zone %d: %d ft\n", i, lim[i]);
    }
}

int main(void)
{
    show_limits_in_feet();
    printf("zone 0 allows 350 m? %s\n", fence_allows(0, 350) ? "YES (limit table corrupted)" : "no");
    return 0;
}

    모듈 내부 static 배열의 쓰기 가능한 주소를 그대로 돌려준다. 표시 모듈이 단위를 피트로 바꾸려고 덮어쓰자 비행 제한 판정이 바뀌어 350 m 비행이 허용된다. C에는 접근 제어가 없지만 파일 범위 static이 private 역할을 하므로 같은 약점이 생긴다.

    좋은 예

    #include <stddef.h>
#include <stdio.h>

/* ---- 비행 제한 모듈(fence.c) ---- */
static int altitude_limit_m[3] = {120, 300, 1500};

/* 호출자 버퍼에 복사해 준다: 내부 표의 주소는 모듈 밖으로 나가지 않는다 */
size_t fence_copy_limits(int *out, size_t cap)
{
    size_t n = sizeof altitude_limit_m / sizeof altitude_limit_m[0];
    if (out == NULL || cap < n) {
        return 0;
    }
    for (size_t i = 0; i < n; ++i) {
        out[i] = altitude_limit_m[i];
    }
    return n;
}

int fence_allows(int zone, int alt_m)
{
    if (zone < 0 || (size_t)zone >= sizeof altitude_limit_m / sizeof altitude_limit_m[0]) {
        return 0;                         /* 알 수 없는 구역은 허용하지 않는다 */
    }
    return alt_m <= altitude_limit_m[zone];
}

/* ---- 다른 모듈(표시 장치) ---- */
static void show_limits_in_feet(void)
{
    int lim[3];
    size_t n = fence_copy_limits(lim, 3);
    for (size_t i = 0; i < n; ++i) {
        lim[i] = lim[i] * 328 / 100;      /* 복사본만 바뀐다 */
        printf("zone %u: %d ft\n", (unsigned)i, lim[i]);
    }
}

int main(void)
{
    show_limits_in_feet();
    printf("zone 0 allows 350 m? %s\n", fence_allows(0, 350) ? "YES (limit table corrupted)" : "no");
    return 0;
}

    호출자 버퍼에 복사해 주는 함수로 바꿔 내부 표의 주소가 모듈 밖으로 나가지 않게 하고, 구역 번호도 범위를 검사해 알 수 없는 구역은 허용하지 않는다. const 포인터를 돌려주는 방법도 있지만 형 변환으로 const를 벗길 수 있으므로 안전 관련 표는 복사가 낫다.

    검증: 실행 결과 — 나쁜 예에서 YES (limit table corrupted) 검출, 좋은 예에서 미검출·zone 0 allows 350 m? no 출력 확인 · 참고: MITRE CWE-495 설명·완화책(Potential Mitigations) 참고, 이 가이드가 새로 작성

    C++

    나쁜 예

    #include <array>
#include <cstdio>

// 무선 통신 제어기: 허용 모드 코드표는 private 멤버다
class RadioController {
    std::array<int, 3> allowedModes_{1, 2, 5};
public:
    std::array<int, 3> &AllowedModes() { return allowedModes_; }   // 내부 배열의 참조를 내준다
    bool Accepts(int mode) const {
        for (int m : allowedModes_) {
            if (m == mode) return true;
        }
        return false;
    }
};

int main() {
    RadioController radio;
    auto &modes = radio.AllowedModes();
    modes[2] = 4;                      // 화면용 정렬·편집이 그대로 내부 상태를 바꾼다
    std::printf("mode 5 accepted: %s\n", radio.Accepts(5) ? "yes" : "NO (private table changed from outside)");
    std::printf("mode 4 accepted: %s\n", radio.Accepts(4) ? "YES (private table changed from outside)" : "no");
    return 0;
}

    private 멤버 배열의 비-const 참조를 반환한다. 받은 쪽이 요소를 고치면 제어기의 허용 모드표가 바뀌어, 허용되지 않은 모드를 받아들인다.

    좋은 예

    #include <array>
#include <cstdio>

// 무선 통신 제어기
class RadioController {
    std::array<int, 3> allowedModes_{1, 2, 5};
public:
    std::array<int, 3> AllowedModes() const { return allowedModes_; }  // 값(복사본)으로 돌려준다
    // 복사 비용이 문제면 const 참조: const std::array<int, 3> &AllowedModesView() const
    bool Accepts(int mode) const {
        for (int m : allowedModes_) {
            if (m == mode) return true;
        }
        return false;
    }
};

int main() {
    RadioController radio;
    auto modes = radio.AllowedModes();
    modes[2] = 4;                      // 복사본만 바뀐다
    std::printf("mode 5 accepted: %s\n", radio.Accepts(5) ? "yes" : "NO (private table changed from outside)");
    std::printf("mode 4 accepted: %s\n", radio.Accepts(4) ? "YES (private table changed from outside)" : "no");
    return 0;
}

    값(복사본)으로 돌려주도록 바꾼다. 복사 비용이 부담되면 const 참조를 돌려주되, 비-const 참조·포인터는 내주지 않는다.

    검증: 실행 결과 — 나쁜 예에서 (private table changed from outside) 검출, 좋은 예에서 미검출·mode 4 accepted: no 출력 확인 · 참고: MITRE CWE-495 Demonstrative Example 2(private 멤버의 비-const 참조 반환) 참고, 이 가이드가 새로 작성

    C#

    나쁜 예

    // 무인기 지상통제: 승인된 데이터링크 주파수 채널표
var plan = new LinkPlan();
int[] shown = plan.ApprovedChannels;
shown[0] = 99;                                   // 외부 코드가 받은 배열을 고친다
Console.WriteLine($"channel 99 approved: {(plan.IsApproved(99) ? "YES (private array modified)" : "no")}");

public sealed class LinkPlan
{
    private readonly int[] _approvedChannels = [12, 17, 23];

    public int[] ApprovedChannels => _approvedChannels;   // CA1819: 속성이 내부 배열을 그대로 반환

    public bool IsApproved(int channel) => Array.IndexOf(_approvedChannels, channel) >= 0;
}

    public 속성이 private 배열을 그대로 반환한다. 받은 쪽이 요소를 바꾸면 승인 채널표가 바뀐다. .NET 분석기가 CA1819(속성은 배열을 반환하면 안 됨)로 알려 준다.

    좋은 예

    // 무인기 지상통제: 승인된 데이터링크 주파수 채널표
var plan = new LinkPlan();
int[] shown = plan.CopyApprovedChannels();       // 필요하면 복사본을 받는다
shown[0] = 99;                                   // 복사본만 바뀐다
Console.WriteLine($"channels: {string.Join(",", plan.ApprovedChannels)}");
Console.WriteLine($"channel 99 approved: {(plan.IsApproved(99) ? "YES (private array modified)" : "no")}");

public sealed class LinkPlan
{
    private readonly int[] _approvedChannels = [12, 17, 23];

    // 읽기 전용 뷰: 호출자는 요소를 바꿀 수 없다
    public IReadOnlyList<int> ApprovedChannels => Array.AsReadOnly(_approvedChannels);

    public int[] CopyApprovedChannels() => (int[])_approvedChannels.Clone();

    public bool IsApproved(int channel) => Array.IndexOf(_approvedChannels, channel) >= 0;
}

    속성은 Array.AsReadOnly()로 만든 읽기 전용 뷰(IReadOnlyList<int>)를 내주고, 배열이 꼭 필요하면 복사본을 돌려주는 메서드를 따로 둔다.

    검증: .NET 컴파일러·분석기 — 나쁜 예에서 CA1819 검출, 좋은 예에서 미검출 · 참고: MITRE CWE-495 설명·완화책(Potential Mitigations) 참고, 이 가이드가 새로 작성

    Java

    나쁜 예

    import java.util.stream.IntStream;

// 서보 제어: 기구 간섭 구역 중심 각도(도) 목록, 앞뒤 5도까지 구동 금지
final class ServoControl {
    private final int[] blockedAngles = {0, 90, 180};

    public int[] getBlockedAngles() {
        return blockedAngles;                    // private 배열의 참조를 그대로 반환
    }

    public boolean mayMoveTo(int angle) {
        return IntStream.of(blockedAngles).allMatch(a -> Math.abs(a - angle) > 5);
    }
}

public class Example {
    public static void main(String[] args) {
        ServoControl servo = new ServoControl();
        // 외부 화면 코드: 화면 기준(45도 회전)으로 바꾸려고 받은 배열을 고친다
        int[] screen = servo.getBlockedAngles();
        for (int i = 0; i < screen.length; i++) {
            screen[i] = (screen[i] + 45) % 360;
        }
        String verdict = servo.mayMoveTo(92) ? "ALLOWED (private array modified)" : "blocked";
        System.out.println("move to 92 deg: " + verdict);
    }
}

    private 배열 필드의 참조를 getter가 그대로 반환한다. final은 참조만 고정할 뿐 요소 변경을 막지 못하므로, 화면 코드가 표시용으로 값을 바꾸자 구동 금지 구역이 옮겨져 92도 구동이 허용된다.

    좋은 예

    import java.util.List;
import java.util.stream.IntStream;

// 서보 제어: 기구 간섭 구역 중심 각도(도) 목록, 앞뒤 5도까지 구동 금지
final class ServoControl {
    private final int[] blockedAngles = {0, 90, 180};

    public int[] getBlockedAngles() {
        return blockedAngles.clone();            // 복사본을 반환
    }

    public List<Integer> blockedAngleList() {    // 또는 수정할 수 없는 목록으로
        return IntStream.of(blockedAngles).boxed().toList();
    }

    public boolean mayMoveTo(int angle) {
        return IntStream.of(blockedAngles).allMatch(a -> Math.abs(a - angle) > 5);
    }
}

public class Example {
    public static void main(String[] args) {
        ServoControl servo = new ServoControl();
        int[] screen = servo.getBlockedAngles();
        for (int i = 0; i < screen.length; i++) {
            screen[i] = (screen[i] + 45) % 360;   // 복사본만 바뀐다
        }
        String verdict = servo.mayMoveTo(92) ? "ALLOWED (private array modified)" : "blocked";
        System.out.println("move to 92 deg: " + verdict + ", list=" + servo.blockedAngleList());
    }
}

    clone()으로 복사본을 반환하거나, 수정할 수 없는 목록(Stream.toList()·List.copyOf())으로 내준다. SpotBugs를 쓰면 EI_EXPOSE_REP로도 찾을 수 있다.

    검증: 실행 결과 — 나쁜 예에서 ALLOWED (private array modified) 검출, 좋은 예에서 미검출·move to 92 deg: blocked 출력 확인 · 참고: MITRE CWE-495 Demonstrative Example 1(public 메서드가 private 배열의 참조 반환) 참고, 이 가이드가 새로 작성 / KISA·행정안전부 「Java 시큐어코딩 가이드」(3판) 캡슐화 6-4 'Public 메소드부터 반환된 private 배열'(인쇄 277쪽) 참고

    Python

    나쁜 예

    class RadioPolicy:
    """무선 허용 모드 표를 감춰 두고 화면에 보여 줄 때만 꺼내 준다."""

    def __init__(self):
        self._allowed_modes = [1, 2, 4]           # 밑줄은 '내부용'이라는 약속일 뿐

    def allowed_modes(self):
        return self._allowed_modes                # 내부 리스트를 그대로 돌려준다


policy = RadioPolicy()
shown = policy.allowed_modes()                    # 화면 모듈이 받은 리스트
shown.append(3)                                   # 화면 정렬·편집 코드가 리스트를 바꾼다
print("mode 3", "ALLOWED (internal table modified)" if 3 in policy.allowed_modes() else "denied")

    Python에는 private 접근 제한이 없고 밑줄(_)은 관례다. 문제는 접근자가 내부의 바꿀 수 있는 리스트를 그대로 돌려주는 것이다. 받은 쪽이 리스트를 바꾸면 객체 안의 안전 표가 함께 바뀌어, 허용하지 않은 모드 3이 허용된다.

    좋은 예

    class RadioPolicy:
    """무선 허용 모드 표를 감춰 두고 화면에 보여 줄 때만 꺼내 준다."""

    def __init__(self):
        self._allowed_modes = (1, 2, 4)           # 바꿀 수 없는 튜플로 보관

    def allowed_modes(self):
        return list(self._allowed_modes)          # 호출자에게는 사본을 준다


policy = RadioPolicy()
shown = policy.allowed_modes()
shown.append(3)                                   # 사본만 바뀐다
print("mode 3", "ALLOWED (internal table modified)" if 3 in policy.allowed_modes() else "denied")

    안전에 직결되는 표는 튜플·frozenset처럼 바꿀 수 없는 형으로 보관하고, 밖으로는 사본(list(…))이나 읽기 전용 뷰(types.MappingProxyType)를 준다. 리스트 안에 바꿀 수 있는 객체가 들어 있으면 copy.deepcopy로 사본을 만들거나 원소도 바꿀 수 없는 형(frozen dataclass)으로 둔다.

    검증: 실행 결과 — 나쁜 예에서 ALLOWED (internal table modified) 검출, 좋은 예에서 미검출·mode 3 denied 출력 확인 · 참고: MITRE CWE-495 Demonstrative Example 1(public 메서드가 private 배열 참조를 반환) 참고, 이 가이드가 새로 작성 / 과학기술정보통신부·한국인터넷진흥원 「Python 시큐어코딩 가이드」(2023. 12.) 캡슐화 6-3 'Public 메소드로부터 반환된 Private 배열'(인쇄 151쪽) 참고

    탐지 방법(Detection Methods)¶

    방법 요지 효과성
    자동 정적 분석 흔히 SAST(Static Application Security Testing)라 부르는 자동 정적 분석(static analysis)은 소스코드(또는 바이너리·컴파일된 코드)를 실행하지 않고 분석해 이 약점의 일부 사례를 찾을 수 있으며, 대개 데이터 흐름·제어 흐름 모델을 만든 뒤 입력 출처('source')와 외부 구성요소나 운영체제 같은 하위 계층과 상호작용하는 목적지('sink')를 잇는 잠재적 취약 패턴을 찾는다.
    원문

    Automated static analysis, commonly referred to as Static Application Security Testing (SAST), can find some instances of this weakness by analyzing source code (or binary/compiled code) without having to execute it. Typically, this is done by building a model of data flow and control flow, then searching for potentially-vulnerable patterns that connect "sources" (origins of input) with "sinks" (destinations where the data interacts with external components, a lower layer such as the OS, etc.)

    점검 착안점 활동 근거
    (Java·C#) public 메서드·속성·getter가 private 배열·컬렉션 필드(final 배열 포함)의 참조를 그대로 돌려주는 곳을 찾고, 복사본(clone, Arrays.copyOf, ToArray)이나 읽기 전용 뷰를 돌려주는지 확인한다. final은 참조만 고정하고 요소 변경은 막지 못한다. I-09 [CWE] CWE-495 완화책(Implementation: 멤버 데이터 복제) · [예시] CWE-495 Java 예시(final 배열 요소 변경)
    (C·C++) C++에서는 private 멤버 배열·컨테이너의 비-const 참조나 포인터를 돌려주는 멤버 함수를, C에서는 파일 범위 static 표의 쓰기 가능한 주소를 돌려주는 함수를 찾는다. I-09 [예시] CWE-495 C·C++ 예시(static 배열 주소·비-const 참조 반환)
    getter로 받은 배열의 요소를 바꾼 뒤 같은 객체를 다시 조회해 내부 판정(제한값, 허용표)이 바뀌는지 확인하는 단위시험을 만든다. I-10 [예시] CWE-495 예시 검증(외부 수정 뒤 내부 표 변경 확인)
    (C#) CA1819(속성은 배열을 반환하면 안 됨) 분석기 경고를 켜서 확인한다. I-08 [예시] CWE-495 C# 예시 검증(CA1819)
