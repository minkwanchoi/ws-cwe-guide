    Use of Externally-Controlled Format String

    항목 내용
    추상화 수준 기본(Base)
    상태 초안(Draft)
    소속 「보안약점 점검 목록」(44개) · 언어 뷰 C·C++(CWE-658·659)
    가이드 적용성 해당
    적용 플랫폼 언어: 언어 무관, C, C++, Perl, Python
    원문 MITRE CWE-134 (CWE 5.0)

    한 줄 요약

    포맷 스트링을 인자로 받는 함수에 외부에서 온 포맷 스트링을 넘겨 생기는 약점이다.

    → 나쁜 예·좋은 예

    설명(Description)¶

    제품이 포맷 스트링을 인자로 받는 함수를 사용하는데, 그 포맷 스트링이 외부 출처에서 온다.

    원문(Description)

    The product uses a function that accepts a format string as an argument, but the format string originates from an external source.

    발생 단계(Modes Of Introduction)¶

    CWE 단계(Phase) 수명주기 단계(가이드 대응) 설명
    구현(Implementation) 구현 프로그래머가 포맷 스트링을 외부에서 제어하도록 의도하는 일은 드물며, 이 약점은 상수 포맷 스트링을 빠뜨린 채 로그 메시지를 만드는 코드에서 자주 생긴다.
    구현(Implementation) 구현 지역화·국제화처럼 언어별 메시지 저장소가 공격 경로가 될 수 있는 경우가 있지만, 그 저장소를 공격자가 제어하면 메시지 길이·형식·내용도 바꿀 수 있으므로 이때 포맷 스트링 문제는 결과적(resultant) 약점이다.

    영향(Common Consequences)¶

    영역 영향 설명
    기밀성 메모리 읽기 포맷 스트링 문제는 정보 노출을 일으키며, 이로 인해 프로그램 공격이 크게 쉬워질 수 있다.
    무결성 / 기밀성 / 가용성 메모리 수정 / 허가되지 않은 코드·명령 실행 포맷 스트링 문제는 임의 코드 실행, 버퍼 오버플로, 서비스 거부, 잘못된 데이터 표현으로 이어질 수 있다.

    완화책(Potential Mitigations)¶

    원문 완화책 3건(수명주기 단계로 묶은 규칙은 색인에 있다).

    요구사항 분석 (본문 제3장)¶

    CWE 단계(Phase) 전략 요지
    요구사항(Requirements) — 이 약점이 생기지 않는 언어를 선택한다.
    원문

    Choose a language that is not subject to this flaw.

    설계 (본문 제4장)¶

    원문 완화책 없음. 이 단계의 기준선 활동: D-02 위협 모델링·신뢰 경계 정의, D-09 설계 보안성 검토

    구현 (본문 제5장)¶

    CWE 단계(Phase) 전략 요지
    구현(Implementation) — 모든 포맷 스트링 함수에는 사용자가 제어할 수 없는 정적 문자열을 넘기고, 인자 개수도 항상 맞게 넘긴다. 가능하다면 포맷 스트링에서 %n 연산자를 지원하지 않는 함수를 쓴다 [REF-116] [REF-117].
    원문

    Ensure that all format string functions are passed a static string which cannot be controlled by the user, and that the proper number of arguments are always sent to that function as well. If at all possible, use functions that do not support the %n operator in format strings. [REF-116] [REF-117]
    빌드·컴파일(Build and Compilation) — 컴파일러와 링커가 잘못된 사용을 탐지할 수 있으므로 높은 경고 수준으로 실행한다.
    원문

    Run compilers and linkers with high warning levels, since they may detect incorrect usage.

    통합 및 시험 (본문 제6장)¶

    원문 완화책 없음

    유지보수 (본문 제7장)¶

    원문 완화책 없음

    예시(나쁜 예·좋은 예)¶

    아래 코드는 이 가이드가 다음 상황을 가정해 새로 작성한 것이다. 데이터링크로 받은 상태 문구나 정비사·운용자가 입력한 메모를 로그·기록 한 줄로 만든다. 외부 문자열을 형식 문자열(포맷 스트링)로 그대로 쓰면 C·C++에서는 %x·%p·%n으로 메모리를 읽거나 쓸 수 있고, Java·C#에서는 '%'·'{' 해석 실패 예외로 처리가 멈추거나 의도하지 않은 인자가 노출된다. Python에서는 str.format이 넘긴 객체의 속성·색인을 따라가 객체 안의 내부 값이 드러난다. 언어마다 분석기·새니타이저·실행 결과로 나쁜 예는 잡히고 좋은 예는 잡히지 않음을 확인했다. 좋은 예는 그 약점 하나를 막는 최소 예이며 그대로 운용 코드가 되는 것은 아니다. 언어 상자를 눌러 펼친다.

    C

    나쁜 예

    #include <stdio.h>

typedef struct { int id; const char *status; } Frame;

/* 데이터링크로 받은 상태 문구를 디버그 UART 로그(여기서는 stderr)에 남긴다 */
static void log_frame(const Frame *fr)
{
    fprintf(stderr, "frame %d: ", fr->id);
    fprintf(stderr, fr->status);             /* 받은 문구를 포맷 스트링으로 사용 */
    fputc('\n', stderr);
}

int main(void)
{
    /* 2번 프레임: %x는 스택 내용을 드러내고 %n이면 메모리에 쓴다 */
    const Frame rx[] = {{1, "LINK OK"}, {2, "%x %x %x %x"}};
    for (size_t i = 0; i < sizeof rx / sizeof rx[0]; ++i) {
        log_frame(&rx[i]);
    }
    return 0;
}

    받은 문자열을 fprintf()의 포맷 인자로 넘긴다. '%x'는 스택 내용을 드러내고 '%n'은 메모리에 쓴다. 컴파일러 -Wformat-security 경고로 잡힌다.

    좋은 예

    #include <stdarg.h>
#include <stdio.h>

typedef struct { int id; const char *status; } Frame;

/* format 속성: 호출부의 포맷 스트링과 인자를 컴파일러가 검사한다 */
static void uart_logf(const char *fmt, ...) __attribute__((format(printf, 1, 2)));

static void uart_logf(const char *fmt, ...)
{
    va_list ap;
    va_start(ap, fmt);
    vfprintf(stderr, fmt, ap);
    va_end(ap);
}

static void log_frame(const Frame *fr)
{
    uart_logf("frame %d: %s\n", fr->id, fr->status);   /* 포맷은 상수, 문구는 인자 */
}

int main(void)
{
    const Frame rx[] = {{1, "LINK OK"}, {2, "%x %x %x %x"}};
    for (size_t i = 0; i < sizeof rx / sizeof rx[0]; ++i) {
        log_frame(&rx[i]);
    }
    return 0;
}

    포맷은 항상 상수 문자열로 두고 받은 문구는 %s 인자로만 넘긴다. 가변 인자 로그 함수에는 format(printf, 1, 2) 속성을 달아 호출부를 컴파일러가 검사하게 하고, -Wformat=2 -Wformat-security 경고를 오류로 다룬다(I-02).

    검증: 컴파일러 경고 — 나쁜 예에서 -Wformat-(security|nonliteral) 검출, 좋은 예에서 미검출 · 참고: MITRE CWE-134 Demonstrative Example 1(입력 문자열을 printf의 포맷으로 사용) 참고, 이 가이드가 새로 작성

    C++

    나쁜 예

    #include <cstdio>
#include <string>

// 정비 단말이 보낸 작업 메모를 고장 기록 한 줄로 만든다
std::string makeFaultLine(const std::string &note) {
    char line[96];
    std::snprintf(line, sizeof line, note.c_str());     // 메모를 포맷 스트링으로 사용
    return line;
}

int main() {
    std::puts(makeFaultLine("hydraulic pump B replaced").c_str());
    std::puts(makeFaultLine("%p %p %p %s").c_str());    // 메모리 내용 노출·비정상 종료 가능
}

    std::snprintf의 포맷 자리에 메모를 넘긴다. '%p %s' 같은 메모는 메모리 내용을 드러내거나 잘못된 주소를 읽어 비정상 종료를 일으킨다.

    좋은 예

    #include <cstdio>
#include <string>

std::string makeFaultLine(const std::string &note) {
    char line[96];
    std::snprintf(line, sizeof line, "NOTE: %s", note.c_str());   // 포맷은 고정, 메모는 인자
    return line;
}

int main() {
    std::puts(makeFaultLine("hydraulic pump B replaced").c_str());
    std::puts(makeFaultLine("%p %p %p %s").c_str());
}

    포맷 문자열을 상수("NOTE: %s")로 고정하고 메모는 인자로 넘긴다(I-02). C++20 이후라면 std::format처럼 컴파일 시간에 포맷을 검사하는 API를 쓴다.

    검증: 컴파일러 경고 — 나쁜 예에서 -Wformat-(security|nonliteral) 검출, 좋은 예에서 미검출 · 참고: MITRE CWE-134 Demonstrative Example 2(외부 문자열을 snprintf의 포맷으로 사용) 참고, 이 가이드가 새로 작성

    C#

    나쁜 예

    using System.Globalization;

// 정비 기록: 장비 번호와 정비사가 입력한 메모로 기록 한 줄을 만든다
Console.WriteLine(Record("SN-1042", "seal replaced"));
Console.WriteLine(Record("SN-1042", "torque {spec} checked"));   // '{' 해석 실패 → 예외

static string Record(string serial, string memo)
{
    // 메모를 형식 문자열에 이어 붙여 string.Format에 넘긴다
    return string.Format(CultureInfo.InvariantCulture, "{0} | " + memo, serial);
}

    메모를 string.Format의 형식 문자열에 이어 붙인다. 메모의 '{spec}'를 형식 항목으로 해석하다 FormatException이 나 기록이 남지 않고, '{0}' 같은 메모는 다른 인자를 드러낼 수 있다.

    좋은 예

    using System.Globalization;

Console.WriteLine(Record("SN-1042", "seal replaced"));
Console.WriteLine(Record("SN-1042", "torque {spec} checked"));

static string Record(string serial, string memo)
{
    // 형식 문자열은 상수로 두고, 메모는 인자로만 넘긴다
    return string.Format(CultureInfo.InvariantCulture, "{0} | {1}", serial, memo);
}

    형식 문자열을 상수("{0} | {1}")로 두고 메모는 인자로만 넘긴다. 보간 문자열($"...")도 같은 효과가 있다.

    검증: 실행 결과 — 나쁜 예에서 FormatException 검출, 좋은 예에서 미검출·torque {spec} checked 출력 확인 · 참고: MITRE CWE-134 Demonstrative Example 1(입력 문자열을 포맷으로 사용, 원문은 C) 참고, 이 가이드가 새로 작성

    Java

    나쁜 예

    public class Example {
    // 운용자 콘솔: 센서 번호와 운용자가 입력한 메모를 경보 창 문구로 만든다
    static String alertLine(int sensorId, String operatorNote) {
        return String.format("[S%04d] " + operatorNote, sensorId);   // 메모가 포맷 스트링에 섞임
    }

    public static void main(String[] args) {
        System.out.println(alertLine(17, "temp rising"));
        System.out.println(alertLine(17, "fuel 35% left"));   // '%' 해석 실패 → 예외로 처리 중단
    }
}

    메모를 String.format의 포맷 문자열에 이어 붙인다. 메모리 손상은 없지만 '35% left'의 '%' 해석에 실패해 UnknownFormatConversionException으로 경보 처리가 멈추고, '%1$s'·'%n' 같은 메모는 출력 형식을 바꾸거나 다른 예외로 처리를 멈추게 한다.

    좋은 예

    public class Example {
    static String alertLine(int sensorId, String operatorNote) {
        return String.format("[S%04d] %s", sensorId, operatorNote);   // 포맷은 상수, 메모는 인자
    }

    public static void main(String[] args) {
        System.out.println(alertLine(17, "temp rising"));
        System.out.println(alertLine(17, "fuel 35% left"));
    }
}

    포맷 문자열은 상수로 두고 메모는 %s 인자로만 넘긴다.

    검증: 실행 결과 — 나쁜 예에서 UnknownFormatConversionException 검출, 좋은 예에서 미검출·[S0017] fuel 35% left 출력 확인 · 참고: MITRE CWE-134 Demonstrative Example 1(입력 문자열을 포맷으로 사용, 원문은 C) 참고, 이 가이드가 새로 작성

    Python

    나쁜 예

    class LinkConfig:
    def __init__(self, channel, psk):
        self.channel = channel
        self.psk = psk                          # 데이터링크 접속 비밀값(예시용 가짜 값)


class Record:
    def __init__(self, unit, result, link):
        self.unit = unit
        self.result = result
        self._link = link                       # 기록을 보낼 링크 설정(내부용)


# 정비 단말이 보낸 문구 틀로 정비 기록 한 줄을 만든다
def log_line(template, rec):
    return template.format(rec=rec)             # 외부 문자열을 서식 문자열로 사용


rec = Record("HYD-2", "OK", LinkConfig(4, "PSK-3E9A-77C1"))   # 예시용 가짜 값
print(log_line("{rec.unit} check {rec.result}", rec))
print(log_line("ch{rec._link.channel} {rec._link.psk}", rec))   # 속성을 따라가 내부 비밀값을 꺼낸다

    Python에는 C의 %n 같은 메모리 쓰기는 없지만, 외부 문자열을 str.format의 서식 문자열로 쓰면 '{rec._link.psk}'처럼 넘긴 객체의 속성·색인을 따라가 그 객체가 들고 있는 내부 값을 읽을 수 있다. 예시는 기록 문구 틀 하나로 링크 설정의 비밀값을 꺼낸다. 속성을 더 따라가면 모듈 전역 변수까지 닿을 수 있고, '{rec.unit:>999999999}' 같은 폭 지정으로 메모리를 크게 쓰게 할 수도 있다. f-문자열에 외부 값을 넣는 것은 값 치환이라 이 문제가 없고, 서식 문자열 자체를 외부에서 받을 때 생긴다.

    좋은 예

    from string import Template


class LinkConfig:
    def __init__(self, channel, psk):
        self.channel = channel
        self.psk = psk


class Record:
    def __init__(self, unit, result, link):
        self.unit = unit
        self.result = result
        self._link = link


def log_line(template, rec):
    # string.Template는 $이름 치환만 하고 속성·색인을 따라가지 않는다. 넘기는 값도 정한 필드뿐
    return Template(template).safe_substitute(unit=rec.unit, result=rec.result)


rec = Record("HYD-2", "OK", LinkConfig(4, "PSK-3E9A-77C1"))   # 예시용 가짜 값
print(log_line("$unit check $result", rec))
print(log_line("ch{rec._link.channel} {rec._link.psk}", rec))

    서식 문자열은 프로그램이 정하고 외부 문구는 값으로만 넣는다. 틀을 외부에서 받아야 하면 string.Template로 $이름 치환만 허용하고 넘기는 값도 정한 필드로 제한한다(I-03). 예시에서 공격 문구는 치환되지 않고 글자 그대로 남는다.

    MITRE 원문 예시(Demonstrative Examples, 영문 3건)

    Example 1. The following program prints a string provided as an argument.

    Bad / C

    #include <stdio.h>

void printWrapper(char *string) {

  printf(string);

}

int main(int argc, char **argv) {

  char buf[5012];
  memcpy(buf, argv[1], 5012);
  printWrapper(argv[1]);
  return (0);

}

    The example is exploitable, because of the call to printf() in the printWrapper() function. Note: The stack buffer was added to make exploitation more simple.

    Example 2. The following code copies a command line argument into a buffer using snprintf().

    Bad / C

    int main(int argc, char **argv){
  char buf[128];
  ...
  snprintf(buf,128,argv[1]);
}

    This code allows an attacker to view the contents of the stack and write to the stack using a command line argument containing a sequence of formatting directives. The attacker can read from the stack by providing more formatting directives, such as %x, than the function takes as arguments to be formatted. (In this example, the function takes no arguments to be formatted.) By using the %n formatting directive, the attacker can write to the stack, causing snprintf() to write the number of bytes output thus far to the specified argument (rather than reading a value from the argument, which is the intended behavior). A sophisticated version of this attack will use four staggered writes to completely control the value of a pointer on the stack.

    Example 3. Certain implementations make more advanced attacks even easier by providing format directives that control the location in memory to read from or write to. An example of these directives is shown in the following code, written for glibc:

    Bad / C

    printf("%d %d %1$d %1$d\n", 5, 9);

    This code produces the following output: 5 9 5 5 It is also possible to use half-writes (%hn) to accurately control arbitrary DWORDS in memory, which greatly reduces the complexity needed to execute an attack that would otherwise require four staggered writes, such as the one mentioned in a separate example.
