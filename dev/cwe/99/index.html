    Improper Control of Resource Identifiers

    항목 내용
    추상화 수준 분류(Class)

    적용 플랫폼 언어 무관
    원문 MITRE CWE-99 (CWE 5.0)

    한 줄 요약

    상위 구성요소에서 받은 입력을 제한하지 않거나 잘못 제한한 채 자원 식별자로 써서 의도한 통제 범위 밖 자원을 가리킬 수 있게 되는 약점이다.

    → 나쁜 예·좋은 예

    설명(Description)¶

    제품이 상위(upstream) 구성요소에서 입력을 받아, 의도한 통제 범위 밖에 있을 수 있는 자원의 식별자로 쓰기 전에 그 입력을 제한하지 않거나 잘못 제한하는 약점이다.

    원문(Description)

    The product receives input from an upstream component, but it does not restrict or incorrectly restricts the input before it is used as an identifier for a resource that may be outside the intended control sphere.

    발생 단계(Modes Of Introduction)¶

    CWE 단계(Phase) 수명주기 단계(가이드 대응) 설명
    아키텍처·설계(Architecture and Design) 설계 —
    구현(Implementation) 구현 자원 삽입 문제는 다음 두 조건을 모두 만족할 때 생긴다. (1) 공격자가 시스템 자원 접근에 쓰이는 식별자를 지정할 수 있다. 예를 들어 공격자가 열 파일 이름의 일부나 사용할 포트 번호를 지정할 수 있다. (2) 자원을 지정함으로써 공격자가 원래는 허용되지 않는 능력을 얻는다. 예를 들어 프로그램이 공격자에게 지정한 파일 덮어쓰기, 공격자가 통제하는 설정으로 실행, 민감한 정보를 제3자 서버로 전송하는 능력을 줄 수 있다. 이로써 공격자가 원래 보호되는 시스템 자원에 접근하거나 수정할 수 있다.
    구현(Implementation) 구현 실현(REALIZATION): 이 약점은 아키텍처 보안 전술을 구현하는 과정에서 생긴다.

    영향(Common Consequences)¶

    영역 영향 설명
    기밀성 / 무결성 애플리케이션 데이터 읽기 / 애플리케이션 데이터 수정 / 파일·디렉터리 읽기 / 파일·디렉터리 수정 공격자가 민감한 데이터나 시스템 자원에 접근하거나 수정할 수 있으며, 설정 파일과 민감한 정보가 담긴 파일을 포함한 보호된 파일·디렉터리에 접근할 수 있다.

    구현 (본문 제5장)¶

    CWE 단계(Phase) 전략 요지
    구현(Implementation) 입력값 검증 모든 입력을 악의적이라고 가정하고, 명세에 엄격히 맞는 입력만 받는 허용목록('accept known good') 방식으로 검증해 맞지 않는 입력은 거부하거나 맞게 변환한다. 검증할 때는 길이·유형·허용 값 전체 범위·누락/추가 입력·구문·관련 필드 간 일관성·업무 규칙을 모두 고려한다(예: 'boat'는 영숫자만 있어 구문상 유효하지만 'red'·'blue' 같은 색상만 받는 필드라면 유효하지 않다). 악의적이거나 잘못된 입력을 찾는 방식(거부목록)에만 의존하지 않는다. 이 방식은 특히 코드 환경이 바뀔 때 원치 않는 입력을 하나 이상 놓치기 쉬워 검증이 우회될 수 있다. 다만 그런 방식도 공격 탐지나 즉시 거부할 정도로 잘못된 입력을 가려내는 데는 쓸모가 있을 수 있다.
    원문

    Assume all input is malicious. Use an "accept known good" input validation strategy, i.e., use a list of acceptable inputs that strictly conform to specifications. Reject any input that does not strictly conform to specifications, or transform it into something that does.

    When performing input validation, consider all potentially relevant properties, including length, type of input, the full range of acceptable values, missing or extra inputs, syntax, consistency across related fields, and conformance to business rules. As an example of business rule logic, "boat" may be syntactically valid because it only contains alphanumeric characters, but it is not valid if the input is only expected to contain colors such as "red" or "blue."

    Do not rely exclusively on looking for malicious or malformed inputs. This is likely to miss at least one undesirable input, especially if the code's environment changes. This can give attackers enough room to bypass the intended validation. However, it can be useful for detecting potential attacks or determining which inputs are so malformed that they should be rejected outright.

    예시(나쁜 예·좋은 예)¶

    아래 코드는 이 가이드가 다음 상황을 가정해 새로 작성한 것이다. 정비 명령·데이터링크 메시지·원격 명령에 담긴 값으로 쓸 자원(출력 채널 파일, 녹화 대상, 지울 보고서, 시험 판정 기록 파일)을 정한다. 공격자는 그 값에 다른 기능이 쓰는 자원 이름(자이로 보정값, 장비 모드 표, 위성 궤도 자료, 연료 맵, 항법 설정)을 넣어 그 자원을 덮어쓰거나 지우게 한다. 언어마다 분석기·새니타이저·실행 결과로 나쁜 예는 잡히고 좋은 예는 잡히지 않음을 확인했다. 좋은 예는 그 약점 하나를 막는 최소 예이며 그대로 운용 코드가 되는 것은 아니다. 언어 상자를 눌러 펼친다.

    C

    나쁜 예

    #include <stdio.h>

/* 정비 명령 메시지: 기록할 출력 채널 이름과 내용 */
typedef struct { char channel[32]; char text[32]; } MaintCmd;

static void show(const char *path)
{
    char buf[64] = "";
    FILE *f = fopen(path, "r");
    if (f != NULL) { if (fgets(buf, sizeof buf, f) == NULL) buf[0] = '\0'; fclose(f); }
    printf("%s: %s\n", path, buf);
}

static void handle(const MaintCmd *m)
{
    FILE *f = fopen(m->channel, "w");      /* 메시지가 지정한 자원 이름을 그대로 연다 */
    if (f == NULL) { puts("open failed"); return; }
    fputs(m->text, f);
    fclose(f);
}

int main(void)
{
    FILE *c = fopen("gyro.cal", "w");      /* 다른 기능이 쓰는 자이로 보정값 */
    if (c != NULL) { fputs("BIAS 0.0031", c); fclose(c); }
    MaintCmd ok  = {"chan1.out", "RESET COUNTERS"};
    MaintCmd bad = {"gyro.cal",  "BIAS 9.9"};    /* 채널 대신 보정 파일 이름 */
    handle(&ok);
    handle(&bad);
    show("gyro.cal");
    return 0;
}

    메시지의 채널 이름 문자열을 그대로 fopen()에 넘긴다. 채널 대신 'gyro.cal'을 보내면 자이로 보정값이 덮어써진다.

    좋은 예

    #include <stdio.h>

/* 메시지는 채널 번호만 담고, 실제 자원 이름은 코드의 고정 표에서 고른다 */
typedef struct { unsigned channel; char text[32]; } MaintCmd;

static const char *const CHANNELS[] = {"chan0.out", "chan1.out", "chan2.out"};

static void show(const char *path)
{
    char buf[64] = "";
    FILE *f = fopen(path, "r");
    if (f != NULL) { if (fgets(buf, sizeof buf, f) == NULL) buf[0] = '\0'; fclose(f); }
    printf("%s: %s\n", path, buf);
}

static void handle(const MaintCmd *m)
{
    if (m->channel >= sizeof CHANNELS / sizeof CHANNELS[0]) {
        printf("rejected: channel %u not allowed\n", m->channel);
        return;
    }
    FILE *f = fopen(CHANNELS[m->channel], "w");
    if (f == NULL) { puts("open failed"); return; }
    fputs(m->text, f);
    fclose(f);
}

int main(void)
{
    FILE *c = fopen("gyro.cal", "w");
    if (c != NULL) { fputs("BIAS 0.0031", c); fclose(c); }
    MaintCmd ok  = {1, "RESET COUNTERS"};
    MaintCmd bad = {9, "BIAS 9.9"};
    handle(&ok);
    handle(&bad);
    show("gyro.cal");
    return 0;
}

    메시지는 채널 번호만 담고, 범위를 검사한 뒤 코드의 고정 표에서 자원 이름을 고른다(I-04).

    검증: 실행 결과 — 나쁜 예에서 gyro.cal: BIAS 9.9 검출, 좋은 예에서 미검출·rejected: channel 9 not allowed 출력 확인 · 참고: MITRE CWE-99 Demonstrative Example 1(외부 입력으로 파일 이름을 정함) 참고, 이 가이드가 새로 작성 / KISA·행정안전부 「C 시큐어코딩 가이드」(3판) 입력데이터 검증 및 표현 1-2 '자원 삽입'(인쇄 8쪽) 참고

    C++

    나쁜 예

    #include <fstream>
#include <iostream>
#include <string>

// 데이터링크 메시지가 녹화 대상 이름을 지정하면 그 이름의 파일에 녹화 자료를 쓴다
void startRecording(const std::string &target, const std::string &frame) {
    std::ofstream out(target, std::ios::trunc);        // 외부 값이 곧 자원 식별자
    out << frame;
}

std::string head(const std::string &p) {
    std::ifstream in(p);
    std::string s;
    std::getline(in, s);
    return s;
}

int main() {
    std::ofstream("modes.tbl") << "UNIT1 IDLE";    // 장비 모드 표
    startRecording("rec-01.raw", "frame-0001");
    startRecording("modes.tbl", "frame-0002");        // 녹화 대상 대신 장비 모드 표
    std::cout << "modes.tbl: " << head("modes.tbl") << '\n';
}

    메시지의 녹화 대상 이름을 그대로 std::ofstream으로 열어 쓴다. 장비 모드 표 이름이 오면 그 파일이 녹화 자료로 바뀐다.

    좋은 예

    #include <array>
#include <fstream>
#include <iostream>
#include <optional>
#include <string>

// 메시지의 녹화 슬롯 번호(0~3)를 고정 자원 이름으로 바꾼다
std::optional<std::string> slotFile(int slot) {
    static const std::array<const char *, 4> files = {"rec-00.raw", "rec-01.raw", "rec-02.raw", "rec-03.raw"};
    if (slot < 0 || slot >= static_cast<int>(files.size())) {
        return std::nullopt;
    }
    return files[static_cast<std::size_t>(slot)];
}

void startRecording(int slot, const std::string &frame) {
    const auto target = slotFile(slot);
    if (!target) {
        std::cout << "rejected: slot " << slot << '\n';
        return;
    }
    std::ofstream out(*target, std::ios::trunc);
    out << frame;
}

std::string head(const std::string &p) {
    std::ifstream in(p);
    std::string s;
    std::getline(in, s);
    return s;
}

int main() {
    std::ofstream("modes.tbl") << "UNIT1 IDLE";
    startRecording(1, "frame-0001");
    startRecording(7, "frame-0002");
    std::cout << "modes.tbl: " << head("modes.tbl") << '\n';
}

    녹화 슬롯 번호(0~3)만 받고 std::optional로 범위 밖을 표현해, 고정 표에 있는 자원만 연다(I-04).

    검증: 실행 결과 — 나쁜 예에서 modes.tbl: frame 검출, 좋은 예에서 미검출·rejected: slot 7 출력 확인 · 참고: MITRE CWE-99 Demonstrative Example 2(외부 값으로 파일을 엶) 참고, 이 가이드가 새로 작성

    C#

    나쁜 예

    // 정비 명령 메시지가 지정한 출력 대상 이름으로 자료를 내보낸다
File.WriteAllText("fuel.map", "MAP-REV 12");            // 연료 제어가 쓰는 맵 파일

Export(new MaintCommand("chan1.out", "TEMP LOG"));
Export(new MaintCommand("fuel.map", "MAP-REV 00"));     // 출력 대상 대신 연료 맵 이름
Console.WriteLine("fuel.map: " + File.ReadAllText("fuel.map"));

static void Export(MaintCommand cmd)
{
    File.WriteAllText(cmd.Target, cmd.Payload);         // 외부 값을 자원 이름으로 바로 사용
}

record MaintCommand(string Target, string Payload);

    명령 메시지의 Target 값을 그대로 File.WriteAllText의 파일 이름으로 쓴다. 'fuel.map'을 보내면 연료 제어가 쓰는 맵이 덮어써진다.

    좋은 예

    File.WriteAllText("fuel.map", "MAP-REV 12");

Export(new MaintCommand("ch1", "TEMP LOG"));
Export(new MaintCommand("fuel.map", "MAP-REV 00"));
Console.WriteLine("fuel.map: " + File.ReadAllText("fuel.map"));

static void Export(MaintCommand cmd)
{
    // 메시지의 값은 허용된 채널 키로만 쓰고, 실제 파일 이름은 고정 표에서 가져온다
    if (!Channels.Files.TryGetValue(cmd.Target, out string? file))
    {
        Console.WriteLine("rejected: unknown channel");
        return;
    }
    File.WriteAllText(file, cmd.Payload);
}

record MaintCommand(string Target, string Payload);

static class Channels
{

    나쁜 예

    import java.io.IOException;
import java.nio.file.Files;
import java.nio.file.Path;

public class Example {
    // 지상 통제 소프트웨어: 원격 명령이 지정한 보고서 이름의 파일을 지운다(보고서 정리)
    static void purgeReport(String reportId) throws IOException {
        Path target = Path.of(reportId);              // 외부 값을 자원 이름으로 바로 사용
        boolean removed = Files.deleteIfExists(target);
        System.out.println("purge " + reportId + ": " + removed);
    }

    public static void main(String[] args) throws IOException {
        Files.writeString(Path.of("rpt-0412.txt"), "daily report");
        Files.writeString(Path.of("ephemeris.dat"), "GPS EPHEMERIS");   // 다른 기능의 자료
        purgeReport("rpt-0412.txt");
        purgeReport("ephemeris.dat");
        System.out.println("ephemeris present: " + Files.exists(Path.of("ephemeris.dat")));
    }
}

    원격 명령의 보고서 이름을 그대로 Path로 만들어 지운다. 다른 기능이 쓰는 위성 궤도 자료 이름을 보내면 그 파일이 삭제된다.

    좋은 예

    import java.io.IOException;
import java.nio.file.Files;
import java.nio.file.Path;
import java.util.regex.Pattern;

public class Example {
    // 원격 명령은 보고서 번호(4자리)만 보내고, 파일 이름 규칙은 코드가 정한다
    static final Pattern REPORT_NO = Pattern.compile("[0-9]{4}");

    static void purgeReport(String reportNo) throws IOException {
        if (!REPORT_NO.matcher(reportNo).matches()) {
            System.out.println("rejected: invalid report number");
            return;
        }
        Path target = Path.of("rpt-" + reportNo + ".txt");
        boolean removed = Files.deleteIfExists(target);
        System.out.println("purge " + target + ": " + removed);
    }

    public static void main(String[] args) throws IOException {
        Files.writeString(Path.of("rpt-0412.txt"), "daily report");
        Files.writeString(Path.of("ephemeris.dat"), "GPS EPHEMERIS");
        purgeReport("0412");
        purgeReport("ephemeris.dat");
        System.out.println("ephemeris present: " + Files.exists(Path.of("ephemeris.dat")));
    }
}

    원격 명령은 보고서 번호(4자리 숫자)만 보내고, 파일 이름 규칙(rpt-번호.txt)은 코드가 정한다(I-04).

    좋은 예

    import json
from pathlib import Path

# 메시지에는 채널 식별자만 싣고, 실제 기록 파일은 프로그램이 가진 표에서 고른다
SINKS = {"ch1": Path("verdicts/ch1.log"), "ch2": Path("verdicts/ch2.log")}
VERDICTS = ("PASS", "FAIL")          # 기록 줄을 위조하지 못하게 판정 값도 표와 대조한다


def record(message):
    try:
        msg = json.loads(message)
        sink_id, case, verdict = msg["sink"], int(msg["case"]), msg["verdict"]
    except (ValueError, KeyError, TypeError):
        print("rejected message: bad format")
        return
    sink = SINKS.get(sink_id) if isinstance(sink_id, str) else None
    if sink is None:
        print("rejected sink:", sink_id)
        return
    if verdict not in VERDICTS:
        print("rejected verdict")
        return
    sink.parent.mkdir(exist_ok=True)
    with sink.open("a", encoding="utf-8") as out:
        out.write(f"case {case}: {verdict}\n")


with open("nav.cfg", "w", encoding="utf-8") as f:
    f.write("MAGVAR=7.9\n")
record('{"sink": "ch1", "case": 101, "verdict": "PASS"}')
record('{"sink": "nav.cfg", "case": 102, "verdict": "PASS"}')
record('{"sink": [], "case": 103, "verdict": "PASS"}')
with open("nav.cfg", encoding="utf-8") as f:
    print("nav.cfg:", " | ".join(f.read().split("\n")))

    메시지에는 채널 식별자만 싣게 하고, 식별자에 대응하는 실제 자원(파일 경로)은 프로그램 안의 표에서 고른다(I-04). 표에 없는 식별자는 거부하므로 외부 값으로 임의의 자원을 고를 수 없다. 형식이 잘못된 메시지와 정해진 값이 아닌 판정도 거부해 기록 줄을 위조하지 못하게 한다.

    Automated static analysis, commonly referred to as Static Application Security Testing (SAST), can find some instances of this weakness by analyzing source code (or binary/compiled code) without having to execute it.
