    NULL Pointer Dereference

    항목 내용
    추상화 수준 기본(Base)
    상태 안정(Stable)
    소속 「보안약점 점검 목록」(44개) · 언어 뷰 C·C++·Java(CWE-658·659·660)
    가이드 적용성 해당
    적용 플랫폼 언어: C, C++, Java, C#, Go, Python
    원문 MITRE CWE-476 (CWE 5.0)

    이름 표기

    「소프트웨어 개발보안 가이드」(2021. 11.)의 항목명은 'Null Pointer 역참조'(인쇄 296쪽)이다. 이 가이드는 같은 항목 본문이 쓰는 한글 표기 '널 포인터(Null Pointer) 역참조'를 이름으로 삼고, 영문은 C 상수 표기대로 NULL로 병기한다.

    한 줄 요약

    유효하리라 기대한 포인터가 실제로는 NULL인데 이를 역참조하는 약점이다.

    → 나쁜 예·좋은 예

    설명(Description)¶

    제품이 유효하다고 기대한 포인터를 역참조하지만, 그 포인터가 NULL이다.

    원문(Description · Dimensions)

    The product dereferences a pointer that it expects to be valid but is NULL.

    Dimensions: Behavior-Type = Dereferenc; Resource-Type = Pointer; Resource-Property = NULL

    발생 단계(Modes Of Introduction)¶

    CWE 단계(Phase) 수명주기 단계(가이드 대응) 설명
    구현(Implementation) 구현 —

    영향(Common Consequences)¶

    영역 영향 설명
    가용성 서비스 거부: 비정상 종료·재시작 널 포인터 역참조는 (일부 플랫폼에서) 예외 처리를 쓸 수 있고 실제로 구현해 둔 경우가 아니면 대개 프로세스 실패로 이어지며, 예외 처리를 쓰더라도 소프트웨어를 안전한 동작 상태로 되돌리기는 여전히 매우 어려울 수 있다.
    무결성 / 기밀성 허가되지 않은 코드·명령 실행 / 메모리 읽기 / 메모리 수정 드물게 NULL이 0x0 메모리 주소와 같고 특권 코드가 그 주소에 접근할 수 있으면 메모리 읽기·쓰기가 가능해져 코드 실행으로 이어질 수 있다.

    완화책(Potential Mitigations)¶

    원문 완화책 5건(수명주기 단계로 묶은 규칙은 색인에 있다).

    구현 (본문 제5장)¶

    CWE 단계(Phase) 전략 요지 효과성
    구현(Implementation) — 수정되었을 수 있거나 NULL을 반환할 수 있는 함수에서 받은 포인터는 사용 전에 NULL인지 검사하고, 멀티스레드나 비동기 환경에서는 검사 전에 적절한 잠금 API로 잠그고 끝나면 해제한다 [REF-1484].
    원문

    For any pointers that could have been modified or provided from a function that can return NULL, check the pointer for NULL before use. When working with a multithreaded or otherwise asynchronous environment, ensure that proper locking APIs are used to lock before the check, and unlock when it has finished [REF-1484].

    		 —
    구현(Implementation) — 값을 반환하는 모든 함수의 결과를 확인하고, 그 값을 사용하기 전에 NULL이 아닌지 검증한다.
    원문

    Check the results of all functions that return a value and verify that the value is non-null before acting upon it.

    구현(Implementation) — 모든 변수와 데이터 저장소를 선언 시점이나 처음 사용 직전에 명시적으로 초기화한다.

    예시(나쁜 예·좋은 예)¶

    아래 코드는 이 가이드가 다음 상황을 가정해 새로 작성한 것이다. 장비 구성 표에서 채널 번호로 장치 설정을 찾는다. 등록되지 않은 채널이면 찾기 함수가 '없음'을 돌려준다. 언어마다 분석기·새니타이저·실행 결과로 나쁜 예는 잡히고 좋은 예는 잡히지 않음을 확인했다. 좋은 예는 그 약점 하나를 막는 최소 예이며 그대로 운용 코드가 되는 것은 아니다. 언어 상자를 눌러 펼친다.

    C

    나쁜 예

    #include <stdio.h>
#include <stddef.h>

typedef struct { int channel; int gain; } DeviceCfg;

static DeviceCfg table[] = {{1, 10}, {2, 20}};

static DeviceCfg *find_cfg(int channel)
{
    for (size_t i = 0; i < sizeof table / sizeof table[0]; ++i) {
        if (table[i].channel == channel) {
            return &table[i];
        }
    }
    return NULL;
}

int main(void)
{
    DeviceCfg *cfg = find_cfg(7);            /* 등록되지 않은 채널 */
    printf("gain %d\n", cfg->gain);          /* NULL 검사 없이 역참조 */
    return 0;
}

    찾기 함수가 NULL을 돌려줄 수 있는데 검사하지 않고 역참조한다. MMU가 없는 MCU에서는 0번지 근처를 읽거나 써서 오동작이 바로 드러나지 않을 수도 있다.

    좋은 예

    #include <stdio.h>
#include <stddef.h>

typedef struct { int channel; int gain; } DeviceCfg;

static DeviceCfg table[] = {{1, 10}, {2, 20}};

static const DeviceCfg *find_cfg(int channel)
{
    for (size_t i = 0; i < sizeof table / sizeof table[0]; ++i) {
        if (table[i].channel == channel) {
            return &table[i];
        }
    }
    return NULL;
}

int main(void)
{
    const DeviceCfg *cfg = find_cfg(7);
    if (cfg == NULL) {
        puts("channel not configured: safe default");
        return 0;                            /* 안전 상태로 전환(D-08) */
    }
    printf("gain %d\n", cfg->gain);
    return 0;
}

    반환값을 쓰기 전에 NULL인지 검사하고, 없으면 설계에서 정한 안전 상태로 처리한다(I-06·D-08).

    검증: AddressSanitizer(clang) — 나쁜 예에서 AddressSanitizer: (SEGV|access-violation) 검출, 좋은 예에서 미검출 · 참고: MITRE CWE-476 Demonstrative Example 1(조회 함수가 돌려준 NULL을 검사 없이 사용) 참고, 이 가이드가 새로 작성 / KISA·행정안전부 「C 시큐어코딩 가이드」(3판) 코드오류 5-1 '널(Null)포인터 역참조'(인쇄 162쪽) 참고

    C++

    나쁜 예

    #include <cstdio>
#include <map>
#include <string>

struct Link { int baud; };

std::map<std::string, Link*> links;

Link *lookup(const std::string &name) {
    auto it = links.find(name);
    return it == links.end() ? nullptr : it->second;
}

int main() {
    static Link uart0{115200};
    links["uart0"] = &uart0;
    Link *l = lookup("uart3");               // 없는 링크
    std::printf("%d\n", l->baud);             // nullptr 역참조
    return 0;
}

    없는 이름이면 nullptr을 돌려주는 함수의 결과를 검사 없이 역참조한다.

    좋은 예

    #include <cstdio>
#include <map>
#include <optional>
#include <string>

struct Link { int baud; };

std::map<std::string, Link> links;

std::optional<Link> lookup(const std::string &name) {
    auto it = links.find(name);
    if (it == links.end()) {
        return std::nullopt;                 // '없음'을 형으로 표현
    }
    return it->second;
}

int main() {
    links["uart0"] = Link{115200};
    if (auto l = lookup("uart3")) {
        std::printf("%d\n", l->baud);
    } else {
        std::puts("link not configured");
    }
    return 0;
}

    '없을 수 있음'을 반환형(std::optional)에 드러내 호출자가 검사를 빠뜨리기 어렵게 한다. 값은 if (auto l = …)처럼 확인한 뒤에만 꺼낸다(검사 없이 ->·*를 쓰면 여전히 미정의 동작).

    검증: AddressSanitizer(clang) — 나쁜 예에서 AddressSanitizer: (SEGV|access-violation) 검출, 좋은 예에서 미검출 · 참고: MITRE CWE-476 Demonstrative Example 1(조회 함수가 돌려준 NULL을 검사 없이 사용) 참고, 이 가이드가 새로 작성

    C#

    나쁜 예

    var sensors = new Dictionary<string, string?> { ["imu"] = "IMU-A", ["gps"] = null };
string? model = sensors["gps"];          // 값이 null일 수 있다
Console.WriteLine(model.Length);           // CS8602: null일 수 있는 참조를 역참조

    null 허용 참조를 검사 없이 역참조한다. Nullable 분석을 켜면 컴파일 경고(CS8602)로 잡힌다.

    좋은 예

    var sensors = new Dictionary<string, string?> { ["imu"] = "IMU-A", ["gps"] = null };
if (sensors.TryGetValue("gps", out string? model) && model is not null)
{
    Console.WriteLine(model.Length);
}
else
{
    Console.WriteLine("sensor model missing");
}

    TryGetValue와 null 검사로 두 경우(키 없음, 값이 null)를 모두 처리한다. Nullable 경고는 오류로 올린다(LCS-08).

    검증: .NET 컴파일러·분석기 — 나쁜 예에서 CS8602 검출, 좋은 예에서 미검출 · 참고: MITRE CWE-476 Demonstrative Example 2(없을 수 있는 속성 값을 검사 없이 사용) 참고, 이 가이드가 새로 작성

    Java

    나쁜 예

    import java.util.HashMap;
import java.util.Map;

public class Example {
    record Profile(String unit, int maxRate) {}

    static final Map<String, Profile> PROFILES = new HashMap<>();

    public static void main(String[] args) {
        PROFILES.put("imu", new Profile("deg/s", 400));
        Profile p = PROFILES.get("gps");     // 없는 키면 null
        System.out.println(p.maxRate());     // NullPointerException
    }
}

    Map.get은 키가 없으면 null을 돌려준다. 검사 없이 메서드를 부르면 NullPointerException으로 처리 스레드가 멈춘다.

    좋은 예

    import java.util.HashMap;
import java.util.Map;
import java.util.Optional;

public class Example {
    record Profile(String unit, int maxRate) {}

    static final Map<String, Profile> PROFILES = new HashMap<>();

    public static void main(String[] args) {
        PROFILES.put("imu", new Profile("deg/s", 400));
        Optional<Profile> p = Optional.ofNullable(PROFILES.get("gps"));
        System.out.println(p.map(Profile::maxRate)
                            .map(String::valueOf)
                            .orElse("profile missing: using safe default"));
    }
}

    없을 수 있는 값을 Optional로 감싸 기본값 처리를 코드에 드러낸다.

    검증: 실행 결과 — 나쁜 예에서 NullPointerException 검출, 좋은 예에서 미검출·using safe default 출력 확인 · 참고: MITRE CWE-476 Demonstrative Example 2·3(없을 수 있는 속성·인텐트 값을 검사 없이 사용) 참고, 이 가이드가 새로 작성 / KISA·행정안전부 「Java 시큐어코딩 가이드」(3판) 코드오류 5-1 '널(Null)포인터 역참조'(인쇄 247쪽) 참고

    Python

    나쁜 예

    from dataclasses import dataclass


@dataclass
class ChannelConfig:
    device: str
    rate_hz: int


CONFIG = {1: ChannelConfig("imu", 200), 2: ChannelConfig("baro", 50)}


# 장비 구성 표에서 채널 번호로 설정을 찾아 표본 주기를 정한다
def sample_period_ms(channel):
    cfg = CONFIG.get(channel)            # 등록되지 않은 채널이면 None
    return 1000 // cfg.rate_hz           # None을 확인하지 않고 속성을 읽는다


print("ch1 period:", sample_period_ms(1), "ms")
print("ch7 period:", sample_period_ms(7), "ms")

    dict.get()은 키가 없으면 None을 돌려주는데, 확인 없이 속성을 읽는다. 등록되지 않은 채널 번호가 들어오면 AttributeError('NoneType' object has no attribute)로 처리기가 비정상 종료한다. re.match()·찾기 함수처럼 '없음'을 None으로 돌려주는 API에서 흔하다.

    좋은 예

    from dataclasses import dataclass
from typing import Optional


@dataclass
class ChannelConfig:
    device: str
    rate_hz: int


CONFIG = {1: ChannelConfig("imu", 200), 2: ChannelConfig("baro", 50)}


def sample_period_ms(channel) -> Optional[int]:
    cfg = CONFIG.get(channel)
    if cfg is None:                      # '없음'을 먼저 처리한다
        return None
    return 1000 // cfg.rate_hz


for ch in (1, 7):
    period = sample_period_ms(ch)
    print(f"ch{ch} period:", "unregistered channel" if period is None else f"{period} ms")

    '없음'을 돌려줄 수 있는 함수는 반환형에 Optional을 적고, 쓰는 쪽에서 is None으로 먼저 처리한다(I-06). mypy·pyright로 타입 검사를 하면 Optional 값을 확인 없이 쓰는 곳을 찾을 수 있다.

    검증: 실행 결과 — 나쁜 예에서 AttributeError: 'NoneType' object has no attribute 검출, 좋은 예에서 미검출·ch7 period: unregistered channel 출력 확인 · 참고: MITRE CWE-476 Demonstrative Example 2(속성이 늘 있다고 가정하고 반환값을 씀) 참고, 이 가이드가 새로 작성 / 과학기술정보통신부·한국인터넷진흥원 「Python 시큐어코딩 가이드」(2023. 12.) 코드오류 5-1 'Null Pointer 역참조'(인쇄 135쪽) 참고

    MITRE 원문 예시(Demonstrative Examples, 영문 4건)

    Example 1. This example takes an IP address from a user, verifies that it is well formed and then looks up the hostname and copies it into a buffer.

    Bad / C

    void host_lookup(char *user_supplied_addr){

  struct hostent *hp;
  in_addr_t *addr;
  char hostname[64];
  in_addr_t inet_addr(const char *cp);

                             /*routine that ensures user_supplied_addr is in the right format for conversion */

  validate_addr_form(user_supplied_addr);
  addr = inet_addr(user_supplied_addr);
  hp = gethostbyaddr( addr, sizeof(struct in_addr), AF_INET);
  strcpy(hostname, hp->h_name);

}

    If an attacker provides an address that appears to be well-formed, but the address does not resolve to a hostname, then the call to gethostbyaddr() will return NULL. Since the code does not check the return value from gethostbyaddr (CWE-252), a NULL pointer dereference (CWE-476) would then occur in the call to strcpy().

    Note that this code is also vulnerable to a buffer overflow (CWE-119).

    Example 2. In the following code, the programmer assumes that the system always has a property named "cmd" defined. If an attacker can control the program's environment so that "cmd" is not defined, the program throws a NULL pointer exception when it attempts to call the trim() method.

    Bad / Java

    String cmd = System.getProperty("cmd");
cmd = cmd.trim();

    Example 3. This Android application has registered to handle a URL when sent an intent:

    Bad / Java

                         ...

IntentFilter filter = new IntentFilter("com.example.URLHandler.openURL");
MyReceiver receiver = new MyReceiver();
registerReceiver(receiver, filter);

                     ...

public class UrlHandlerReceiver extends BroadcastReceiver {

  @Override
  public void onReceive(Context context, Intent intent) {

    if("com.example.URLHandler.openURL".equals(intent.getAction())) {
      String URL = intent.getStringExtra("URLToOpen");
      int length = URL.length();

                                     ...

    }

  }

}

    The application assumes the URL will always be included in the intent. When the URL is not present, the call to getStringExtra() will return null, thus causing a null pointer exception when length() is called.

    Example 4. Consider the following example of a typical client server exchange. The HandleRequest function is intended to perform a request and use a defer to close the connection whenever the function returns.

    Bad / Go

    func HandleRequest(client http.Client, request *http.Request) (*http.Response, error) {

                          response, err := client.Do(request)

                          defer response.Body.Close()

                          if err != nil {

                                  return nil, err

                          }
  ...

                     }

    If a user supplies a malformed request or violates the client policy, the Do method can return a nil response and a non-nil err.

    This HandleRequest Function evaluates the close before checking the error. A deferred call's arguments are evaluated immediately, so the defer statement panics due to a nil response.

    Identify error conditions that are not likely to occur during normal usage and trigger them. If you trigger an unhandled exception or similar error that was discovered and handled by the application's environment, it may still indicate unexpected conditions that were not handled by the application itself.

    		 —
    자동 정적 분석 흔히 SAST(Static Application Security Testing)라 부르는 자동 정적 분석(static analysis)은 소스코드(또는 바이너리·컴파일된 코드)를 실행하지 않고 분석해 이 약점의 일부 사례를 찾을 수 있으며, 대개 데이터 흐름·제어 흐름 모델을 만든 뒤 입력 출처('source')와 외부 구성요소나 운영체제 같은 하위 계층과 상호작용하는 목적지('sink')를 잇는 잠재적 취약 패턴을 찾는다.
    원문

    Automated static analysis, commonly referred to as Static Application Security Testing (SAST), can find some instances of this weakness by analyzing source code (or binary/compiled code) without having to execute it. Typically, this is done by building a model of data flow and control flow, then searching for potentially-vulnerable patterns that connect "sources" (origins of input) with "sinks" (destinations where the data interacts with external components, a lower layer such as the OS, etc.)

    		 높음(High)
    자동 동적 분석 C/C++용 AddressSanitizer(ASan) [REF-1518]처럼 컴파일 시 통합되어 메모리 안전성 오류에 대한 실행 시 오류 검사 장치를 넣는 도구를 쓴다.
    원문

    Use tools that are integrated during compilation to insert runtime error-checking mechanisms related to memory safety errors, such as AddressSanitizer (ASan) for C/C++ [REF-1518].
