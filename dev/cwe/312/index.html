    Cleartext Storage of Sensitive Information

    항목 내용
    추상화 수준 기본(Base)
    상태 초안(Draft)
    소속 「보안약점 점검 목록」(44개)
    가이드 적용성 해당
    적용 플랫폼 언어: 언어 무관, Go · 기술: 클라우드 컴퓨팅(Cloud Computing), 산업제어시스템·운영기술(ICS/OT), 모바일(Mobile)
    원문 MITRE CWE-312 (CWE 5.0)

    이름 표기

    「소프트웨어 개발보안 가이드」(2021. 11.)의 구현단계 기준은 CWE-312·319를 '암호화되지 않은 중요정보'(인쇄 227쪽) 하나로 묶는다. 이 가이드는 둘을 따로 다루므로 같은 가이드 분석·설계단계 사례의 그림 제목 '중요정보 평문저장'(그림 3-32, 인쇄 119쪽)을 띄어 써서 이름으로 쓴다.

    한 줄 요약

    다른 제어 영역에서 접근할 수도 있는 자원에 중요정보를 평문으로 저장하는 약점이다.

    → 나쁜 예·좋은 예

    설명(Description)¶

    제품이 다른 제어 영역(control sphere)에서 접근할 수도 있는 자원 안에 중요정보를 평문으로 저장하는 약점이다.

    원문(Description)

    The product stores sensitive information in cleartext within a resource that might be accessible to another control sphere.

    발생 단계(Modes Of Introduction)¶

    CWE 단계(Phase) 수명주기 단계(가이드 대응) 설명
    아키텍처·설계(Architecture and Design) 설계 누락(OMISSION): 아키텍처·설계 단계에서 보안 전술을 빠뜨려 생기는 약점이다.

    영향(Common Consequences)¶

    영역 영향 설명
    기밀성 애플리케이션 데이터 읽기 시스템에 접근할 수 있는 공격자는 평문(암호화되지 않은 상태)으로 저장된 중요정보를 읽을 수 있으며, 사람이 읽을 수 없게 인코딩되어 있더라도 특정 기법으로 어떤 인코딩이 쓰였는지 알아내 정보를 디코딩할 수 있다.

    완화책(Potential Mitigations)¶

    원문 완화책 2건(수명주기 단계로 묶은 규칙은 색인에 있다).

    요구사항 분석 (본문 제3장)¶

    원문 완화책 없음

    설계 (본문 제4장)¶

    원문 완화책 없음. 이 단계의 기준선 활동: D-05 암호·키·비밀 관리 설계

    구현 (본문 제5장)¶

    CWE 단계(Phase) 전략 요지
    구현(Implementation) / 시스템 구성(System Configuration) / 운용(Operation) — 클라우드(예: S3 버킷, Azure blob, Google Cloud Storage 등)에 데이터를 저장할 때는 제공자의 통제 기능으로 저장 데이터를 암호화한다 [REF-1297] [REF-1299] [REF-1301]. (유지보수 단계에도 해당)
    원문

    When storing data in the cloud (e.g., S3 buckets, Azure blobs, Google Cloud Storage, etc.), use the provider's controls to encrypt the data at rest. [REF-1297] [REF-1299] [REF-1301]
    구현(Implementation) / 시스템 구성(System Configuration) / 운용(Operation) — 클라우드 같은 일부 시스템·환경에서는 소프트웨어 계층과 하드웨어 계층 모두에 '이중 암호화'가 요구될 수 있고, 개발자가 더 넓은 시스템·환경의 관리자와 책임을 나누지 않고 두 계층을 모두 단독으로 책임질 수도 있다. (유지보수 단계에도 해당)
    원문

    In some systems/environments such as cloud, the use of "double encryption" (at both the software and hardware layer) might be required, and the developer might be solely responsible for both layers, instead of shared responsibility with the administrator of the broader system/environment.

    통합 및 시험 (본문 제6장)¶

    원문 완화책 없음

    유지보수 (본문 제7장)¶

    이 단계를 함께 가리키는 원문 완화책은 구현 단계에 2건 실었다('유지보수 단계에도 해당' 표시).

    예시(나쁜 예·좋은 예)¶

    아래 코드는 이 가이드가 다음 상황을 가정해 새로 작성한 것이다. 임무 계획 단말이 다음 임무의 경로와 데이터링크 접속 비밀값을 로컬 파일에 저장한다. 저장 매체(SD 카드·이동식 디스크·정비 노트북)가 분실·탈취되거나 정비 반출되면 파일 내용을 그대로 읽을 수 있다. 예시는 저장한 파일에서 비밀값 문자열이 보이는지 직접 찾아 본다. 언어마다 분석기·새니타이저·실행 결과로 나쁜 예는 잡히고 좋은 예는 잡히지 않음을 확인했다. 좋은 예는 그 약점 하나를 막는 최소 예이며 그대로 운용 코드가 되는 것은 아니다. 언어 상자를 눌러 펼친다.

    C

    나쁜 예

    #define _GNU_SOURCE
#include <stdio.h>
#include <string.h>

/* 임무 계획 레코드를 그대로 파일에 쓴다 */
static int store_plan(const char *path, const char *record)
{
    FILE *fp = fopen(path, "w");
    if (fp == NULL) {
        return -1;
    }
    fputs(record, fp);
    fclose(fp);
    return 0;
}

/* 매체를 손에 넣은 사람이 하는 일: 파일에서 비밀값을 찾는다 */
static int medium_reveals(const char *path, const char *needle)
{
    unsigned char raw[512];
    FILE *fp = fopen(path, "rb");
    if (fp == NULL) {
        return 0;
    }
    size_t got = fread(raw, 1, sizeof raw, fp);
    fclose(fp);
    return memmem(raw, got, needle, strlen(needle)) != NULL;
}

int main(void)
{
    const char *secret = "EXAMPLE-ONLY-LINK-SECRET";
    char record[160];
    snprintf(record, sizeof record, "route=WP1>WP2>WP3\nlink_secret=%s\n", secret);
    if (store_plan("plan.dat", record) != 0) {
        puts("save failed");
        return 1;
    }
    puts(medium_reveals("plan.dat", secret) ? "PLAINTEXT FOUND ON MEDIUM" : "medium holds ciphertext only");
    return 0;
}

    임무 경로와 링크 비밀값을 평문 그대로 파일에 쓴다. 매체를 손에 넣은 사람은 strings 같은 도구로 비밀값을 바로 읽는다.

    좋은 예

    #define _GNU_SOURCE
#include <stdio.h>
#include <string.h>
#include <openssl/crypto.h>
#include <openssl/evp.h>
#include <openssl/rand.h>

/* 시험용 대체 구현: 실제 장비는 보안요소·eFuse에 주입된 저장용 키를 쓴다 */
static int keystore_storage_key(unsigned char key[32])
{
    return RAND_bytes(key, 32) == 1 ? 0 : -1;
}

/* 검증된 암호 라이브러리의 AES-256-GCM으로 암호화해 [IV|태그|암호문]으로 쓴다 */
static int store_plan(const char *path, const unsigned char key[32], const char *record)
{
    unsigned char iv[12], tag[16], body[256];
    int n = (int)strlen(record), out = 0, tail = 0, ok = 0;
    if (n > (int)sizeof body || RAND_bytes(iv, sizeof iv) != 1) return -1;
    EVP_CIPHER_CTX *ctx = EVP_CIPHER_CTX_new();
    ok = ctx != NULL && EVP_EncryptInit_ex(ctx, EVP_aes_256_gcm(), NULL, key, iv) == 1
         && EVP_EncryptUpdate(ctx, body, &out, (const unsigned char *)record, n) == 1
         && EVP_EncryptFinal_ex(ctx, body + out, &tail) == 1
         && EVP_CIPHER_CTX_ctrl(ctx, EVP_CTRL_GCM_GET_TAG, sizeof tag, tag) == 1;
    EVP_CIPHER_CTX_free(ctx);
    FILE *fp = ok ? fopen(path, "wb") : NULL;
    if (fp == NULL) return -1;
    fwrite(iv, 1, sizeof iv, fp);
    fwrite(tag, 1, sizeof tag, fp);
    fwrite(body, 1, (size_t)(out + tail), fp);
    return fclose(fp) == 0 ? 0 : -1;
}

int main(void)
{
    const char *secret = "EXAMPLE-ONLY-LINK-SECRET";
    unsigned char key[32], raw[512];
    char record[160];
    snprintf(record, sizeof record, "route=WP1>WP2>WP3\nlink_secret=%s\n", secret);
    if (keystore_storage_key(key) != 0 || store_plan("plan.dat", key, record) != 0) {
        puts("save refused");
        return 1;
    }
    OPENSSL_cleanse(key, sizeof key);
    OPENSSL_cleanse(record, sizeof record);   /* 평문 버퍼 소거 */
    FILE *fp = fopen("plan.dat", "rb");       /* 매체를 손에 넣은 사람처럼 저장 파일을 훑어본다 */
    size_t got = fp ? fread(raw, 1, sizeof raw, fp) : 0;
    if (fp) fclose(fp);
    puts(memmem(raw, got, secret, strlen(secret)) ? "PLAINTEXT FOUND ON MEDIUM" : "medium holds ciphertext only");
    return 0;
}

    검증된 암호 라이브러리(OpenSSL)의 AES-256-GCM으로 암호화해 [IV|태그|암호문]으로 저장하고, 저장용 키는 보안요소·eFuse에서 받는 인터페이스로 분리한다(예시의 키 함수는 시험용 대체). 저장 뒤 평문 버퍼와 키는 OPENSSL_cleanse로 지운다(D-05).

    검증: 실행 결과 · Linux(gcc)에서 빌드 — 나쁜 예에서 PLAINTEXT FOUND ON MEDIUM 검출, 좋은 예에서 미검출·medium holds ciphertext only 출력 확인 · 참고: MITRE CWE-312 Demonstrative Example 4(설정·속성 파일에 평문으로 둔 자격 증명) 참고, 이 가이드가 새로 작성

    C++

    나쁜 예

    #include <cstdio>
#include <fstream>
#include <iterator>
#include <string>

// 운용자 콘솔이 다음 임무의 경로와 링크 비밀값을 설정 파일에 그대로 저장한다
static void save_plan(const char *path, const std::string &record) {
    std::ofstream out(path, std::ios::binary);
    out << record;
}

// 디스크를 손에 넣은 사람이 하는 일: 파일 내용에서 비밀값을 찾는다
static bool disk_reveals(const char *path, const std::string &needle) {
    std::ifstream in(path, std::ios::binary);
    const std::string data((std::istreambuf_iterator<char>(in)), std::istreambuf_iterator<char>());
    return data.find(needle) != std::string::npos;
}

int main() {
    const std::string secret = "EXAMPLE-ONLY-LINK-SECRET";
    save_plan("plan.cfg", "route=WP1>WP2>WP3\nlink_secret=" + secret + "\n");
    std::puts(disk_reveals("plan.cfg", secret) ? "PLAINTEXT FOUND ON MEDIUM" : "medium holds ciphertext only");
    return 0;
}

    Windows 운용자 콘솔이 경로와 링크 비밀값을 설정 파일에 그대로 쓴다. 디스크나 백업을 읽을 수 있는 사람은 누구나 비밀값을 얻는다.

    좋은 예

    #include <windows.h>
#include <wincrypt.h>
#include <cstdio>
#include <fstream>
#include <iterator>
#include <stdexcept>
#include <string>
#include <vector>

// Windows DPAPI: 운영체제가 로그온 사용자 자격에 묶인 키로 암호화하므로 응용이 키를 직접 들고 있지 않다
static bool seal(const std::string &plain, std::vector<unsigned char> &sealed) {
    DATA_BLOB in{static_cast<DWORD>(plain.size()),
                 reinterpret_cast<BYTE *>(const_cast<char *>(plain.data()))};
    DATA_BLOB out{};
    if (!CryptProtectData(&in, L"mission-plan", nullptr, nullptr, nullptr, CRYPTPROTECT_UI_FORBIDDEN, &out)) {
        return false;
    }
    sealed.assign(out.pbData, out.pbData + out.cbData);
    LocalFree(out.pbData);
    return true;
}

static void save_plan(const char *path, const std::string &record) {
    std::vector<unsigned char> sealed;
    if (!seal(record, sealed)) {
        throw std::runtime_error("seal failed: plan not saved");   // 평문으로 대신 저장하지 않는다
    }
    std::ofstream out(path, std::ios::binary);
    out.write(reinterpret_cast<const char *>(sealed.data()), static_cast<std::streamsize>(sealed.size()));
}

static bool disk_reveals(const char *path, const std::string &needle) {
    std::ifstream in(path, std::ios::binary);
    const std::string data((std::istreambuf_iterator<char>(in)), std::istreambuf_iterator<char>());
    return data.find(needle) != std::string::npos;
}

int main() {
    const std::string secret = "EXAMPLE-ONLY-LINK-SECRET";
    std::string record = "route=WP1>WP2>WP3\nlink_secret=" + secret + "\n";
    save_plan("plan.cfg", record);
    SecureZeroMemory(record.data(), record.size());   // 메모리의 평문도 지운다
    std::puts(disk_reveals("plan.cfg", secret) ? "PLAINTEXT FOUND ON MEDIUM" : "medium holds ciphertext only");
    return 0;
}

    Windows DPAPI(CryptProtectData)로 로그온 사용자 자격에 묶인 키로 암호화해 저장하고, 암호화에 실패하면 평문으로 대신 저장하지 않고 예외로 멈춘다. 메모리의 평문은 SecureZeroMemory로 지운다(WIN-06). 예시의 secret 문자열과 이어 붙일 때 생긴 임시 문자열까지 지우지는 못하므로, 실제로는 비밀값의 사본을 줄이고 남은 사본도 지운다.

    검증: 실행 결과 — 나쁜 예에서 PLAINTEXT FOUND ON MEDIUM 검출, 좋은 예에서 미검출·medium holds ciphertext only 출력 확인 · 참고: MITRE CWE-312 Demonstrative Example 4(설정·속성 파일에 평문으로 둔 자격 증명) 참고, 이 가이드가 새로 작성

    C#

    나쁜 예

    using System.Text;

const string Secret = "EXAMPLE-ONLY-LINK-SECRET";
string planFile = Path.Combine(Environment.CurrentDirectory, "plan.txt");

// 임무 계획 단말이 경로와 링크 비밀값을 텍스트 파일에 그대로 저장한다
File.WriteAllText(planFile, $"route=WP1>WP2>WP3\nlink_secret={Secret}\n");

    File.WriteAllText로 링크 비밀값을 텍스트 파일에 그대로 저장한다. 파일을 읽을 수 있는 사람은 누구나 비밀값을 얻는다.

    좋은 예

    using System.Security.Cryptography;
using System.Text;

const string Secret = "EXAMPLE-ONLY-LINK-SECRET";
string planFile = Path.Combine(Environment.CurrentDirectory, "plan.bin");

// 시험용 대체 구현: 실제로는 키 저장소(HSM·보안요소·OS 키 저장소)에서 저장용 키를 받는다
byte[] storageKey = RandomNumberGenerator.GetBytes(32);

// AES-GCM으로 암호화해 [논스|태그|암호문]으로 저장한다

byte[] body = new byte[record.Length];
using (var gcm = new AesGcm(storageKey, tag.Length))
{
    gcm.Encrypt(nonce, record, body, tag);
}

CryptographicOperations.ZeroMemory(record);      // 평문 버퍼 소거
CryptographicOperations.ZeroMemory(storageKey);

    AesGcm으로 암호화해 [논스|태그|암호문]으로 저장하고, 저장 뒤 평문과 키를 CryptographicOperations.ZeroMemory로 지운다. 키는 HSM·보안요소·OS 키 저장소에서 받는 자리로 둔다(예시의 키는 시험용 난수, D-05).

    Java

    나쁜 예

    import java.io.IOException;
import java.io.OutputStream;
import java.nio.charset.StandardCharsets;
import java.nio.file.Files;
import java.nio.file.Path;
import java.util.Properties;

public class Example {
    // 임무 계획 단말이 경로와 링크 비밀값을 속성 파일에 그대로 저장한다
    static void savePlan(Path file, String route, String linkSecret) throws IOException {
        Properties plan = new Properties();
        plan.setProperty("route", route);
        plan.setProperty("link.secret", linkSecret);
        try (OutputStream out = Files.newOutputStream(file)) {
            plan.store(out, "mission plan");
        }
    }

    // 매체를 손에 넣은 사람이 하는 일: 파일 내용에서 비밀값을 찾는다
    static boolean mediumReveals(Path file, String needle) throws IOException {
        String raw = new String(Files.readAllBytes(file), StandardCharsets.ISO_8859_1);
        return raw.contains(needle);
    }

    public static void main(String[] args) throws IOException {
        String secret = "EXAMPLE-ONLY-LINK-SECRET";
        Path file = Path.of("plan.properties");
        savePlan(file, "WP1>WP2>WP3", secret);
        System.out.println(mediumReveals(file, secret) ? "PLAINTEXT FOUND ON MEDIUM" : "medium holds ciphertext only");
    }
}

    Properties 파일에 링크 비밀값을 평문으로 저장한다. 속성 파일은 사람이 읽는 텍스트라 매체만 있으면 그대로 드러난다.

    좋은 예

    import java.io.IOException;
import java.nio.ByteBuffer;
import java.nio.charset.StandardCharsets;
import java.nio.file.Files;
import java.nio.file.Path;
import java.security.GeneralSecurityException;
import java.security.SecureRandom;
import javax.crypto.Cipher;
import javax.crypto.KeyGenerator;
import javax.crypto.SecretKey;
import javax.crypto.spec.GCMParameterSpec;

public class Example {
    static final SecureRandom RNG = new SecureRandom();

    // 시험용 대체 구현: 실제로는 KeyStore·HSM(PKCS#11)에 둔 저장용 키를 꺼낸다
    static SecretKey storageKey() throws GeneralSecurityException {
        KeyGenerator kg = KeyGenerator.getInstance("AES");
        kg.init(256, RNG);
        return kg.generateKey();
    }

    // AES-GCM으로 암호화해 [IV|암호문+태그]로 저장한다
    static void savePlan(Path file, SecretKey key, byte[] record) throws IOException, GeneralSecurityException {
        byte[] iv = new byte[12];
        RNG.nextBytes(iv);
        Cipher gcm = Cipher.getInstance("AES/GCM/NoPadding");
        gcm.init(Cipher.ENCRYPT_MODE, key, new GCMParameterSpec(128, iv));
        byte[] sealed = gcm.doFinal(record);
        Files.write(file, ByteBuffer.allocate(iv.length + sealed.length).put(iv).put(sealed).array());
    }

    static boolean mediumReveals(Path file, String needle) throws IOException {
        String raw = new String(Files.readAllBytes(file), StandardCharsets.ISO_8859_1);
        return raw.contains(needle);
    }

    public static void main(String[] args) throws IOException, GeneralSecurityException {
        String secret = "EXAMPLE-ONLY-LINK-SECRET";
        byte[] record = ("route=WP1>WP2>WP3\nlink.secret=" + secret + "\n").getBytes(StandardCharsets.UTF_8);
        Path file = Path.of("plan.bin");
        savePlan(file, storageKey(), record);
        java.util.Arrays.fill(record, (byte) 0);   // 평문 버퍼 소거
        System.out.println(mediumReveals(file, secret) ? "PLAINTEXT FOUND ON MEDIUM" : "medium holds ciphertext only");
    }
}

    AES/GCM/NoPadding으로 암호화해 [IV|암호문+태그]로 저장하고, 키는 KeyStore·HSM에서 꺼내는 자리로 분리한다(예시의 키 생성은 시험용 대체). 평문 바이트 배열은 저장 뒤 0으로 채운다(D-05). String은 지울 수 없어 예시의 secret 문자열 사본은 메모리에 남으므로, 실제로는 비밀값을 처음부터 byte[]·char[]로 다룬다.

    좋은 예

    import json
import os

from cryptography.hazmat.primitives.ciphers.aead import AESGCM

LINK_PSK = "DL-PSK-61a9c0"            # 데이터링크 접속 비밀값(예시용 가짜 값)
MEDIUM_KEY = AESGCM.generate_key(bit_length=256)   # 실제로는 키 적재 장비가 넣고 매체에는 두지 않는 키


def save_mission(path, route):
    plain = json.dumps({"route": route, "link_psk": LINK_PSK}).encode()
    nonce = os.urandom(12)
    # 인증 암호화(AES-256-GCM): 내용을 감추고 바꿔치기도 복호화 단계에서 드러난다
    sealed = AESGCM(MEDIUM_KEY).encrypt(nonce, plain, b"mission-0412")
    with open(path, "wb") as f:
        f.write(nonce + sealed)


save_mission("mission-0412.bin", ["WP1", "WP2", "WP3"])
raw = open("mission-0412.bin", "rb").read()
print("PLAINTEXT FOUND ON MEDIUM" if LINK_PSK.encode() in raw else "no plaintext on medium")

    모든 항목에 공통인 시험 활동. T-01 정적시험과 T-02 타깃 동적시험은 대상 약점을 가리지 않고 모든 과제가 수행한다.

    환경 지침 6건. 과제 환경에 맞는 지침은 지침 선택 도구로 고른다. 축별로 최대 8건을 보이고 나머지는 부록 C에서 찾는다.

    축 지침
    탑재 환경 (2건) PC-03 저장·전송 데이터 보호, SOC-04 키 저장 위치
    운영체제/런타임 (2건) WIN-06 자격증명 저장 처리, LNX-06 난수·암호 모듈 사용
    개발·시험 망 환경 (2건) NET-CL-06 이동식 매체 보호, NET-CL-10 백업·복구·폐기 관리
