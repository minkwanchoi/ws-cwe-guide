    Use of Insufficiently Random Values

    항목 내용

    Comments: Examine children of this entry to see if there is a better fit
    적용 플랫폼 언어: 언어 무관, Go, Python · 기술 무관
    원문 MITRE CWE-330 (CWE 5.0)

    한 줄 요약

    예측할 수 없는 수에 의존하는 보안 맥락에서 충분히 무작위적이지 않은 수나 값을 쓰는 약점이다.

    → 나쁜 예·좋은 예

    설명(Description)¶

    제품이 예측할 수 없는 수에 의존하는 보안 맥락에서 충분히 무작위적이지 않은 수나 값을 사용하는 약점이다.

    배경(Background Details)

    컴퓨터는 결정적(deterministic) 기계이므로 진정한 난수를 만들어 낼 수 없다. 의사난수 생성기(PRNG)는 시드(seed)에서 시작해 이후 값을 계산하는 알고리즘으로 난수성을 근사한다. PRNG에는 통계적 PRNG와 암호학적 PRNG 두 종류가 있다. 통계적 PRNG는 유용한 통계적 성질을 제공하지만, 출력을 예측하기가 매우 쉽고 재현하기 쉬운 수열을 이루므로, 생성 값을 예측할 수 없어야 보안이 유지되는 경우에는 쓰기에 적합하지 않다. 암호학적 PRNG는 예측하기 더 어려운 출력을 만들어 이 문제를 해결한다. 값이 암호학적으로 안전하려면 공격자가 그 값을 진정한 난수와 구별하는 일이 불가능하거나 가능성이 매우 낮아야 한다.

    원문(Description · Background Details · Dimensions)

    The product uses insufficiently random numbers or values in a security context that depends on unpredictable numbers.

    Computers are deterministic machines, and as such are unable to produce true randomness. Pseudo-Random Number Generators (PRNGs) approximate randomness algorithmically, starting with a seed from which subsequent values are calculated. There are two types of PRNGs: statistical and cryptographic. Statistical PRNGs provide useful statistical properties, but their output is highly predictable and forms an easy to reproduce numeric stream that is unsuitable for use in cases where security depends on generated values being unpredictable. Cryptographic PRNGs address this problem by generating output that is more difficult to predict. For a value to be cryptographically secure, it must be impossible or highly improbable for an attacker to distinguish between it and a truly random value.

    Dimensions: Behavior-Type = Use; Resource-Type = Values; Resource-Property = Insufficiently Random

    영향(Common Consequences)¶

    영역 영향 설명
    기밀성 / 기타 기타 민감한 자원 접근을 제한하는 보호 메커니즘이 세션 ID나 암호 키 생성용 시드 같은 무작위 값에 의존하면, ID나 키를 추측해 보호 대상 자원에 접근할 수 있다.
    접근 통제 / 기타 보호 메커니즘 우회 / 기타 제품이 자원 식별에 고유하고 추측할 수 없는 ID에 의존하면, 공격자가 다른 사용자 소유 자원의 ID를 추측해 그 자원을 읽거나 같은 ID로 자원을 미리 만들어 정상 프로그램이 의도한 사용자에게 자원을 보내지 못하게 할 수 있다(예: 사용자 이름 기반 파일에 세션 정보를 두는 제품에서 공격자가 피해자용 파일을 미리 만들고 권한을 설정해 피해자의 세션 생성을 막아 애플리케이션을 쓰지 못하게 할 수 있다).
    접근 통제 보호 메커니즘 우회 / 권한 획득 또는 신원 도용 인가·인증 메커니즘이 세션 ID나 암호 키 생성용 시드 같은 무작위 값에 의존해 제한된 기능에 대한 접근을 제한하는 경우, 공격자가 ID나 키를 추측해 그 기능에 접근할 수 있다.

    요구사항 분석 (본문 제3장)¶

    CWE 단계(Phase) 전략 요지

(원문 표현 그대로다. NIST CMVP는 2022. 4. 1.부터 FIPS 140-2 신규 인증 신청을 받지 않고, 2026. 9. 22.에 FIPS 140-2 인증서를 모두 Historical 목록으로 옮겼다. Historical 목록의 모듈은 기존 시스템에만 쓰도록 안내되므로 새로 고를 때는 FIPS 140-3 인증을 보고, 국내 사업은 검증필 암호모듈(KCMVP) 요구 여부를 확인한다.) (설계 단계에도 해당)
    원문

    Use products or modules that conform to FIPS 140-2 [REF-267] to avoid obvious entropy problems. Consult FIPS 140-2 Annex C ("Approved Random Number Generators").

    설계 (본문 제4장)¶

    CWE 단계(Phase) 전략 요지
    아키텍처·설계(Architecture and Design) — 해당 분야 전문가가 현재 강하다고 보는 검증된 알고리즘을 쓰고, 충분한 길이의 시드를 쓰는 잘 시험된 구현을 고른다. 일반적으로 암호학적으로 안전하다고 명시되지 않은 의사난수 생성기(PRNG)는 아마 통계용 PRNG이므로 보안에 민감한 맥락에 쓰면 안 된다. 생성기가 알려지고 시드를 추측할 수 있으면 의사난수 생성기는 예측 가능한 수를 낼 수 있다. 256비트 시드는 '충분히 무작위적인' 수를 만드는 좋은 출발점이다.
    원문

    Use a well-vetted algorithm that is currently considered to be strong by experts in the field, and select well-tested implementations with adequate length seeds.

    In general, if a pseudo-random number generator is not advertised as being cryptographically secure, then it is probably a statistical PRNG and should not be used in security-sensitive contexts.

    Pseudo-random number generators can produce predictable numbers if the generator is known and the seed can be guessed. A 256-bit seed is a good starting point for producing a "random enough" number.

    구현 (본문 제5장)¶

    CWE 단계(Phase) 전략 요지
    구현(Implementation) — 하드웨어 장치 같은 고품질 의사난수 출력원에서 필요할 때 스스로 시드를 다시 받는 PRNG를 고려한다.
    원문

    Consider a PRNG that re-seeds itself as needed from high quality pseudo-random output sources, such as hardware devices.

    예시(나쁜 예·좋은 예)¶

    아래 코드는 이 가이드가 다음 상황을 가정해 새로 작성한 것이다. 정비 콘솔이 원격 정비 접속을 허용하기 전에 도전값(challenge)을 보내고 응답을 검사하며, 데이터링크는 세션마다 논스를 새로 만든다. 이 값을 예측할 수 있으면 공격자가 응답을 미리 준비하거나 이전 메시지를 재전송할 수 있다. 언어마다 분석기·새니타이저·실행 결과로 나쁜 예는 잡히고 좋은 예는 잡히지 않음을 확인했다. 좋은 예는 그 약점 하나를 막는 최소 예이며 그대로 운용 코드가 되는 것은 아니다. 언어 상자를 눌러 펼친다.

    C

    나쁜 예

    #include <stdio.h>
#include <stdlib.h>
#include <time.h>

/* 원격 정비 접속 전 보낼 16바이트 도전값(challenge)을 만든다 */
static void make_challenge(unsigned char *out, size_t n)
{
    srand((unsigned)time(NULL));          /* 시각을 시드로: 접속 시각을 알면 같은 값을 다시 만든다 */
    for (size_t i = 0; i < n; ++i) {
        out[i] = (unsigned char)(rand() & 0xFF);   /* 통계용 의사난수 */
    }
}

int main(void)
{
    unsigned char challenge[16];
    make_challenge(challenge, sizeof challenge);
    for (size_t i = 0; i < sizeof challenge; ++i) {
        printf("%02x", challenge[i]);
    }
    putchar('\n');
    return 0;
}

    srand(time(NULL))와 rand()로 도전값을 만든다. rand()는 통계용 의사난수이고 시드가 초 단위 시각이라 접속 시각만 알면 같은 값을 다시 만들 수 있다. clang-tidy가 cert-msc30-c(rand 사용)와 cert-msc32-c(예측 가능한 시드)로 경고한다.

    좋은 예

    #define _CRT_RAND_S
#include <stdio.h>
#include <stdlib.h>

/* 운영체제의 암호용 난수 생성기를 쓴다(Windows rand_s; Linux는 getrandom, MCU는 검증된 TRNG·DRBG) */
static int make_challenge(unsigned char *out, size_t n)
{
    for (size_t i = 0; i < n; ++i) {
        unsigned int r;
        if (rand_s(&r) != 0) {
            return -1;                    /* 난수를 못 얻으면 약한 값으로 대신하지 않는다 */
        }
        out[i] = (unsigned char)(r & 0xFF);
    }
    return 0;
}

int main(void)
{
    unsigned char challenge[16];
    if (make_challenge(challenge, sizeof challenge) != 0) {
        puts("rng failure: maintenance session refused");
        return 1;
    }
    for (size_t i = 0; i < sizeof challenge; ++i) {
        printf("%02x", challenge[i]);
    }
    putchar('\n');
    return 0;
}

    운영체제의 암호용 난수 생성기(Windows rand_s, Linux getrandom, MCU는 검증된 TRNG·DRBG)를 쓰고, 난수를 얻지 못하면 약한 값으로 대신하지 않고 접속을 거부한다(LNX-06·BSP-07).

    검증: clang-tidy — 나쁜 예에서 cert-msc30-c 검출, 좋은 예에서 미검출 · 참고: MITRE CWE-330 Demonstrative Example 1(예측 가능한 시드의 PRNG로 세션 ID 생성) 참고, 이 가이드가 새로 작성 / KISA·행정안전부 「C 시큐어코딩 가이드」(3판) 보안기능 2-7 '적절하지 않은 난수 값의 사용'(인쇄 99쪽) 참고

    C++

    나쁜 예

    #include <array>
#include <cstdint>
#include <cstdio>
#include <random>

// 데이터링크 세션마다 쓸 128비트 논스를 만든다
static std::array<std::uint32_t, 4> session_nonce() {
    static std::mt19937 engine;            // 시드 없음: 전원을 켤 때마다 같은 순서의 값이 나온다
    std::array<std::uint32_t, 4> nonce{};
    for (auto &word : nonce) {
        word = static_cast<std::uint32_t>(engine());
    }
    return nonce;
}

int main() {
    const auto nonce = session_nonce();
    std::printf("%08x%08x%08x%08x\n", static_cast<unsigned>(nonce[0]), static_cast<unsigned>(nonce[1]),
                static_cast<unsigned>(nonce[2]), static_cast<unsigned>(nonce[3]));
    return 0;
}

    std::mt19937을 시드 없이 만들어 기본 시드로 논스를 뽑는다. 전원을 켤 때마다 같은 순서의 값이 나오며, mt19937은 출력 몇백 개로 내부 상태를 복원할 수 있는 통계용 생성기다. clang-tidy cert-msc51-cpp가 예측 가능한 시드를 경고한다.

    좋은 예

    #include <windows.h>
#include <bcrypt.h>
#include <array>
#include <cstdint>
#include <cstdio>
#include <optional>

// 운영체제의 암호용 난수 생성기(CNG)를 쓴다. MCU라면 검증된 TRNG·DRBG 드라이버로 바꾼다.
static std::optional<std::array<std::uint8_t, 16>> session_nonce() {
    std::array<std::uint8_t, 16> nonce{};
    const NTSTATUS st = BCryptGenRandom(nullptr, nonce.data(), static_cast<ULONG>(nonce.size()),
                                        BCRYPT_USE_SYSTEM_PREFERRED_RNG);
    if (!BCRYPT_SUCCESS(st)) {
        return std::nullopt;               // 실패를 약한 난수로 메우지 않는다
    }
    return nonce;
}

int main() {
    const auto nonce = session_nonce();
    if (!nonce) {
        std::puts("rng failure: link session not opened");
        return 1;
    }
    for (const auto b : *nonce) {
        std::printf("%02x", static_cast<unsigned>(b));
    }
    std::puts("");
    return 0;
}

    나쁜 예

    import java.util.Random;

public class Example {
    static final long MULT = 0x5DEECE66DL, INC = 0xBL, MASK = (1L << 48) - 1;

    // 공격자: 관측한 도전값 두 개로 java.util.Random의 48비트 내부 상태를 되살려 다음 값을 계산한다
    static Integer predictNext(int seen1, int seen2) {
        for (long low = 0; low < (1L << 16); low++) {
            long state = ((seen1 & 0xFFFFFFFFL) << 16) | low;
            long after = (state * MULT + INC) & MASK;
            if ((int) (after >>> 16) == seen2) {
                return (int) (((after * MULT + INC) & MASK) >>> 16);
            }
        }
        return null;
    }

    public static void main(String[] args) {
        Random gen = new Random();              // 통계용 의사난수로 정비 접속 도전값을 만든다
        int c1 = gen.nextInt();
        int c2 = gen.nextInt();
        int c3 = gen.nextInt();
        Integer guess = predictNext(c1, c2);    // c1, c2만 엿보았다
        System.out.println(guess != null && guess == c3 ? "NEXT CHALLENGE PREDICTED" : "prediction failed");
    }
}

    java.util.Random으로 정비 접속 도전값을 만든다. 48비트 선형 합동 생성기라 연속된 출력 두 개만 엿보면 내부 상태를 되살려 다음 도전값을 맞힌다(예시가 실제로 계산한다).

    MITRE 원문 예시(Demonstrative Examples, 영문 3건)

    Example 1. This code attempts to generate a unique random identifier for a user's session.

    Bad / PHP

    function generateSessionID($userID){
  srand($userID);
  return rand();
}

    Because the seed for the PRNG is always the user's ID, the session ID will always be the same. An attacker could thus predict any user's session ID and potentially hijack the session.

    This example also exhibits a Small Seed Space (CWE-339).

    Example 2. The following code uses a statistical PRNG to create a URL for a receipt that remains active for some period of time after a purchase.

    Bad / Java

    String GenerateReceiptURL(String baseUrl) {
  Random ranGen = new Random();
  ranGen.setSeed((new Date()).getTime());
  return(baseUrl + ranGen.nextInt(400000000) + ".html");
}

    This code uses the Random.nextInt() function to generate "unique" identifiers for the receipt pages it generates. Because Random.nextInt() is a statistical PRNG, it is easy for an attacker to guess the strings it generates. Although the underlying design of the receipt system is also faulty, it would be more secure if it used a random number generator that did not produce predictable receipt identifiers, such as a cryptographic PRNG.

    Example 3. The example code is taken from the PRNG inside the buggy OpenPiton SoC of HACK@DAC'21 [REF-1370]. The SoC implements a pseudo-random number generator using a Linear Feedback Shift Register (LFSR).

    An example of LFSR with the polynomial function P(x) = x6+x4+x3+1 is shown in the figure.

    Bad / SystemVerilog

           reg in_sr, entropy16_valid;

        reg [15:0] entropy16;

        assign entropy16_o = entropy16;

        assign entropy16_valid_o = entropy16_valid;

        always @ (*)

        begin

          in_sr = ^ (poly_i [15:0] & entropy16 [15:0]);

        end

    A LFSR's input bit is determined by the output of a linear function of two or more of its previous states. Therefore, given a long cycle, a LFSR-based PRNG will enter a repeating cycle, which is predictable.

    탐지 방법(Detection Methods)¶

    방법 요지 효과성
    블랙박스 시험 운영체제·네트워크와 상호작용하는 소프트웨어 프로세스를 살피는 모니터링 도구를 쓴다. 소스코드가 없거나, 직접 개발하지 않은 소프트웨어이거나, 빌드 단계에서 새 약점이 들어오지 않았는지 확인하려 할 때 유용하다. 도구로는 실행 중인 프로세스에 붙는 디버거, truss(Solaris)·strace(Linux) 같은 시스템 호출 추적 도구, FileMon·RegMon·Process Monitor 등 Sysinternals 유틸리티(Windows), 네트워크 트래픽을 보는 스니퍼·프로토콜 분석기가 있다. 모니터를 프로세스에 붙여 무작위성을 쓰는 시점을 알려 주는 라이브러리 함수를 찾는다. 여러 번 실행해 시드가 바뀌는지 본다.     요구사항 분석 원문 완화책(요구사항) 1건 → 완화책
    설계 키·IV·논스·세션 ID 생성에는 암호학적 난수 생성기(DRBG)와 충분한 엔트로피원을 사용하도록 설계한다.
    구현(C·C++) rand()/srand(time()) 사용을 금지하고 getrandom(), /dev/urandom, 검증된 DRBG(CTR_DRBG 등)를 사용한다.
    구현(Java) java.util.Random 대신 java.security.SecureRandom을 사용한다.
    통합 및 시험 정적 분석의 약한 PRNG 탐지, 생성 값 통계 검정(NIST SP 800-22)과 재부팅 후 값 반복 여부를 시험한다. 통계 검정 통과는 예측 불가능성을 보장하지 않으므로 엔트로피원은 NIST SP 800-90B로 평가한다.
    유지보수 엔트로피원 하드웨어 변경 시 건전성 시험을 재수행한다.
    임베디드 고려 MCU는 부팅 직후 엔트로피가 부족하므로 SoC TRNG를 사용하고, 없으면 ADC 잡음 등에서 엔트로피를 모은 뒤 DRBG의 시드로 쓴다. 재부팅 시 같은 시드가 반복되지 않게 한다.

    도구가 보고하는 하위 CWE는 도구 미지원 시 대안 ⓪을 본다.

    기준선 활동 2건

    • D-05 암호·키·비밀 관리 설계 (설계)
    • D-09 설계 보안성 검토 (설계)

    모든 항목에 공통인 시험 활동. T-01 정적시험과 T-02 타깃 동적시험은 대상 약점을 가리지 않고 모든 과제가 수행한다.

    환경 지침 6건. 과제 환경에 맞는 지침은 지침 선택 도구로 고른다. 축별로 최대 8건을 보이고 나머지는 부록 C에서 찾는다.

    축 지침

    IDE/컴파일러 (1건) MSVC-06 C# 입출력 안전 처리
