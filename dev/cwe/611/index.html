    Improper Restriction of XML External Entity Reference

    항목 내용
    추상화 수준 기본(Base)
    상태 초안(Draft)
    소속 보조 항목(「보안약점 점검 목록」·언어 뷰 밖, 매뉴얼 7-10쪽 '추가 식별' 근거)
    가이드 적용성 조건부 — XML 파서 사용
    적용 플랫폼 언어: 언어 무관, XML · 기술: 기술 무관, 웹 기반(Web Based)
    원문 MITRE CWE-611 (CWE 5.0)

    한 줄 요약

    XML 문서의 개체(entity)가 의도한 통제 범위 밖의 문서를 가리킬 수 있어, 제품이 잘못된 문서를 출력에 포함하는 약점이다.

    → 나쁜 예·좋은 예

    설명(Description)¶

    제품이 의도한 통제 범위 밖의 문서로 해석되는 URI를 가진 XML 개체(entity)를 포함할 수 있는 XML 문서를 처리해, 잘못된 문서를 출력에 포함하는 약점이다.

    배경(Background Details)

    XML 문서는 선택적으로 DTD(Document Type Definition)를 포함하며, DTD의 여러 기능 중 하나로 XML 개체(entity)를 정의할 수 있다. 치환 문자열을 URI 형태로 제공해 개체를 정의할 수 있다. XML 파서는 이 URI의 내용에 접근해 그 내용을 XML 문서에 다시 포함한 뒤 추가로 처리할 수 있다.

    원문(Description · Background Details)

    The product processes an XML document that can contain XML entities with URIs that resolve to documents outside of the intended sphere of control, causing the product to embed incorrect documents into its output.

    XML documents optionally contain a Document Type Definition (DTD), which, among other features, enables the definition of XML entities. It is possible to define an entity by providing a substitution string in the form of a URI. The XML parser can access the contents of this URI and embed these contents back into the XML document for further processing.

    발생 단계(Modes Of Introduction)¶

    CWE 단계(Phase) 수명주기 단계(가이드 대응) 설명
    구현(Implementation) 구현 실현(REALIZATION): 이 약점은 아키텍처 보안 전술을 구현하는 과정에서 생긴다.

    영향(Common Consequences)¶

    영역 영향 설명
    기밀성 애플리케이션 데이터 읽기 / 파일·디렉터리 읽기 공격자가 조작한 DTD를 넣을 수 있고 기본 개체 해석기(entity resolver)가 켜져 있으면 공격자가 시스템의 임의 파일에 접근할 수 있다. file:// URI로 외부 개체를 정의한 XML 파일을 제출해 처리하는 애플리케이션이 로컬 파일을 읽게 할 수 있다(예: Windows의 file:///c:/winnt/win.ini, Unix 계열의 비밀번호 파일 file:///etc/passwd). 읽은 내용은 XML을 처리하는 애플리케이션으로 다시 들어가며, 애플리케이션이 그 데이터를 (예: 오류 메시지로) 되돌려 보내면 파일 내용이 노출될 수 있다.
    무결성 보호 메커니즘 우회 공격자는 http:// 같은 스킴의 URI를 쓴 조작된 DTD를 제공해, 공격자가 직접 닿을 수 없는 서버로 애플리케이션이 외부 HTTP 요청을 보내게 할 수 있다. 이렇게 하면 방화벽 제한을 우회하거나, 포트 스캔 같은 공격의 출처를 숨기거나, 서버가 다른 시스템과 맺은 신뢰 관계를 달리 악용할 수 있다.
    가용성 서비스 거부: 자원 소모(CPU) / 서비스 거부: 자원 소모(메모리) 큰 파일이나 /dev/random처럼 항상 데이터를 반환하는 장치를 가리키는 URI 때문에 제품이 CPU 사이클이나 메모리를 과도하게 쓸 수 있다. 또는 URI가 중첩되거나 재귀적인 개체 참조를 많이 담은 파일을 가리켜 구문 분석을 더 느리게 할 수도 있다.

    예시(나쁜 예·좋은 예)¶

    아래 코드는 이 가이드가 다음 상황을 가정해 새로 작성한 것이다. 시험 도구·임무 계획 도구·정비 단말이 협력 업체나 다른 단말에서 받은 XML(ICD 정의, 임무 계획, 시험 장비 구성)을 읽는다. XML 문서는 머리의 DTD에 외부 개체를 선언할 수 있어서, 해석기가 외부 개체를 풀면 문서 밖의 로컬 파일 내용이 필드 값으로 들어와 화면·보고서·오류 메시지로 드러난다. 예시는 작업 폴더에 가짜 키 파일을 만들고, 그 파일을 외부 개체로 가리키는 XML을 읽었을 때 키 파일 내용이 출력되는지 본다. 언어마다 분석기·새니타이저·실행 결과로 나쁜 예는 잡히고 좋은 예는 잡히지 않음을 확인했다. 좋은 예는 그 약점 하나를 막는 최소 예이며 그대로 운용 코드가 되는 것은 아니다. 언어 상자를 눌러 펼친다.

    C

    나쁜 예

    #define COBJMACROS
#include <stdio.h>
#include <windows.h>
#include <msxml6.h>

/* 시험 도구가 협력 업체에서 받은 ICD 정의 XML을 읽어 필드 설명을 화면에 보여 준다 */
static void show_field_note(const wchar_t *icd_path)
{
    IXMLDOMDocument2 *doc = NULL;
    if (FAILED(CoCreateInstance(&CLSID_DOMDocument60, NULL, CLSCTX_INPROC_SERVER,
                                &IID_IXMLDOMDocument2, (void **)&doc))) {
        return;
    }
    VARIANT off = {0};
    V_VT(&off) = VT_BOOL;
    V_BOOL(&off) = VARIANT_FALSE;
    BSTR prop = SysAllocString(L"ProhibitDTD");
    IXMLDOMDocument2_put_async(doc, VARIANT_FALSE);
    IXMLDOMDocument2_put_validateOnParse(doc, VARIANT_FALSE);
    IXMLDOMDocument2_setProperty(doc, prop, off);              /* DTD를 허용한다 */
    IXMLDOMDocument2_put_resolveExternals(doc, VARIANT_TRUE);  /* 외부 개체까지 풀어 넣는다 */

    VARIANT src = {0};
    V_VT(&src) = VT_BSTR;
    V_BSTR(&src) = SysAllocString(icd_path);
    VARIANT_BOOL loaded = VARIANT_FALSE;
    IXMLDOMDocument2_load(doc, src, &loaded);

    BSTR xpath = SysAllocString(L"/icd/field/note");
    IXMLDOMNode *note = NULL;
    BSTR text = NULL;
    if (loaded == VARIANT_TRUE && IXMLDOMDocument2_selectSingleNode(doc, xpath, &note) == S_OK
        && IXMLDOMNode_get_text(note, &text) == S_OK) {
        wprintf(L"field note: %ls\n", text);
    } else {
        wprintf(L"rejected: ICD file not loaded\n");
    }
    SysFreeString(text);
    if (note != NULL) IXMLDOMNode_Release(note);
    SysFreeString(xpath);
    VariantClear(&src);
    SysFreeString(prop);
    IXMLDOMDocument2_Release(doc);
}

int main(void)
{
    /* 시험 준비: 작업 폴더의 가짜 키 파일과, 외부 개체로 그 파일을 가리키는 ICD 파일 */
    FILE *f = fopen("maint_link.key", "w");
    if (f == NULL) return 1;
    fputs("KEY-EXAMPLE-ONLY-7731", f);
    fclose(f);
    f = fopen("received_icd.xml", "w");
    if (f == NULL) return 1;
    fputs("<?xml version=\"1.0\"?>\n<!DOCTYPE icd [<!ENTITY leak SYSTEM \"maint_link.key\">]>\n"
          "<icd><field id=\"0x21\"><note>&leak;</note></field></icd>\n", f);
    fclose(f);

    wchar_t full[MAX_PATH];
    if (GetFullPathNameW(L"received_icd.xml", MAX_PATH, full, NULL) == 0) return 1;
    if (FAILED(CoInitializeEx(NULL, COINIT_APARTMENTTHREADED))) return 1;
    show_field_note(full);
    CoUninitialize();
    return 0;
}

    MSXML 6.0 문서 객체의 기본값(DTD 금지, 외부 개체 미해석)을 바꿔 ProhibitDTD를 false로, resolveExternals를 true로 둔다. DTD에 선언한 외부 개체가 작업 폴더의 키 파일을 가리키므로 파일 내용이 note 값으로 들어와 화면에 나온다. 파일 경로 대신 http:// 주소를 넣으면 시험 도구가 내부망의 다른 서버로 요청을 보내게 할 수도 있다.

    좋은 예

    #define COBJMACROS
#include <stdio.h>
#include <windows.h>
#include <msxml6.h>

/* DTD를 금지하고 외부 개체·외부 스키마를 풀지 않는 문서 객체를 만든다 */
static IXMLDOMDocument2 *new_hardened_document(void)
{
    IXMLDOMDocument2 *doc = NULL;
    if (FAILED(CoCreateInstance(&CLSID_DOMDocument60, NULL, CLSCTX_INPROC_SERVER,
                                &IID_IXMLDOMDocument2, (void **)&doc))) {
        return NULL;
    }
    VARIANT on = {0};
    V_VT(&on) = VT_BOOL;
    V_BOOL(&on) = VARIANT_TRUE;
    BSTR prohibit = SysAllocString(L"ProhibitDTD");
    HRESULT hr = IXMLDOMDocument2_setProperty(doc, prohibit, on);   /* MSXML6 기본값이지만 명시한다 */
    SysFreeString(prohibit);
    if (FAILED(hr) || FAILED(IXMLDOMDocument2_put_resolveExternals(doc, VARIANT_FALSE))
        || FAILED(IXMLDOMDocument2_put_async(doc, VARIANT_FALSE))) {
        IXMLDOMDocument2_Release(doc);
        return NULL;                                                 /* 설정에 실패하면 해석하지 않는다 */
    }
    return doc;
}

/* 시험 도구가 협력 업체에서 받은 ICD 정의 XML을 읽어 필드 설명을 화면에 보여 준다 */
static void show_field_note(const wchar_t *icd_path)
{
    IXMLDOMDocument2 *doc = new_hardened_document();
    if (doc == NULL) {
        wprintf(L"rejected: parser setup failed\n");
        return;
    }
    VARIANT src = {0};
    V_VT(&src) = VT_BSTR;
    V_BSTR(&src) = SysAllocString(icd_path);
    VARIANT_BOOL loaded = VARIANT_FALSE;
    IXMLDOMDocument2_load(doc, src, &loaded);

    BSTR xpath = SysAllocString(L"/icd/field/note");
    IXMLDOMNode *note = NULL;
    BSTR text = NULL;
    if (loaded == VARIANT_TRUE && IXMLDOMDocument2_selectSingleNode(doc, xpath, &note) == S_OK
        && IXMLDOMNode_get_text(note, &text) == S_OK) {
        wprintf(L"field note: %ls\n", text);
    } else {
        wprintf(L"rejected: ICD file with DTD or malformed content\n");   /* 원인은 기록에 남기고(예시에서는 생략) 내용은 보여 주지 않는다 */
    }
    SysFreeString(text);
    if (note != NULL) IXMLDOMNode_Release(note);
    SysFreeString(xpath);
    VariantClear(&src);
    IXMLDOMDocument2_Release(doc);
}

int main(void)
{
    /* 시험 준비: 작업 폴더의 가짜 키 파일과, 외부 개체로 그 파일을 가리키는 ICD 파일 */
    FILE *f = fopen("maint_link.key", "w");
    if (f == NULL) return 1;
    fputs("KEY-EXAMPLE-ONLY-7731", f);
    fclose(f);
    f = fopen("received_icd.xml", "w");
    if (f == NULL) return 1;
    fputs("<?xml version=\"1.0\"?>\n<!DOCTYPE icd [<!ENTITY leak SYSTEM \"maint_link.key\">]>\n"
          "<icd><field id=\"0x21\"><note>&leak;</note></field></icd>\n", f);
    fclose(f);

    wchar_t full[MAX_PATH];
    if (GetFullPathNameW(L"received_icd.xml", MAX_PATH, full, NULL) == 0) return 1;
    if (FAILED(CoInitializeEx(NULL, COINIT_APARTMENTTHREADED))) return 1;
    show_field_note(full);
    CoUninitialize();
    return 0;
}

    ProhibitDTD를 true로, resolveExternals를 false로 명시하고, 설정 호출이 하나라도 실패하면 문서 객체를 쓰지 않는다. DTD가 든 파일은 읽는 단계에서 거부되어 외부 개체가 풀리지 않는다(I-03). 거부 사유는 기록에 남기고 화면에는 파일 내용을 보여 주지 않는다. ICD 정의에 DTD가 꼭 필요하면 resolveExternals를 false로 둔 채 내부 선언만 받고, 내부 개체 확장이 문서를 부풀리지 않도록 크기 한도(MaxXMLSize 등)를 함께 둔다(CWE-776).

    검증: 실행 결과 — 나쁜 예에서 field note: KEY-EXAMPLE-ONLY 검출, 좋은 예에서 미검출·rejected: ICD file with DTD or malformed content 출력 확인 · 참고: MITRE CWE-611 설명·완화책(XML 해석기의 외부 개체 확장 끄기) 참고, 이 가이드가 새로 작성

    C++

    나쁜 예

    #include <windows.h>
#include <msxml2.h>
#include <cstdio>
#include <fstream>
#include <memory>

struct ComRelease {
    void operator()(IUnknown *p) const { if (p) p->Release(); }
};
template <class T> using ComPtr = std::unique_ptr<T, ComRelease>;

struct Bstr {
    BSTR s;

class MessageNames(xml.sax.ContentHandler):            # <msg> 요소의 글자를 모은다
    def __init__(self):
        super().__init__()
        self.names, self.buf = [], None

    def startElement(self, name, attrs):
        if name == "msg":
            self.buf = []

    def characters(self, content):
        if self.buf is not None:
            self.buf.append(content)

    def endElement(self, name):
        if name == "msg":
            self.names.append("".join(self.buf))
            self.buf = None

    names = MessageNames()
    parser.setContentHandler(names)
    parser.parse(io.BytesIO(xml_bytes))
    return names.names

def refuse_dtd(xml_bytes):
    # ICD 정의 파일에는 DTD가 필요 없다: 문서형 선언·개체 선언이 있으면 해석 전에 거부한다
    scan = xml.parsers.expat.ParserCreate()

    def reject(*_):
        raise ValueError("DTD/entity declaration not allowed in ICD file")
    scan.StartDoctypeDeclHandler = reject
    scan.EntityDeclHandler = reject
    scan.Parse(xml_bytes, True)


def load_icd(xml_bytes):
    refuse_dtd(xml_bytes)
    root = ET.fromstring(xml_bytes)                     # ElementTree는 외부 개체를 읽지 않는다
    return [m.text for m in root.iter("msg")]

<icd><msg>NAV_STATE</msg><msg>&ext;</msg></icd>"""

    ICD 정의 파일처럼 DTD가 필요 없는 입력은 문서형 선언·개체 선언이 있으면 해석 전에 거부하고, 외부 개체를 읽지 않는 해석기(ElementTree)로 읽는다(I-03, LPY-03). 신뢰 경계 밖의 XML은 defusedxml(기본으로 개체 선언·외부 참조 금지, forbid_dtd=True로 DTD도 금지)을 쓰는 것이 간단하다. Bandit은 표준 xml 모듈 사용 자체를 B313~B319(해석 호출)·B405~B409(가져오기)로 알리므로 좋은 예에도 보고가 남는다. 위 대책을 확인하고 사유를 남겨 닫거나 defusedxml로 바꾼다.

    검증: 실행 결과 — 나쁜 예에서 SITE-KEY=44AF 검출, 좋은 예에서 미검출·rejected: DTD/entity declaration not allowed 출력 확인 · 참고: MITRE CWE-611 설명·완화책(XML 해석기의 외부 개체 확장 끄기) 참고, 이 가이드가 새로 작성 / 과학기술정보통신부·한국인터넷진흥원 「Python 시큐어코딩 가이드」(2023. 12.) 입력데이터 검증 및 표현 1-8 '부적절한 XML 외부 개체 참조'(인쇄 39쪽) 참고

    MITRE 원문(CWE 5.0)에는 이 항목의 예시(Demonstrative Examples)가 없다.

    탐지 방법(Detection Methods)¶

    방법 요지 효과성
    자동 정적 분석 흔히 SAST(Static Application Security Testing)라 부르는 자동 정적 분석(static analysis)은 소스코드(또는 바이너리·컴파일된 코드)를 실행하지 않고 분석해 이 약점의 일부 사례를 찾을 수 있으며, 대개 데이터 흐름·제어 흐름 모델을 만든 뒤 입력 출처('source')와 외부 구성요소나 운영체제 같은 하위 계층과 상호작용하는 목적지('sink')를 잇는 잠재적 취약 패턴을 찾는다.
    원문

    Automated static analysis, commonly referred to as Static Application Security Testing (SAST), can find some instances of this weakness by analyzing source code (or binary/compiled code) without having to execute it. Typically, this is done by building a model of data flow and control flow, then searching for potentially-vulnerable patterns that connect "sources" (origins of input) with "sinks" (destinations where the data interacts with external components, a lower layer such as the OS, etc.)

    		 높음(High)
