    D-1. C#: Microsoft .NET 보안 규칙 94개¶

    Microsoft Learn 「Security rules (code analysis)」 목록의 Security 범주 규칙 94개를 CWE와 이 가이드의 C# 지침(LCS)에 대응시킨다(원천 dotnet/docs 커밋 고정본, 조회 2026. 10. 18.). 규칙 문서에는 CWE 번호가 없어 대응은 이 가이드의 판단이다. BinaryFormatter 보안 가이드가 CWE-502를 연결하는 BinaryFormatter·LosFormatter·NetDataContractSerializer 관련 7개만 'MS 문서 명시'로 표시했다. CWE 칸의 첫 번호가 주 대응이다.

    • 적용성은 데스크톱·서비스 형태의 무기체계 C# 소프트웨어 기준이다: 해당 50개, 조건부 26개, 비해당 18개. 웹 UI(ASP.NET)를 두는 과제는 웹 전용으로 비해당 판정한 규칙을 다시 판정한다(LCS-01).
    • 범위는 주 대응 CWE가 보안약점 점검 목록 44개 안(21개), 언어 뷰 153개 안(28개), 보조 항목(A-3, 18개), 그 밖(27개) 중 어디인지다.
    • 켜지는 모드는 .NET SDK 10.0.402 분석 모드 구성 기준이다. .NET 10 기본값(Default·Minimum)에서는 Security 범주 규칙이 하나도 켜지지 않고, Recommended는 24개, All은 94개를 켠다. 'All'로 적은 규칙은 All 모드(AnalysisMode 또는 AnalysisModeSecurity)에서만 켜진다(5.6, LCS-09).
    • C# 지침: ●는 지침·근거 문장에 그 규칙(또는 규칙이 보는 형식 이름)이 있는 것, ◐는 같은 CWE만 다루는 것이다. 지침 칸이 비어 있으면 이 가이드의 C# 지침이 그 규칙을 다루지 않는다.
    • 출처: 규칙 제목은 Microsoft Learn 원문(원천 dotnet/docs, © Microsoft, CC BY 4.0)이고, 한글 요약과 CWE 대응은 이 가이드가 작성한 것이다(변경).
    • 규칙의 대상 조건 한계(오염 추적 규칙 CA3001~CA3012, CA3075·CA3077)와 실험 결과는 5.6에, 대안은 6.2와 LCS-09에 있다.
